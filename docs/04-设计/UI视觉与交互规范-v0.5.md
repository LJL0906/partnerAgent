## 3. 品牌与视觉基调

### 3.1 核心印象

```text
冷静的科技底色
+ 有生命感的蓝紫能量
+ 近黑色的结构锚点
+ 少量薄荷色的正向反馈
= 温柔、聪明、年轻的个人伙伴
```

### 3.2 视觉原则

- 冷白画布承载阅读，不使用米白、暖黄或大面积彩色底。
- 每屏只保留一个高能视觉焦点，通常是品牌字标、主按钮或当前关键建议。
- 蓝紫渐变只表达品牌与 AI 能力，不用于普通正文和所有卡片。
- 近黑用于主文字、AI 核心和选中态结构，避免“传统后台蓝”。
- 薄荷色只表达在线、完成或成功；琥珀色表示提醒；红色只表示错误或危险。
- 优先使用开放布局、列表和轨道，避免卡片套卡片和默认宫格后台感。
- 装饰必须服务状态或交互，不能用大量发光、渐变描边和悬浮图标堆出科技感。

### 3.3 标志性母题

- **渐变字标**：“伙伴”使用蓝到紫的短程渐变、略紧字距和较强字重，只在一级入口使用。
- **AI 能量体**：近黑色圆角体内出现一个蓝紫能量点或短轨迹，用于助手核心、生成中和 AI 状态。
- **响应切角**：关键候选容器或主按钮允许在右下角使用单一切角，表示内容仍可被确认或送出。
- **轻悬浮**：只在输入器、底部固定操作区和临时浮层使用柔和阴影。

### 4.2 字体

字体栈：

```text
iOS: PingFang SC, SF Pro Display, SF Pro Text
Android: Noto Sans CJK SC, Roboto
Fallback: system-ui, sans-serif
```

| Token | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| `type.brand` | `32 / 38` | `800` | “伙伴”一级字标 |
| `type.display` | `28 / 36` | `750` | 今日主标题、空态主句 |
| `type.pageTitle` | `22 / 30` | `700` | 二级页面标题 |
| `type.sectionTitle` | `17 / 24` | `650` | 区块标题、候选标题 |
| `type.body` | `16 / 24` | `400` | 消息与主要内容 |
| `type.bodyStrong` | `16 / 24` | `600` | 重点正文、列表主值 |
| `type.control` | `15 / 20` | `600` | 按钮、Tab、表单值 |
| `type.label` | `13 / 18` | `600` | 字段名、状态标签 |
| `type.caption` | `12 / 18` | `400` | 时间、来源、帮助文案 |

规则：

- 品牌字标允许负字距 `-1px`；正文与控件不使用夸张字距。
- 一页最多同时出现五级文字层级。
- 数字和时间使用等宽数字特性时，不改变中文字体气质。
- 正文最小字号为 14，辅助信息最小字号为 12；支持系统动态字体时不得截断关键操作文案。

### 4.3 间距

采用 4px 基础网格：

| Token | 值 | 常见用途 |
| --- | --- | --- |
| `space.1` | `4` | 图标内部、紧凑状态 |
| `space.2` | `8` | 标签内部、相邻元信息 |
| `space.3` | `12` | 控件内部、小列表间距 |
| `space.4` | `16` | 页面横向基准、卡片内边距 |
| `space.5` | `20` | 列表分组、主要控件间距 |
| `space.6` | `24` | 区块间距 |
| `space.8` | `32` | 大区块间距 |
| `space.10` | `40` | 首屏标题与主内容 |
| `space.12` | `48` | 空态和页面节奏 |

移动端页面默认左右安全边距 20；紧凑列表分隔线可以延伸至 16。点击目标最小 `44 × 44`。

### 4.4 圆角、切角与描边

| Token | 值 | 用途 |
| --- | --- | --- |
| `radius.sm` | `10` | 标签、小按钮、状态容器 |
| `radius.md` | `16` | 输入框、列表块、次级卡片 |
| `radius.lg` | `22` | 候选卡、摘要卡、固定操作区 |
| `radius.pill` | `999` | 仅用于短状态、头像、圆形按钮 |
| `cut.corner` | `10` | 关键容器右下单切角 |
| `border.default` | `1px solid color.border` | 普通容器 |
| `border.focus` | `2px solid color.brand.500` | 键盘聚焦 |

切角不是所有控件的默认造型。仅允许用于 AI 候选、主按钮、输入发送端等关键交互；普通列表、设置字段和正式 Action 使用标准圆角。

### 4.5 阴影与辉光

| Token | 参数 | 用途 |
| --- | --- | --- |
| `shadow.float` | `0 8 24 rgba(25,28,50,0.08)` | 输入器、浮动底栏 |
| `shadow.overlay` | `0 16 40 rgba(25,28,50,0.14)` | 弹窗、底部抽屉 |
| `glow.ai` | `0 0 20 rgba(104,91,246,0.22)` | AI 能量点，单屏至多一次 |

常规卡片默认无阴影，只使用描边或背景分区。禁止多层彩色辉光和大面积玻璃拟态。

### 4.6 图标

- 默认使用统一线框图标族，优先 `Lucide` 或与其一致的自定义 SVG。
- 常规画布 `24 × 24`，紧凑图标 `20 × 20`，导航图标 `24 × 24`。
- 默认线宽 `1.8`，端点和转角使用圆角。
- 填充只用于选中态小区域、状态点或 AI 核心，不混用 Emoji。
- 图标按钮必须有无障碍标签；图标不可替代“确认”“撤销”等关键文字。

## 5. 布局与页面骨架

### 5.1 安全区

- 页面背景延伸至设备边缘，实际内容遵循系统安全区。
- 顶栏内容区高度建议 56，不含状态栏。
- 底部 Tab Bar 内容区高度建议 64，不含 Home Indicator 安全区。
- 带键盘页面使用键盘避让；输入器不得遮挡最后一条消息或确认按钮。

### 5.2 顶栏

统一结构：

```text
[返回/品牌]  页面标题或上下文  [全局入口/更多]
```

- 一级“助手”页展示渐变“伙伴”字标，不再重复普通标题。
- 二级页使用普通近黑页面标题，不重复渐变品牌字标。
- 返回、更多、历史均使用 44 × 44 点击区和统一 24px 图标。
- 顶栏最多一个右侧主入口；待确认数量可使用小型角标。

### 5.3 底部导航

固定五项：

```text
助手　今日　执行　记忆　我的
```

- 未选中：`color.text.tertiary` 线框图标与文字。
- 选中：保留该栏目原有语义图标，置于统一的近黑圆角容器内，并使用极小蓝紫能量点或蓝紫文字强调。
- 不得把所有选中图标都替换成同一个 AI 图标。
- 角标只显示待处理数量；`99+` 封顶。
- 二级详情页可保留 Tab Bar，也可根据任务沉浸度隐藏；同一导航层级必须一致。

## 6. 核心组件规范

### 6.1 按钮

| 变体 | 外观 | 使用场景 |
| --- | --- | --- |
| `primary` | 蓝紫实底或规范渐变、白字 | 每屏唯一主动作 |
| `secondary` | 白底、灰边、近黑字 | 暂不处理、测试连接 |
| `tertiary` | 透明底、品牌色文字 | 查看来源、展开说明 |
| `danger` | 浅红底、危险红字 | 删除、确认阻断等破坏性操作 |
| `icon` | 44px 透明或浅底容器 | 返回、更多、附件 |

尺寸：

- `lg`: 高 52，左右内边距 20，适合底部主 CTA。
- `md`: 高 44，左右内边距 16，适合页面内操作。
- `sm`: 高 36，左右内边距 12，只用于次要紧凑操作。

状态：默认、按压、聚焦、加载、禁用、成功。加载时保留按钮原宽，禁用态不能只降低透明度，还需禁止交互并提供语义。

### 6.2 文本输入与表单字段

- 普通字段高度 52，多行字段最小高度 96。
- 标签位于字段上方；占位符不能替代字段标签。
- 默认灰色 1px 描边，聚焦使用 2px 品牌描边和轻微外环。
- 错误状态使用危险色描边、错误图标和字段下方说明。
- API Key 默认遮挡，支持显隐切换，但不得在截图、日志或导出中泄漏。
- 下拉选择、日期时间、推理等级使用同一字段骨架，不模拟浏览器默认控件。
- 聊天 Composer 与普通表单共享颜色和状态 Token，但结构不同：Composer 可以包含附件、语音、发送和生成状态。

### 6.3 标签与徽标

标签只承载短状态，不承载整句说明：

- `AI 生成`：蓝紫浅底 + 星点图标。
- `待确认`：蓝紫浅底 + 明确文字。
- `低/中/高风险`：分别使用中性、琥珀、危险语义，并带文字。
- `已完成/在线`：薄荷浅底 + 勾选或状态点。
- `已过期`：琥珀或危险语义，依据是否已阻塞操作决定。

### 6.4 AI 候选卡

候选是“待用户决定的提案”，不是正式 Action。

必须包含：

- 对象类型与候选数量。
- 标题摘要。
- 风险等级。
- 过期时间或剩余时间。
- “查看并确认”入口。

视觉规则：

- 可使用蓝紫轻描边、单切角和细小能量轨迹。
- 不使用完成勾、绿色实体状态或“已创建”文案。
- 默认选中只代表本次提交将包含它，不代表已经确认。
- 一条消息产生多个候选时使用列表，不堆叠多个厚重卡片。

### 6.5 正式 Action 容器

- 使用白色实体表面、中性实线描边或开放列表结构。
- 标题旁明确显示“已确认”或正式状态，不使用候选切角偏移边。
- 执行、计划、时效三个状态必须同时可见，不能合并为一个模糊标签。
- 来源、确认记录、对象版本和变更历史是详情页固定区块。

### 6.6 列表与时间线

- 默认优先开放列表，行高不小于 56。
- 同组列表使用分隔线，不为每一行增加独立阴影卡片。
- 时间线使用 2px 中性轨道；当前节点使用品牌色，完成节点使用成功色，异常节点使用对应语义色。
- 时间、来源等元信息使用 `type.caption`，不得抢过主内容。

### 6.7 开关、复选框与单选

- 开关轨道建议 `48 × 28`；开启为品牌色，关闭为中性灰。
- 复选框建议视觉尺寸 22，点击区不小于 44。
- 候选复选框必须有选中、未选、禁用、冲突四态。
- 高风险候选不能仅靠批次全选完成确认，必须有独立风险确认控件。

### 6.8 反馈

| 场景 | 表现 |
| --- | --- |
| 页面初始加载 | 与页面结构一致的骨架屏，不使用全屏 Spinner |
| 局部生成 | AI 能量点短轨迹 + 明确“正在整理”文案 |
| 成功 | 轻量行内反馈；随后读取服务端权威状态 |
| 网络失败 | 原位错误摘要 + 重试，不清空用户输入 |
| 版本冲突 | 阻止覆盖，展示“内容已更新”并要求刷新 |
| 候选过期 | 禁用确认，展示过期原因和重新分析入口 |
| 批次失败 | 明确“整批未生效”，保留候选供重试 |
| 空状态 | 一句解释 + 一个有效下一步，不堆装饰插画 |

## 7. 一期关键页面交互

### 7.1 聊天首页

```text
进入应用
→ 直接看到伙伴与最近会话
→ 输入自然语言
→ 普通聊天自然回复，不强制结构化
→ 识别到明确行动意图时展示 Action 候选入口
→ 点击进入确认中心详情
```

页面主次：消息内容 > 输入器 > 候选入口 > 模型和连接元信息。模型切换等工具默认收起，避免把首页做成控制台。

### 7.2 确认中心详情

```text
读取服务端候选与版本
→ 查看来源、风险和不确定性
→ 逐项选择或编辑允许字段
→ 查看本次变更摘要
→ 明确确认
→ 等待原子事务结果
→ 重新读取批次与正式 Action
```

规则：

- 支持确认、修改后确认、取消和暂不处理。
- 可编辑字段完全以服务端 `editable_fields` 为准。
- 高风险批次独立展示和提交，不提供混合“全部确认”。
- 提交期间锁定重复操作；相同操作标识重试不得产生重复 Action。
- 确认成功前不允许把候选画成正式对象。

### 7.3 行动详情

固定展示：

1. 行动标题和正式身份。
2. 执行状态：待开始 / 进行中 / 暂时搁置 / 已完成 / 已取消。
3. 计划状态：正常 / 已延期。
4. 时效状态：无截止时间 / 未过期 / 已过期 / 不适用。
5. 计划时间、截止时间、优先级、关联目标。
6. 原始消息来源、确认记录、版本和变更历史。
7. 可执行操作和撤销资格。

撤销路径：

```text
申请撤销
→ 查询撤销资格
→ 生成整批撤销候选
→ 返回确认中心再次确认
→ 创建新版本并保留旧历史
```

撤销不是删除，也不能用本地乐观状态直接回退。

### 7.4 今日首页

- 只聚合已确认的正式 Action、提醒和待确认入口。
- AI 给出的“今日优先建议”必须标注为建议，不得表现为正式 Action。
- 复杂日历、拖拽排序、自动执行和完整提醒系统不属于首个业务纵切。
- 页面资产插画只属于内容资产，不作为 UI Token 或通用组件。

### 7.5 模型配置

- 当前业务纵切不以完整模型配置中心为交付目标；本页主要用于提取表单规范。
- 连接测试与保存配置是不同动作；测试成功不等于已经保存。
- 服务商 Logo 属于第三方资产，不纳入品牌 Token；设计图中的 Logo 仅为占位参考。
- API Key 必须遮挡，不写入 `EXPO_PUBLIC_*`、URL、日志或明文持久化。

## 8. 三类确认事务的视觉区分

| 事务 | 标题前缀 | 视觉容器 | 主动作 | 禁止混淆 |
| --- | --- | --- | --- | --- |
| 业务候选确认 | “确认创建/修改” | 蓝紫轻描边候选容器 | 确认生效 | 不能显示为已创建 |
| 隐私外发决定 | “发送前隐私检查” | 中性表面 + 敏感类别提示 | 脱敏后发送/允许一次 | 不能叫业务确认 |
| 工具执行审批 | “允许执行操作” | 中性表面 + 工具与影响说明 | 允许执行 | 不能和 Action 候选混批 |

三类事务必须使用不同标题、图标、说明和结果文案。危险程度仍由语义色表达，不能用三套互相竞争的品牌色。

## 9. 动效规范草案

仅定义动效意图，精确参数在真机阶段冻结：

- AI 生成：能量点沿 24–48px 短轨迹呼吸，避免全屏粒子动画。
- 候选出现：由回复内容向候选容器轻微下落并实体化，说明“建议变成可确认提案”。
- 确认完成：主按钮进入短暂成功态，然后过渡到服务端权威结果。
- 页面切换：使用平台原生 push / modal 语义，不自定义复杂 3D 转场。
- 所有非必要动效遵守 `prefers-reduced-motion` 或系统“减少动态效果”。

## 10. 无障碍与内容规则

- 正文与背景目标对比度不低于 `4.5:1`；大字和图形目标不低于 `3:1`。
- 关键点击区域不小于 `44 × 44`。
- 状态不能仅靠颜色表达。
- 屏幕阅读器应读出“候选，待确认”“正式行动，进行中”等对象身份。
- 错误提示与对应字段建立可访问关联；提交失败后焦点移动至错误摘要。
- 支持 200% 字体放大时，按钮可增高、正文可换行，关键文案不得省略。
- 文案使用陪伴式语气，但涉及确认、风险、失败和隐私时必须直接、具体、不卖萌。

## 11. 禁止用法

- 大面积红色、粉色、米黄色或暖灰作为品牌主视觉。
- 红黑电竞风、霓虹赛博朋克、密集网格、数据大屏式科技感。
- 每张卡都使用渐变描边、切角、阴影或发光。
- 用多种 Emoji 代替统一图标。
- 把普通闲聊自动渲染为任务候选。
- 把候选、分析结果和正式 Action 画成同一种卡片。
- 确认成功前显示“已创建”“已完成”或更新正式状态。
- 把执行、计划和时效状态压成一个标签。
- 把取消候选、撤销 Action 和删除数据设计成同一个动作。
- 把第三方模型 Logo、今日插画或生成图中的偶然装饰提取为全局 Token。

## 12. Expo 实现建议

Token 建议按以下层次落地：

```text
src/theme/
├── colors.ts
├── typography.ts
├── spacing.ts
├── radius.ts
├── shadows.ts
└── motion.ts

src/components/ui/
├── AppButton.tsx
├── AppIcon.tsx
├── AppField.tsx
├── StatusBadge.tsx
├── AppHeader.tsx
├── AppTabBar.tsx
├── CandidateCard.tsx
└── FeedbackState.tsx
```

实现约束：

- 同类元素必须复用组件或 Token，不在页面内复制一次性颜色和尺寸。
- `AppHeader`、`AppTabBar`、按钮高度、图标线宽和页面边距优先统一。
- 候选与正式 Action 使用不同组件，不能只通过传入不同颜色区分。
- Android 与 iOS 保持同一信息层级；阴影可使用各平台等效实现。
- 先完成聊天 → 确认 → Action 详情纵切，再扩展今日与完整模型配置页。

## 13. v1.0 冻结条件

在 v0.5 升级为 v1.0 前，至少完成：

1. 统一 Header、Tab Bar、CTA、圆角切角、图标和阴影参数。
2. 补齐按钮、输入框、复选框、开关的按压、聚焦、加载、禁用和错误状态。
3. 补齐候选过期、版本冲突、批次失败、撤销阻塞、网络恢复和空状态样本。
4. 在 iOS 与 Android 真机验证动态字体、键盘弹起、长文本和安全区。
5. 校验色彩对比度、点击目标和屏幕阅读器标签。
6. 对照设计样本完成聊天 → 确认 → Action → 撤销候选主链路的视觉回归。

暂不冻结：深色模式、平板/横屏、复杂日历、完整提醒、Goal/Memory 页面和高级动效。

## 14. 设计决策记录

- 当前品牌主色采用电子蓝紫，不采用红白主题。
- “伙伴”使用渐变字标，但二级页标题保持普通近黑文字。
- AI 感通过能量点、短轨迹、切角和状态动效表达，不通过传统企业后台或赛博朋克堆叠表达。
- 当前七页只用于建立同一套组件语言；登录、注册、模型配置和今日页不扩大首个业务纵切的开发范围。
- 本文档为 v0.5；精确像素和动效参数以首轮 Expo 实现和真机复核结果为准。
