## 1. 选型总览

v1 采用**混合 Agent 架构**，结合 TypeScript 和 Python 生态各自的优势：

```text
移动客户端：Expo + React Native + TypeScript + Expo Router
通信协议：REST 承载 Command/Query，WebSocket 承载流式与主动事件
业务后端：NestJS + TypeScript
实时 Agent：Pi Agent Core + pi-ai（TypeScript）
复杂工作流：LangGraph + LangChain（Python）
AI/RAG 服务：Python + FastAPI
主数据库：PostgreSQL + pgvector
文件存储：私有核心主机本地文件系统
后台任务：BullMQ（TypeScript）
知识库：Obsidian 双向同步
部署：Docker Compose 私有核心主机
```

## 2. 架构设计理念

### 2.1 混合 Agent 架构

```text
【实时交互层】- Pi Agent (TypeScript)
├─ 陪伴聊天（低延迟、流式体验）
├─ 辅助解答（快速响应）
├─ 实时行动协助（即时反馈）
└─ 简单多轮对话

【复杂任务层】- LangGraph (Python)
├─ 每日摘要生成（多步骤分析）
├─ 每周复盘（需要暂停/恢复）
├─ 深度文档分析（多阶段工作流）
└─ 长时间运行的后台任务

【统一模型层】- pi-ai (TypeScript)
└─ 多提供商统一接口（两个 Agent 层共用）
```

**设计原则**：

- 实时交互用 TypeScript（类型安全、NestJS 零摩擦集成、事件流直观）
- 复杂工作流用 Python（状态机强大、ML 生态完善、适合长时任务）
- 模型调用统一化（避免重复配置、统一成本追踪）

### 2.2 运行形态

```text
单用户私有部署
├─ 用户可控的私有核心主机
├─ Expo 移动客户端（手机）
├─ 未来扩展：电脑端访问（暂不锁定实现方式）
└─ 核心数据保存在私有主机

运行关系：
Expo 移动 App
     ↓ WebSocket (HTTPS)
NestJS Business Core
     ├─ Pi Agent Service（实时交互）
     ├─ Workflow Service（复杂任务）
     └─ Model Gateway (pi-ai)
     ↓
PostgreSQL + pgvector
     ↓
Python FastAPI (RAG + 深度分析)
     ├─ LangChain RAG
     ├─ LangGraph 工作流
     └─ 文档解析、Embedding
     ↓
外部模型和服务（用户可配置）
```

### 4.2 核心服务

#### 4.2.1 Pi Agent Service（实时交互）

```typescript
@Injectable()
export class PiAgentService {
  private models: Models;
  private sessions: Map<string, Agent> = new Map();

  constructor(
    private readonly ragService: RagService,
    private readonly goalService: GoalService,
    private readonly modelGateway: ModelGatewayService,
  ) {
    // 使用统一的 Model Gateway
    this.models = this.modelGateway.getModels();
  }

  async createSession(userId: string, config: SessionConfig) {
    const model = this.models.getModel(
      config.provider, // 用户配置的提供商
      config.modelId, // 用户配置的模型
    );

    const agent = new Agent({
      initialState: {
        systemPrompt: this.buildSystemPrompt(userId),
        model,
        tools: this.buildTools(userId),
        messages: [],
      },
      streamFn: this.models.streamSimple.bind(this.models),
    });

    // 事件流 → WebSocket
    agent.subscribe((event) => {
      this.emitToClient(userId, this.mapEvent(event));
    });

    this.sessions.set(userId, agent);
    return agent;
  }

  private buildTools(userId: string): Tool[] {
    return [
      this.ragSearchTool(userId),
      this.proposeGoalTool(userId),
      this.proposeActionTool(userId),
      this.proposeMemoryTool(userId),
      this.getCurrentContextTool(userId),
      // ... 其他工具
    ];
  }
}
```

#### 4.2.3 Model Gateway Service（统一模型层）

```typescript
@Injectable()
export class ModelGatewayService {
  private models: Models;

  constructor(private readonly configService: ConfigService) {
    this.models = createModels();

    // 根据用户配置初始化提供商
    this.initProviders();
  }

  private initProviders() {
    const config = this.configService.get("models");

    // 用户可以配置任意提供商
    if (config.anthropic?.enabled) {
      this.models.setProvider(
        anthropicProvider({
          apiKey: config.anthropic.apiKey,
        }),
      );
    }

    if (config.openai?.enabled) {
      this.models.setProvider(
        openaiProvider({
          apiKey: config.openai.apiKey,
        }),
      );
    }

    if (config.google?.enabled) {
      this.models.setProvider(
        googleProvider({
          apiKey: config.google.apiKey,
        }),
      );
    }

    // 支持本地模型（Ollama、vLLM 等）
    if (config.local?.enabled) {
      this.models.setProvider(
        openaiCompatibleProvider({
          baseURL: config.local.baseURL,
          apiKey: "local",
        }),
      );
    }
  }

  getModels(): Models {
    return this.models;
  }

  // 供 Python 服务调用
  async invokeModel(request: ModelRequest): Promise<ModelResponse> {
    const model = this.models.getModel(request.provider, request.modelId);
    const response = await this.models.complete(model, request.context);
    return response;
  }
}
```

## 5. Agent Runtime

### 5.1 Pi Agent Core（实时交互）

**技术**：`@earendil-works/pi-agent-core` + `@earendil-works/pi-ai`

**核心能力**：

- Agent Loop（处理一次聊天回合）
- 多轮上下文处理
- Tool Calling 和参数校验
- 流式 Agent 事件
- 运行取消和状态管理

**事件流**：

```
prompt("Hello")
├─ agent_start
├─ turn_start
├─ message_start { userMessage }
├─ message_end { userMessage }
├─ message_start { assistantMessage }
├─ message_update { text_delta }（流式输出）
├─ tool_execution_start { toolName, args }
├─ tool_execution_end { result }
├─ message_end { assistantMessage }
├─ turn_end
└─ agent_end
```

**工具分层**：

**只读工具**：

- `search_records`：搜索历史记录
- `get_current_context`：获取当前上下文
- `get_goal_context`：获取目标上下文
- `get_action_context`：获取行动上下文
- `retrieve_evidence`：检索依据
- `get_suggestion_evidence`：获取建议依据

**提议型工具**：

- `propose_action`：提议行动
- `propose_goal_change`：提议目标变更
- `propose_memory`：提议记忆保存
- `propose_decision`：提议决策记录
- `propose_reminder_change`：提议提醒变更

**正式写入**：

- 不作为普通 Agent Tool 暴露
- 统一通过 `SubmitConfirmationBatch` 和 NestJS 业务逻辑

### 5.2 LangGraph（复杂工作流）

**技术**：LangGraph + LangChain（Python）

**适用场景**：

- 多阶段资料研究
- 长时间运行的 AI 任务（需要暂停/恢复）
- 复杂周复盘（多节点、多分支）
- 附件深度解析（v1.1）
- 多 Agent 协作任务

**工作流示例（每周复盘）**：

```python
from langgraph.graph import StateGraph, END
from langchain_anthropic import ChatAnthropic
from langchain_openai import ChatOpenAI

class WeeklyReviewWorkflow:
    def __init__(self, user_id: str, model_config: dict):
        self.user_id = user_id

        # 根据用户配置选择模型
        if model_config['provider'] == 'anthropic':
            self.model = ChatAnthropic(
                model=model_config['model_id'],
                api_key=model_config['api_key']
            )
        elif model_config['provider'] == 'openai':
            self.model = ChatOpenAI(
                model=model_config['model_id'],
                api_key=model_config['api_key']
            )

        self.graph = self._build_graph()

    def _build_graph(self):
        graph = StateGraph(ReviewState)

        # 多阶段分析流程
        graph.add_node("fetch_data", self.fetch_week_data)
        graph.add_node("analyze_goals", self.analyze_goals)
        graph.add_node("analyze_actions", self.analyze_actions)
        graph.add_node("generate_insights", self.generate_insights)
        graph.add_node("create_report", self.create_report)

        # 条件分支
        graph.add_conditional_edges(
            "fetch_data",
            self.should_continue,
            {
                "continue": "analyze_goals",
                "insufficient_data": "create_fallback"
            }
        )

        graph.add_edge("analyze_goals", "analyze_actions")
        graph.add_edge("analyze_actions", "generate_insights")
        graph.add_edge("generate_insights", "create_report")
        graph.add_edge("create_report", END)

        graph.set_entry_point("fetch_data")

        # 使用 Checkpoint 支持暂停/恢复
        return graph.compile(
            checkpointer=SqliteSaver("workflow_checkpoints.db")
        )

    async def run(self, thread_id: str):
        result = await self.graph.ainvoke(
            {"user_id": self.user_id},
            config={"configurable": {"thread_id": thread_id}}
        )
        return result
```

### 6.2 职责范围

**核心职责**：

- 结构化输出辅助处理
- 复杂 AI 任务（长时间、可暂停、可恢复）

**LangChain 使用边界**：

**用于**：

- Retriever 集成（向量检索、混合检索）
- Embedding 集成（OpenAI、Cohere、本地 BGE）
- Reranker 集成（Cohere Rerank、本地 BGE Rerank）
- 文档加载和解析（LlamaParse、Unstructured）
- Prompt 辅助（PromptTemplate、ChatPromptTemplate）
- 结构化输出（Pydantic 模型）
- 基础 AI Chain（LCEL）

**不负责**：

- 正式业务状态（由 NestJS + PostgreSQL 管理）
- 确认中心
- 目标/行动状态机
- 正式对象删除和撤销

**LangGraph 使用边界**：

**限定用于**：

- 多阶段资料研究
- 长时间运行的 AI 任务
- 需要暂停和恢复的任务
- v1.1 附件深度解析
- 复杂周复盘
- 多节点、多分支、多工具 AI 流程

**状态管理**：

- LangGraph 只保存 AI 工作流状态（Graph State、Checkpoint、Interrupt）
- 产品正式状态仍由 NestJS 管理（Goal、Action、Memory、Decision、ConfirmationBatch）

**多层记忆架构**（优化点）：

```sql
-- 工作记忆（短期，当前对话）
CREATE TABLE working_memory (
  id UUID PRIMARY KEY,
  session_id UUID REFERENCES sessions(id),
  content TEXT,
  context JSONB,
```

```typescript
// src/obsidian/obsidian-import.service.ts
@Injectable()
export class ObsidianImportService {
  private watcher: FSWatcher;

  async startWatching() {
    this.watcher = fs.watch(
      this.vaultPath,
      { recursive: true },
      async (event, filename) => {
        if (filename.endsWith(".md")) {
          await this.handleFileChange(filename);
        }
      },
    );
  }

  private async handleFileChange(filename: string) {
    const content = await fs.readFile(
      path.join(this.vaultPath, filename),
      "utf-8",
    );

    // 解析 frontmatter
    const { data: frontmatter, content: body } = matter(content);

    if (frontmatter.type === "goal") {
      // 检查是否已存在
      const existingGoal = await this.goalService.findById(frontmatter.id);

      if (existingGoal) {
        // 冲突检测
        if (existingGoal.updatedAt > new Date(frontmatter.updated)) {
          // 数据库更新，忽略文件变更或提示用户解决冲突
          await this.handleConflict(existingGoal, frontmatter, body);
        } else {
          // 文件更新，创建候选等待确认
          await this.createGoalCandidate(frontmatter, body);
        }
      } else {
        // 新目标，创建候选
        await this.createGoalCandidate(frontmatter, body);
      }
    }
  }

  private async createGoalCandidate(frontmatter: any, body: string) {
    // 通过确认中心创建候选
    await this.goalService.createCandidate({
      title: this.extractTitle(body),
      description: body,
      status: "pending_confirmation",
      source: "obsidian_import",
      sourceMetadata: { frontmatter },
    });
  }
}
```

### 12.1 外发敏感信息策略

**所有离开私有核心主机的数据**都经过：


**覆盖**：

- OCR API
- 网页解析服务
- 第三方工具

**强制识别类别**：

- 身份证件（正则匹配）
- 银行卡（Luhn 算法）
- 密码模式（连续字符、键盘序列）
- API Key 和密钥格式

```typescript
// src/security/egress-policy.service.ts
@Injectable()
export class EgressPolicyService {
  async checkPayload(payload: any, destination: string): Promise<EgressDecision> {
    const sensitive = this.detectSensitive(payload);

    if (sensitive.length === 0) {
      return { action: 'allow', payload };
    }

    // 检查用户隐私设置
    const userPolicy = await this.getUserPolicy();

    if (userPolicy.mode === 'strict') {
      // 严格模式：自动脱敏
      return {
        action: 'redact',
        payload: this.redactSensitive(payload, sensitive),
        redacted: sensitive.map(s => s.type)
      };
    } else if (userPolicy.mode === 'ask') {
      // 询问模式：等待用户决定
      return {
        action: 'ask_user',
        payload,
        sensitive,
        destination
      };
    }
  }

  private detectSensitive(payload: any): SensitiveItem[] {
    const items: SensitiveItem[] = [];

    // 身份证
    if (this.idCardPattern.test(payload)) {
      items.push({ type: 'id_card', value: '***', position: ... });
    }

    // 银行卡
    if (this.bankCardPattern.test(payload)) {
      items.push({ type: 'bank_card', value: '***', position: ... });
    }

    // API Key
    if (this.apiKeyPattern.test(payload)) {
      items.push({ type: 'api_key', value: '***', position: ... });
    }

    return items;
  }
}
```

2. ✅ Pi Agent 可以处理普通聊天，流式事件正常
3. ✅ NestJS 稳定集成 pi-agent-core 和 pi-ai
4. ✅ Pi Agent 的工具调用和事件流正常
5. ✅ Agent 取消不会破坏状态
6. ✅ PostgreSQL 可以保存聊天对象和确认事务
7. ✅ pgvector 与结构化查询协作正常
8. ✅ NestJS 可以按需调用 Python FastAPI
9. ✅ Python 服务无法直接写入正式业务对象
10. ✅ External Data Egress Policy 可以覆盖所有外发数据
11. ✅ 本地文件系统支持附件保存、解析、删除、导出
12. ✅ BullMQ 可以支持定时任务和重试
13. ✅ Obsidian 双向同步可以正常运行
14. ✅ Docker Compose 可以启动并恢复所有服务
15. ✅ 用户可以自由配置和切换模型

## 16. 最终技术栈总结

```text
【前端】
Expo + React Native + TypeScript + Expo Router

【通信】
WebSocket（全双工实时通信）

【业务层】
NestJS + TypeScript
+ Pi Agent Service（实时交互）
+ Workflow Service（复杂任务调度）
+ Model Gateway Service（统一模型层）

【Agent 层】
Pi Agent Core + pi-ai（TypeScript，实时交互）
LangGraph + LangChain（Python，复杂工作流）

【模型层】
pi-ai（统一的多提供商接口）
支持：Anthropic、OpenAI、Google、本地模型（Ollama/vLLM）
用户可配置和切换

【AI/RAG 层】
Python + FastAPI
LangChain（RAG 集成）
LangGraph（复杂工作流）

【数据层】
PostgreSQL + pgvector（多层记忆架构）
本地文件系统（附件和导出）

【任务队列】
BullMQ（TypeScript，Redis-backed）

【知识库】
Obsidian 双向同步

【可观测性】
Winston（日志）+ Prometheus + Grafana（监控）+ OpenTelemetry（追踪）

【部署】
Docker Compose + 私有核心主机
支持 GPU（可选）
```

## 17. 与原方案的主要差异

| 维度       | 原方案                   | 最终方案             | 原因                                    |
| ---------- | ------------------------ | -------------------- | --------------------------------------- |
| 通信协议   | HTTP + SSE               | WebSocket            | 真正的双向实时通信，支持复杂交互        |
| Agent 架构 | 单一 Pi Agent            | Pi Agent + LangGraph | 实时交互（Pi）+ 复杂工作流（LangGraph） |
| 后台任务   | PostgreSQL BackgroundJob | BullMQ               | TypeScript 原生，功能更强大             |
| 知识库     | Obsidian 单向导出        | Obsidian 双向同步    | 极大提升实用性，融入用户工作流          |
| 多模态     | v1.1 引入                | v1.0 全面支持        | 现代 AI 助手标配，技术已成熟            |
| 可观测性   | 基础日志                 | 完善的日志+监控+追踪 | 持续优化的基础，私有部署必需            |
| 模型配置   | 未明确                   | 用户可配置任意模型   | 灵活性和可扩展性                        |
