## 1. 文档目的与使用规则

本文件回答的不是“本地是否允许保存用户完整内容”，而是以下问题：

```text
本地保存的完整内容
如何在每次对外发送前被统一识别、按设置处理、阻止绕过，
并且不与正式业务变更确认混淆？
```

术语约定：

- **本地完整内容**：本地原始记录、附件、结构化对象、长期记忆、处境模型及其派生内容中允许按既有规则保存的真实内容。
- **外发内容**：已经为某次外部模型调用组装完成、即将交给外部供应商的请求内容；包含文本、附件解析文本、RAG 上下文和工具参数等实际发送载荷。
- **敏感命中**：本地策略在外发内容中识别出的疑似敏感片段或来源标记；它不等于业务对象已确认，也不等于识别绝对正确。
- **隐私外发确认**：用户决定某一外发内容是否可按指定处理结果发送的操作。
- **业务变更确认**：用户决定目标、行动、长期记忆、删除或其他正式对象是否在本地生效的操作。

除非上游文档已经明确确认，本文件中的“推荐答案”均为待产品确认的详细方案，不得被实现为不可配置、不可替换的规则。

## 2. 已确认约束摘要

以下是上游文档已经确认、实现不得违反的边界：

1. v1 优先本地保存；本地完整保存与对外模型发送严格分离。
2. v1 强制识别的敏感类别为：身份证件、银行卡、密码、API Key 和其他密钥。
3. 外部模型请求发出前必须经过敏感信息处理；脱敏后可以继续发送。
4. 统一拦截覆盖普通请求、带 RAG 的请求、后台任务请求和模型重试请求；客户端不能绕过 Local Core 直接调用外部模型。
5. 已确认的敏感信息可以保存到本地长期记忆，但需要单独分组、明显标记，不能被“确认全部”无提示保存；外部模型不能看到未脱敏值。
6. 隐私外发确认与业务变更确认是两条不同边界，任意一方不能替代另一方。
7. 基础模型调用日志只保留基础元数据，不自动保存完整模型输入上下文、完整 RAG 结果、完整模型原始回复或 API Key。
8. v1 需要应用访问保护；导出需要支持加密或设置密码；API Key 不得进入普通导出包。
9. 敏感信息的具体识别器、脱敏替换格式、提醒模式交互、误报／漏报处理和单次放行规则仍未确认；本地数据库和原始附件是否额外加密也仍未确认。

## 3. 关键问题与推荐答案

### 问题 1：v1 到底识别哪些身份证件、银行卡、密码和密钥内容？

**推荐答案：** v1 以“外发风险类别”为最小稳定边界，而不是以某一种国家证件格式、某一供应商密钥前缀或某一正则表达式作为产品边界。识别结果应同时保留类别、命中位置或来源、识别置信信息和处理结果，但不应把命中的明文复制到策略日志中。

建议的类别解释如下；这是识别范围说明，不是对具体格式、规则库或 OCR 能力的冻结：

| 已确认类别 | 建议覆盖的内容边界 | 不应据此假定已经确定的细节 |
|---|---|---|
| 身份证件 | 用户在文本、附件解析结果、记忆或 RAG 片段中出现的证件号码、证件图像／扫描件的可识别文字，以及能直接用于身份核验的证件字段组合。 | 证件种类清单、各国号码校验规则、图片 OCR 的识别器和置信阈值。 |
| 银行卡 | 卡号、卡片图像／解析文字，以及与卡号一起出现、足以增加支付或账户风险的关联字段。 | 是否把账户号、支付口令、有效期或安全码分别归类、如何校验和如何处理局部号码。 |
| 密码 | 明示的登录密码、口令、一次性验证码、恢复码，以及在配置、命令或附件中以“密码值”方式出现的内容。 | 密码字段名词表、口令强度判断、一次性验证码是否与其他类别合并展示。 |
| API Key 和其他密钥 | API Key、访问令牌、私钥、服务账号凭据、会话令牌和其他可用于认证、签名、调用或取得权限的秘密值。 | 各供应商前缀库、私钥格式、熵判断、是否支持特定代码仓库或配置文件解析器。 |

**已确认边界：** 上述四类是 v1 必须在外部模型调用前识别的类别；其他敏感类别暂未被列为 v1 强制识别范围。本地敏感标记可出现在原始记录、附件、事实、长期记忆、目标、行动、行动结果、处境模型和索引内容中，但标记不能代替识别器，也不能证明内容一定已被正确识别。

**待决策项：** 各类别的子类型、格式规则、附件和图像识别深度、置信阈值、规则库更新方式，以及“疑似”与“确认命中”的交互文案。

### 问题 2：统一外发拦截应位于哪里，如何避免漏掉调用路径？

**推荐答案：** 将唯一强制执行点放在“完整外发请求已经组装完成、供应商适配器尚未取得载荷”之间。业务任务只能请求 Local Core 生成外发请求；供应商适配器只能接收经过策略钩子判定后的可发送载荷，不能接收原始上下文。

```text
业务任务
→ 分析编排／上下文组装／RAG 检索
→ External Request Builder（完整外发请求）
→ Sensitive Information Policy Hook（识别、策略判定、提醒／脱敏／阻止）
→ Model Provider Adapter
→ 外部模型供应商
```

此处的“完整”是指本次真正会离开设备的全部内容已经合并完成，而不是只扫描用户刚输入的一段文字。策略钩子应对最终载荷重新检查；不能仅依赖原始记录或索引对象上已有的敏感标记。

**已确认边界：** 上游架构已固定上述逻辑位置，并要求覆盖用户本次输入、RAG 结果、当前目标和行动、长期记忆、处境模型、附件解析结果、每日摘要和周复盘上下文、工具参数、后台任务以及每次重试请求。客户端不得绕过 Local Core 直接调用模型。

**待决策项：** 外部 Embedding、外部语音识别、外部 OCR 或未来第三方工具是否属于同一“外发接收方”并复用该钩子；这些外部能力的具体接入方式尚未冻结。推荐后续统一采用同一外发策略边界，但不能在本文件中视为既成事实。

### 问题 3：提醒模式、脱敏模式和禁止发送模式分别应如何工作？

**推荐答案：** 将策略结果表达为三种用户可理解的结果，而不是把“检测到敏感信息”直接等同于“拒绝请求”：

| 策略结果 | 推荐行为 | 用户看到的重点 |
|---|---|---|
| 自动脱敏后发送 | 在本地将本次外发载荷处理为不含未脱敏敏感值的版本，再发送处理后的版本。 | 告知命中的类别、处理结果和本次是否已外发；不展示被替换的完整秘密值。 |
| 提醒并等待决定 | 暂停该次外发，不把原始载荷交给供应商；待用户查看处理说明后，再选择按处理后内容发送、取消或返回编辑。 | 清楚区分本地保留的完整内容与外部将收到的处理后内容。 |
| 禁止发送 | 阻断本次外发，不因任务紧急、后台执行或重试而自动降级为发送。 | 告知被阻断的敏感类别及可选的本地处理方式。 |

推荐把“提醒”理解为需要用户完成隐私外发决策的模式，而不是只弹出提示后自动继续；后台没有前台交互时，不应静默把提醒模式转换为自动发送。

**已确认边界：** 敏感信息处理由设置控制；已确认需要支持“提醒或脱敏”的策略方向，脱敏后继续发送。上游交接文档还列出了自动脱敏后发送、发送前查看并确认、检测到敏感信息时禁止发送等设置方向，并给出“自动脱敏后发送”作为当前默认建议。

**待决策项：** 最终向用户开放的模式集合、默认值、模式名称、提醒时暂停还是提示后继续、提醒卡片内容、是否允许逐段编辑处理结果，以及禁止发送后的恢复路径。上述内容在确认前不得以本文推荐替代产品决策。

### 问题 4：普通对话、RAG、后台任务和重试如何保证使用同一套规则？

**推荐答案：** 以“任何一次外部模型请求”作为统一处理单元，而非按功能页面分别实现。每次请求在最终载荷生成后都经历同一策略链路，并携带请求来源和任务类型用于展示与最小日志；策略本身不因来源不同而跳过。

| 场景 | 推荐处理方式 |
|---|---|
| 普通对话／输入分析 | 扫描本次用户输入与为回答补充的全部上下文；只向供应商交付策略允许的最终载荷。 |
| RAG 问答与建议 | 先在本地完成召回和来源组装，再扫描最终选中的 RAG 片段及用户问题；不能因为原文已经在本地索引中就跳过检查。 |
| 后台任务 | 每日摘要、周复盘、提醒相关建议等在需要调用模型时走同一网关。遇到需用户决定的提醒模式，推荐将任务停留为待处理／可通知状态，而不是后台自动外发。 |
| 同模型重试和跨模型切换 | 每一次实际请求都重新经过策略钩子；不能把首次扫描或首次批准机械复用于内容、模型、工具参数或上下文已经变化的请求。 |
| 模型连接测试 | 若测试只包含系统生成的无用户内容，则仍经统一网关但通常不会命中用户数据；若测试包含用户提供的内容，必须按一般请求处理。 |

**已确认边界：** 普通请求、RAG、后台任务和重试请求均必须在发出前通过敏感信息处理；当前模型失败后重试或切换模型时，每次请求重新经过敏感处理。后台任务可生成建议、提醒和候选，但不能绕过确认中心写入正式对象。

**已落实补充：** 提醒模式使用持久化隐私外发记录；默认 15 分钟过期，过期后任务以 `EGRESS_001` 失败且不调用 Provider。单次决定绑定任务、请求指纹、Provider、Model ID 和来源，任一项变化即失效；服务重启后从数据库恢复 ready 决定。通知渠道与模型连接测试的具体载荷仍待后续任务收口。

### 问题 5：敏感信息保存到本地长期记忆后，何时可以、何时不可以对外发送？

**推荐答案：** 将“保存为敏感记忆”和“作为本次外发上下文”拆为两个连续但独立的判定：

```text
用户确认保存敏感长期记忆
→ 本地写入敏感标记、来源和确认信息
→ 后续需要检索时可在本地受限召回
→ 被选入某次外发上下文后
→ 再经该次完整外发载荷的敏感策略处理
→ 只有处理后的内容可发送
```

敏感记忆应在确认界面明确提示本地会保存什么、属于何种敏感类别，以及外部模型不会收到未脱敏值。将其标记为敏感不意味着永不参与本地 RAG；也不意味着可以绕过外发前处理。

**已确认边界：** 用户确认后敏感信息可写入本地长期记忆，并应单独分组、明显标记，不能因“确认全部”无提示保存。RAG 检索结果含有敏感标记；外部模型不能看到未脱敏敏感值。本地数据库和原始文件是否额外加密尚未确认，不能把“允许本地保存”误写为“已经采用某种静态加密”。

**待决策项：** 敏感长期记忆的单独确认交互、列表访问和编辑权限、是否默认排除于某些 RAG 场景、敏感标记传播规则、存储加密方案与密钥管理方案。

### 问题 6：隐私外发确认与业务变更确认的先后关系是什么？

**推荐答案：** 两类确认分别表达不同用户意图，并使用不同的状态与幂等边界：

```text
隐私外发确认：是否允许“这一次”按处理后的内容离开设备
业务变更确认：是否允许目标／行动／长期记忆等正式对象在本地生效
```

若一次交互同时涉及敏感外发和敏感记忆候选，推荐流程为：先在模型调用前依据隐私模式完成或等待隐私处理；模型返回后，如产生正式业务候选，再由确认中心完成业务变更确认。业务确认卡片可以展示与本次外发有关的提示，但不能把确认业务对象视为已同意外发；同样，用户同意本次处理后外发，也不能创建或保存任何正式对象。

对于模型尚未调用、但用户手工创建敏感记忆的情况，不应凭空要求隐私外发确认，因为此时并没有外发；仍应走业务确认。对于已经完成外发、后续用户拒绝业务候选的情况，应保留两者独立结果，不能倒推已发生的外发不存在。

**已确认边界：** 确认中心只处理业务变更确认；隐私外发是另一边界。涉及敏感长期记忆或敏感外发时，界面必须显式说明敏感类别、本地将保存什么、外部模型将收到什么处理后内容、是否已脱敏以及是否需要单独确认外发。

**待决策项：** 两类确认是否可在同一屏呈现、前后顺序的具体交互、隐私确认的撤销提示、被阻断请求是否保留为草稿或候选，以及确认操作的具体标识和持久化模型。

### 问题 7：误报、漏报和单次放行应如何处理？

**推荐答案：** 识别能力应被视为风险降低措施，而不是“已识别即绝对正确”或“未命中即绝对安全”。处理原则如下：

- **误报**：向用户展示类别和本次外发影响，不在普通日志中暴露完整命中值；推荐允许用户返回编辑、取消发送，或在明确的单次隐私决定后继续该次处理。不得因为一次误报自动建立永久白名单。
- **漏报**：继续依靠最终载荷统一拦截、所有重试重复检查、最小必要上下文和用户可见来源等多层约束降低影响；系统不能承诺对所有格式、图片或语义表达零漏报。
- **单次放行**：推荐只对一个已经确定的外发请求及其处理后载荷生效，不能自动扩展为同一会话、同一记忆、同一类别、后续后台任务或后续重试的永久许可。若请求内容发生变化，推荐重新判定；具体“变化”的比较范围需要后续确认。
- **纠错反馈**：推荐记录不含敏感明文的最小处理结果和用户动作，用于排查策略质量；是否建立用户级规则、白名单或反馈训练闭环尚不确定。

**已确认边界：** 误报、漏报和单次放行规则均未冻结；因此实现不能暗中加入永久放行、全局白名单、自动接受误报或“检测失败后继续发送”等行为。敏感标记不能保证所有敏感内容均已被正确识别。

**待决策项：** 用户可选择的误报动作、单次放行的有效范围和失效条件、是否支持对某一内容重新检测、漏报的用户反馈入口、策略质量指标和最小审计字段。

### 问题 8：日志、调试信息和数据导出可以保存、展示或带走哪些敏感内容？

**推荐答案：** 将“业务数据导出”与“模型调用日志”严格分开：前者是在用户主动导出本地个人数据时按导出保护规则处理，后者仅用于基础调用可观测性，默认不复制请求正文。策略执行过程只记录满足排障和状态展示所需的最小元数据，不记录完整敏感片段或原始外发载荷。

| 内容 | 已确认或推荐处理 |
|---|---|
| 基础模型调用日志 | 已确认仅保留基础元数据；不得自动记录完整请求上下文、完整 RAG 结果、完整模型原始回复或 API Key。具体字段和保留周期后续确定。 |
| 敏感策略日志 | 推荐只记录是否命中、类别、策略结果、请求来源／任务类型、是否发生重试和最小错误摘要；不记录命中明文、替换前后完整正文或 API Key。 |
| 普通业务导出 | 已确认支持 Markdown、JSON 和原始文件压缩包，并覆盖核心业务数据、关系和必要历史；由于本地原始记录和敏感记忆可被保存，完整导出可能包含敏感内容。 |
| API Key 与配置秘密 | 已确认不得进入普通导出包，也不得进入基础调用日志。 |
| 导出保护 | 已确认导出需支持加密或设置密码；具体加密格式、密码规则、目录结构、敏感内容是否默认排除及导出前提示均尚待《v1-数据导出》确认。 |

推荐在用户发起导出前提示其所选范围是否可能包含原始记录、附件或敏感记忆，但不在本文件中预设默认勾选项、导出包格式或密码实现。

**已确认边界：** 导出不能只导出当前列表而丢失来源关系和历史状态；完整导出默认可涵盖原始记录、结构化对象、来源关系和附件，聊天展示、待确认内容、过期对象和基础调用记录可作为可选项。数据库额外加密、原始文件单独加密、导出加密格式和密码规则未确认。

**待决策项：** 日志字段全集与保留周期、策略日志是否单独展示、导出范围默认值、敏感内容预览与二次确认、导出失败后的临时文件清理，以及具体加密和密码方案。

## 4. 推荐的统一状态与失败边界

以下是为后续实现提供的推荐状态语义，不改变已经确认的业务确认事务规则：

```text
外发请求已组装
→ 未检测到敏感信息：可发送
→ 检测到敏感信息：按当前策略
   ├── 已脱敏可发送
   ├── 等待隐私决定
   ├── 已阻断
   └── 已取消
→ 已交给供应商／调用失败可重试／最终失败
```

推荐约束：

1. 只有“可发送”或“已脱敏可发送”的最终载荷可以到达供应商适配器。
2. 因策略等待、取消或阻断而未发出的请求，不应被计入模型供应商调用成功；但可在最小状态记录中反映本地阻断结果。
3. 模型调用超时或失败后的重试，必须重新走外发策略；不得从日志、缓存或先前失败请求中直接取出未处理载荷发送。
4. 用户的业务确认事务仍遵循确认中心的原子性、幂等和版本校验；隐私处理失败、取消或阻断不得产生正式对象。
5. 后台任务遇到需要用户决定的隐私状态时，推荐保留任务幂等键和最小状态，等待用户处理或按后续规则终止，不能重复弹出或重复外发。

其中，具体状态名称、存储表结构、任务重试次数和隐私确认操作的幂等键均为待技术设计内容。

## 5. 已确认边界与待决策项汇总

### 5.1 本文件继承的已确认边界

- v1 必须识别身份证件、银行卡、密码、API Key 和其他密钥。
- 本地完整内容可按既有规则保存；对外请求必须先检查和处理。
- 拦截位于完整外发请求组装后、外部模型请求发出前，由 Local Core 的统一模型网关链路执行。
- 普通对话、RAG、后台任务、工具参数和每次模型重试均在覆盖范围内。
- 脱敏后可继续发送；外部模型不能看到未脱敏敏感值。
- 敏感长期记忆经用户确认后可在本地保存，且需要显著标记和单独提示。
- 隐私外发确认与业务变更确认相互独立。
- 基础调用日志不保存完整上下文、完整 RAG 结果、完整原始回复或 API Key。
- API Key 不进入普通导出包；导出需要加密或设置密码。

### 5.2 本次推荐、尚待确认后采纳的方案

- 用“最终外发载荷”作为统一扫描对象，并令供应商适配器仅接收策略通过后的载荷。
- 把提醒模式设计为暂停并等待用户隐私决定，后台任务不静默自动发送。
- 将单次放行限制为一次确定的外发请求，不建立永久或全局许可。
- 对策略审计仅保留不含敏感明文的最小元数据。
- 敏感记忆可受限参与本地检索，但每次选入外发上下文后再次检查。
- 任何外部接收方最终应复用统一外发策略；外部 Embedding、OCR、语音识别和工具接入范围待另行确认。

### 5.3 仍待产品／技术决策的内容

- 身份证件、银行卡、密码和密钥的具体子类型、识别器、规则库、OCR 边界和置信阈值。
- 脱敏替换格式、同一实体是否使用稳定占位符、是否保留局部可见信息。
- 最终隐私模式集合、默认值、提醒交互、阻断后的恢复方式和后台等待策略。
- 误报处理、漏报反馈、单次放行范围与失效条件，是否支持白名单或用户规则。
- 隐私确认的页面布局、操作标识、状态持久化、超时和撤销提示。
- 外部 Embedding、外部 OCR、外部语音识别、第三方工具等非主模型调用的具体外发边界。
- 本地数据库、原始附件和敏感长期记忆的额外静态加密方案与密钥管理。
- 基础调用日志与敏感策略日志的具体字段、保留周期、查看权限和删除策略。
- 导出包的目录结构、加密格式、密码规则、敏感内容默认范围、预览与二次确认。

## 6. 验收标准

以下标准按“已确认约束必须满足”和“推荐方案确认后应满足”分开使用。

### 6.1 已确认约束验收

- 用户输入、RAG 结果、长期记忆、处境模型、附件解析结果、工具参数、后台任务上下文和每次重试请求，在实际交给外部模型前均会进入敏感处理链路。
- 客户端不能绕过 Local Core 或模型网关直接把业务内容交给外部模型。
- 系统至少对身份证件、银行卡、密码、API Key 和其他密钥执行外发前识别；未将其他类别误表述为 v1 已强制覆盖项。
- 在脱敏发送路径中，外部模型拿不到未脱敏的敏感值。
- 敏感信息在用户确认后可以作为本地长期记忆保存，并有敏感标记和显著提示；保存敏感记忆不自动等于对外发送许可。
- 业务变更确认与隐私外发确认分别表达、分别记录；任何一项均不能替代另一项。
- 后台任务只能生成建议、提醒和候选，不能因敏感处理或重试而绕过确认中心创建正式对象。
- 基础调用日志不含完整请求上下文、完整 RAG 结果、完整模型原始回复或 API Key。
- 普通导出包不含 API Key；导出流程提供加密或设置密码的能力。

### 6.2 本次推荐方案确认后验收

- 每个外部供应商适配器只接收经统一策略判定后的最终载荷；无法从适配器接口取得未经处理的完整上下文。
- 提醒模式下，请求在用户作出隐私决定前不会发送；后台任务不会把等待决定静默转换为自动发送。
- 同一业务请求在重试或切换模型时会重新经过策略钩子；新的或变化后的外发载荷不会复用不适用的处理结果。
- 单次放行仅覆盖确认时对应的一次外发请求；后续会话、后台任务、重试或内容变化后的请求不会自动继承。
- 命中、阻断、取消和失败的策略记录不包含敏感明文、完整原始载荷、完整替换前后文本或 API Key。
- 用户导出前能够获知所选范围可能包含敏感原始记录、附件或敏感记忆；具体提示内容按后续导出方案验收。
- 误报、漏报或未确认的技术细节不会被伪装成“已解决”或“零风险”；界面与文档明确保留相应待决策边界。
