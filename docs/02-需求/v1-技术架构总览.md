## 1. 架构定位

### 1.1 运行形态

```text
单用户私有部署
├─ 私有核心主机（用户可控）
├─ Expo 移动客户端（iOS/Android）
└─ 未来：电脑端访问（方式待定）
```

### 1.2 "本地优先"定义

用户数据优先保存在用户控制的私有核心主机，不是"每个终端独立本地数据库"。

### 1.3 v1 范围边界

**提供**：

- 单用户私有部署
- 手机客户端（Expo）
- 电脑端访问（实现方式待定）

**不包含**：

- 多用户/多租户
- 公共云 SaaS
- 多设备同步和冲突合并
- 完全离线可用

## 3. 核心服务边界

### 3.1 Expo 客户端

**职责**：

- 文字、语音、图片、文件输入
- 聊天和流式事件展示
- 确认中心和候选卡片
- 目标、行动、记忆、建议页面
- 模型配置和切换
- 本地通知

**边界**：

- 不直接访问数据库
- 不调用 Python AI 服务
- 不调用外部模型
- 不自行组装 RAG 上下文

### 3.2 NestJS Business Core

**职责**：

- API 和认证
- 会话和消息管理
- 确认中心和状态机
- Goal/Action/Memory/Decision 业务逻辑
- RAG 编排和上下文组装
- 外发安全策略
- Pi Agent 和 LangGraph 调度
- 后台任务管理（BullMQ）

### 3.3 Agent Runtime

**Pi Agent（实时交互）**：

- 陪伴聊天、辅助解答、行动协助
- 流式事件和工具调用
- 只读工具和提议型工具

**LangGraph（复杂工作流）**：

- 每日摘要、每周复盘
- 多阶段分析任务
- 长时间运行的后台任务
- 支持暂停/恢复

**pi-ai（统一模型层）**：

- 多提供商统一接口
- 支持 Anthropic、OpenAI、Google、本地模型
- 用户可配置和切换

### 3.4 Python AI/RAG Service

**职责**：

- RAG 召回和重排
- Embedding
- 文档解析和多模态处理
- LangChain 集成
- LangGraph 复杂工作流

**边界**：

- 不直接创建/修改正式业务对象
- 不绕过 NestJS 的确认中心
- 只返回候选和分析结果

### 3.5 PostgreSQL + pgvector

**PostgreSQL（权威数据）**：

- 用户/设备
- 会话/消息/记录
- 候选/确认
- Goal/Action/Memory/Decision
- 提醒/任务/导出
- 多层记忆架构

**pgvector（派生检索层）**：

- Embedding 向量
- 向量检索
- 可重建的派生索引

## 4. 关键数据流

### 4.1 用户输入 → Agent 响应

```text
用户消息（文字/语音/图片/文件）
→ NestJS 保存原始记录
→ 判断场景和是否需要 RAG
→ RAG（PostgreSQL + pgvector + Python）
→ 组装上下文 + 外发安全检查
→ Pi Agent（实时）或 LangGraph（复杂任务）
→ 模型调用（通过 pi-ai）
→ 返回结果（回复/分析/候选）
→ 保存消息和候选
→ WebSocket 推送到客户端
```

### 4.2 确认流程

```text
Agent 生成候选
→ 用户在确认中心查看
→ 用户提交确认
→ NestJS 校验（版本/权限/风险）
→ 数据库事务（创建/更新正式对象 + 记录来源和变更）
→ 登记索引更新任务
→ 提交事务
→ 异步刷新索引
```

### 4.3 后台任务

```text
定时触发（摘要/复盘/提醒）
→ BullMQ 任务队列
→ NestJS 查询数据 + 组装上下文
→ Python AI（LangGraph）
→ 生成结果/候选
→ 需要确认的进入确认中心
→ 通知用户
```

## 5. 安全边界

### 5.1 外发安全策略

所有离开私有核心主机的数据都经过：

```text
最终载荷组装
→ External Data Egress Policy
→ 脱敏/等待决定/阻止
→ 外部适配器
```

**覆盖范围**：

- pi-ai 模型请求
- Python AI 的外部模型请求
- Embedding/语音识别/OCR
- 网页解析/第三方工具

**必须防止**：

- Agent 绕过策略直接访问模型
- Python 绕过 NestJS 直接发送个人数据
- 未脱敏的秘密外发

### 5.2 权威性边界

**权威数据**：

- PostgreSQL 正式业务对象
- 原始文件存储中的附件

**派生数据**：

- pgvector、全文索引
- RAG 依据集合
- 摘要、复盘结果
- Agent Session
- LangGraph Checkpoint

## 6. 部署架构

### 6.1 Docker Compose

```yaml
services:
  nestjs: # NestJS Business Core
  python-ai: # Python FastAPI AI Service
  postgres: # PostgreSQL + pgvector
  redis: # BullMQ 任务队列
```

### 6.2 部署位置

- 用户自有电脑
- 家用小主机（NUC、Mac Mini）
- NAS（Synology、QNAP）
- 用户控制的私有服务器

## 7. v1.0 核心范围

**必须落地**：

- Expo 移动客户端（iOS/Android）
- NestJS 业务后端
- Pi Agent + LangGraph 混合架构
- PostgreSQL + pgvector
- BullMQ 后台任务
- 基础 RAG
- 每日摘要和到期提醒
- Obsidian 双向同步
- 多模态支持（语音/图片/文档）
- 可观测性（Winston + Prometheus + Grafana + OpenTelemetry）

## 8. 技术栈总结

```text
前端：Expo + React Native + TypeScript
通信：WebSocket（全双工）
业务：NestJS + TypeScript
Agent：Pi Agent Core + LangGraph
模型：pi-ai（用户可配置）
数据：PostgreSQL + pgvector
任务：BullMQ（Redis-backed）
AI/RAG：Python + FastAPI + LangChain + LangGraph
知识库：Obsidian 双向同步
部署：Docker Compose + 私有核心主机
```

## 9. 权威边界

```text
NestJS + PostgreSQL = 业务权威
Pi Agent = 实时交互底座
LangGraph = 复杂工作流层
Python = AI/RAG 执行层
pgvector = 派生检索层
Obsidian = 知识交换层
```

**不允许**：

- Agent 直接写正式对象
- Python 直接写正式业务表
- RAG 直接修改业务状态
- Obsidian 修改直接回写业务对象
- 索引替代 PostgreSQL 权威数据
