# 行动预览自动意图识别实施计划

> 目标：删除聊天输入框的“行动预览”手动开关，由 Agent 在普通聊天任务中按用户意图决定是否生成未确认行动预览。

## 约束

- 普通问答不生成预览；明确的计划、安排或行动意图可调用 `emit_chat_preview`。
- 意图不明确时先追问，不用关键词规则替代模型判断。
- 自动预览仍必须通过共享 Schema，固定 `unconfirmed`、`applied=false`，不得写入正式业务表。
- 保留后端显式 `structured_preview` 模式作为确定性契约和测试入口，但正式前端不再暴露模式开关。

## 实施步骤

1. 在 `agent-system-prompt.spec.ts`、`chat-task.store.spec.ts` 和前端输入测试中先加入失败用例，分别约束自动意图提示、普通聊天允许零个或合法 action 预览、输入框不再出现手动开关。
2. 修改 `agent-system-prompt.ts` 与 `pi-agent.service.ts`：普通 ChatTask 也提供无副作用预览工具；只有显式结构化模式才强制生成和纠正，普通模式由模型判断。
3. 修改 `chat-task.store.ts`：普通聊天接受零个或通过共享契约校验的 action 预览，继续拒绝非法、已应用或其他类型载荷。
4. 修改 `chat-input.tsx`、`use-chat.ts` 与 `chat-message-submission.ts`：删除输出模式状态、按钮和 UI 提交链中的模式参数，所有正式前端消息固定按普通自动模式提交；低层 API 仅保留确定性契约测试入口。
5. 更新真实 PostgreSQL 恢复用例，以普通 chat 的合法预览验证重启恢复和正式表零变化，并继续用非法已应用预览验证事务拒绝。
6. 运行 contracts、backend、frontend 的针对性测试，再运行根 build、lint、unit 与 memory e2e；复核文档口径不再描述为用户手动选择。
