# 阶段成果收口实施计划

> **执行说明：** 按现有授权完成 T01–T09 收口，不新增业务能力；每项先补回归，再做最小修改并复验。

**目标：** 消除阶段复核发现的契约、持久化、恢复、修订号、证据与文档阻塞，使聊天与未确认 action 预览具备可提交、可恢复、可追溯且不写正式业务表的可复核交付。

**架构：** `@partner-agent/contracts` 继续作为 REST、WS、预览模式和状态的唯一公开契约。预览仍保存在助手消息附件中，由 ChatTask fenced 事务原子提交；不新增正式 Action、Candidate、AnalysisRun 或预览业务表。ChatTask 新增持久递增 revision，恢复出口重新执行共享契约校验。

**技术栈：** TypeScript、NestJS、TypeORM、PostgreSQL 16、Expo 57、Vitest/Jest。

## 全局约束

- 正式业务数据只能经既有 `SubmitConfirmationBatch` 事务写入；本计划不得调用或扩展正式业务写入。
- 保留 `/api/v1`、`/ws/v1`、PostgreSQL、TypeORM、Pi Agent 和 Expo 57 技术栈。
- 不修改 `pi/`，不读取或输出密钥，不覆盖无关工作区改动。
- 旧 REST/WS 兼容只允许保留已登记边界，并明确退役条件；不得新增无版本兼容旁路。
- 所有新迁移只增量追加，不改写历史迁移，不清空现有数据。
