# Agent 结构化输出实施计划

> **执行说明：** 本计划在当前任务内直接实施；保持输出工具无业务 Repository、正式业务零写入。

**目标：** 让持久 ChatTask 通过运行级 `emit_chat_preview` 工具生成、校验并原子保存真实 action 预览，非法或缺失输出明确失败。

**架构：** 每个结构化预览任务创建独立收集器和工具实例，模型只能提交 `ChatPreviewProposalV1` 内容。收集器校验 Schema、来源、时间、数量和大小，并以 task + 序号生成稳定 preview ID；Runner 先持久化正文增量，最终调用 `completeAssistantOutput` 同时提交正文、预览、上下文和任务终态。普通聊天不暴露该工具，也不从正文提取 JSON。

**技术栈：** NestJS、TypeScript、Pi Agent、TypeBox、Vitest、TypeORM/PostgreSQL。

## 全局约束

- 只开放 `action` 预览，固定 `confirmation_status: unconfirmed`、`applied: false`。
- 输出工具不注册为正式业务或外部副作用工具，不持有任何 Repository。
- 只允许当前任务的 `original_record` 与用户 `chat_message` 来源。
- 首次非法输出后最多允许一次纠正；所有模型轮次仍经过现有 ModelGateway 和预算钩子。
- 完成提交成功后才发布完成状态；取消、失租、冲突时不保存成功附件。
