# 聊天时间线与复杂任务待办计划

**目标：** 所有消息型内容严格按服务端时间线展示；复杂任务由模型维护临时待办，聊天页提供轻量入口和浮层进度，全部完成后自动清空并隐藏。

**架构：** 预览、候选、审批和工具状态统一留在 `ChatMessageList`，不再抽取到底部输入区。新增内部 `update_task_todo` 工具与 `todo_update` WS 事件：模型只在复杂任务中提交完整待办快照，前端以当前任务为作用域保存；收到全完成快照或任务进入终态时立即清空。待办不写正式 Action 表，也不混入聊天正文。

## 约束

- 消息展示顺序只由 `sequence`、时间和稳定 ID 决定，不按消息类型重新分区。
- 简单问答不得生成待办；复杂任务应先拆分 2 至 8 个可验证步骤。
- 待办状态仅允许 `pending`、`in_progress`、`completed`，每次工具调用提交完整快照。
- 待办全部完成、任务失败、取消或完成时，前端清空待办并隐藏入口。
- 待办入口位于聊天页标题栏右侧、新建会话按钮左侧；浮层支持点击遮罩或关闭图标退出。

## 实施任务

### 1. 恢复统一消息时间线

- 删除底部待处理事项分区及其组件。
- `ChatScreen` 直接把完整 `items` 交给消息列表。
- 正式候选恢复为时间线内卡片，结构化预览、审批和工具状态继续由 `ChatItemBubble` 原位渲染。
- 增加回归测试，验证候选与预览不会被移动到输入区。

### 2. 建立模型待办协议

- 在共享契约增加 `TaskTodoItemV1`、`TodoUpdateEventV1` 和严格解析校验。
- 新增 `update_task_todo` 内部工具，校验数量、唯一 ID、文本长度和状态。
- Agent 系统提示词约束复杂任务先创建、执行中更新、结束前全量完成；普通回答不调用。
- Agent 事件映射隐藏内部工具卡，仅发布脱敏待办快照。

### 3. 接入实时状态和浮层

- Chat store 保存当前任务待办，忽略其他会话或任务的事件。
- `todo_update` 更新待办；全完成快照与任何任务终态都清空。
- 新增标题栏待办入口与浮层组件，展示完成数、当前步骤和逐项状态。
- 增加 store、事件路由、组件和聊天页装配测试。

### 4. 验证与文档

- 运行根 build、lint、test。
- 启动 Expo Web，检查页面身份、错误覆盖层、控制台及标题栏交互；无可用登录态时明确记录登录后聊天态未做真数据点击。
