# 聊天直接执行行动计划

**目标：** 取消权限型确认 UI；清晰的单一行动意图直接通过现有审计事务生效，仅在意图不确定或存在多个候选时显示聊天内选择预览。

**架构：** `emit_chat_preview` 继续作为模型输出行动结构的受控入口。服务端按确定性规则分流：单候选、置信度不低于 0.85 且没有不确定性说明时，在聊天完成事务内创建候选并立即调用统一确认事务；其余情况只保存结构化预览供聊天澄清，不创建确认批次。前端不再展示正式候选确认卡，确认中心保留兼容历史数据但不作为新聊天流程入口。

## 约束

- 正式 Action 仍只能经过统一确认事务写入，保留幂等、审计、版本与撤销数据。
- 用户已授予应用范围内的最高完整权限，不再触发风险或权限二次确认。
- 选择卡只表达意图澄清，不代表正式业务对象已生效。
- 不修改与本流程无关的工具审批、隐私出站或历史数据。

## 实施任务

### 1. 冻结自动执行判定

- 在行动候选生产模块增加纯函数：仅一个预览、`confidence >= 0.85`、`uncertainty` 为空时返回自动执行；多候选或不确定预览返回聊天澄清。
- 先添加边界测试，再实现判定。

### 2. 复用统一确认事务

- 从 `ConfirmationTransactionService` 提取可在已有 QueryRunner 事务中调用的执行入口。
- 现有 HTTP `SubmitConfirmationBatch` 继续调用同一入口，不改变协议。
- 聊天完成事务对自动执行分支创建单候选批次后立即提交，并且不保存预览附件、不发送候选待确认事件。
- 澄清分支只保存预览附件，不创建 `confirmation_batches` 或 `candidate_items`。

### 3. 收口聊天展示

- 前端聊天流不再把正式 `candidate` 放入底部“查看并确认”卡。
- `structured_preview` 仅承载不确定或多选内容；普通单候选执行完成只显示助手正文。
- 修复快照对结构化预览的权威替换，避免旧预览残留。

### 4. 提示词、文档与验证

- 更新系统提示词：明确单一清晰行动会直接执行，模型只能在不确定或多选时要求澄清；完成声明必须依赖工具/事务结果。
- 更新项目进度文档中与“所有行动必须人工确认”冲突的当前状态说明。
- 执行后端候选/确认/聊天任务测试、前端聊天状态与渲染测试、两端构建和 lint，并在 Android 模拟器验证清晰单行动与澄清卡两条路径。
