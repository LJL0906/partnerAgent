# 后端 API 契约对齐实施计划

**目标：** 让 Local Core 的聊天请求、命令响应和恢复快照遵循共享契约，并让会话设置类命令复用现有 operation 账本。

**方案：** 模型列表与解析统一由 `ModelSelectionService` 从 Model Gateway 能力生成；应用服务在写入前解析共享请求，在返回前校验引用一致性。会话重命名、归档和模型切换通过 `ChatTaskStore` 已有 `local_core_operations` 账本执行；快照 adapter 只接受安全消息、工具视图、任务和结构化预览，不接收任意 metadata。

## 实施任务

1. 为默认模型回退、真实推理等级和未知模型补单元测试，随后统一 list/resolve 能力来源。
2. 为聊天/结构化预览请求模式、规范受理结果、引用不一致和分析 501 补应用服务测试，随后接入共享 parser。
3. 为 rename/archive/model-selection 的重复重试和旧重试不覆盖新结果补测试，随后扩展现有 operation 账本的通用命令入口。
4. 用共享 fixture 覆盖消息、运行态、工具安全视图和 structured preview，重写 `buildChatItemsSnapshot` 并移除 metadata 透传。
5. 删除仅由镜像测试引用的 `mapServerPushEventToChatItems`、`mergeChatItems`、`previewCandidate`，以全仓 `rg` 输出作为引用证据。
6. 运行 contracts build/test、后端目标单测、后端 build/lint 和不含真实 PostgreSQL 的 e2e；复核任务范围 Markdown 与最终 diff。
