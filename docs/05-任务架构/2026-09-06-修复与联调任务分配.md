## 1. 阶段交付目标

先修问题、对齐数据，再验通现有技术链：

```text
登录与 owner 隔离
→ REST 提交文字/选择模型
→ PostgreSQL 受理任务与原始输入
→ Pi Agent + 现有 Model Gateway
→ 普通正文，或经 Schema 校验的 action 结构化预览
→ 聊天消息/运行态持久化
→ WS 正文与完成通知 + REST 安全快照
→ 前端展示与刷新/重启恢复
```

结构化结果随聊天保存，固定 `confirmation_status:'unconfirmed'`、`applied:false`。本期预览链不创建正式确认批次、不调用 SubmitConfirmationBatch、不写正式事实/目标/行动/长期记忆及其派生表。

当前基线不是全绿：731 单测通过，build 失败，memory e2e 130 通过/2 失败。这些是历史基准数字；每个执行者需要提供自己提交上的实际结果。
