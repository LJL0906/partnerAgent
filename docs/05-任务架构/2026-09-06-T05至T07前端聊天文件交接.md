## 当前稳定接口与不变量

1. `useChatStore().items` 是唯一可写的聊天展示集合；`messages` 只是从 `items` 即时生成的只读兼容投影，禁止恢复双写。
2. `mergeSnapshot(items, toolViews)` 按稳定 item ID 与递增 revision 合并。服务端 revision 必须为正整数；本地乐观输入使用 `revision = 0` 哨兵，并按同一 `operation_id` 被权威用户 item 替换。
3. `applyChatSessionSnapshot(snapshot, expectedSessionId)` 是 REST 快照入口：优先解析当前 `items/tool_views` 契约；仅保留严格校验的旧 `messages` envelope 迁移入口。
4. `reconcileChatFromRest(taskId, sessionId)` 返回 `[taskResult, sessionResult]` 两个 `PromiseSettledResult`。调用方必须检查对应结果，不能假定函数会因单项失败而抛错。
5. REST 快照可从 `active_task` 接管进行中任务；transport unknown 保持 `recovering` 和发送锁，直到权威任务收敛或确认可用原 operation/input 重试。
6. `findSessionToolViewForItem(toolViews, item)` 按 `tool_call_id` 取得服务端工具权威投影。审批按钮、风险、过期和可撤销资格只取 `SessionToolView`；缺失时显示“状态待同步”并触发 REST 恢复，不猜测 pending。
7. WS delta 只在稳定 item ID、递增 revision 和 UTF-16 `text_offset` 连续时追加；重复忽略，缺口或旧协议事件走 REST 恢复。channel cursor 不能当 item revision。
8. 会话切换、账户切换和异步回调均受 session revision、session ID、owner/request generation 隔离。T07 的预览回读也必须复用这些边界。
