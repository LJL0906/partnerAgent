# 数据库、消息身份与任务恢复交付

日期：2026-09-06  
范围：T03 数据库、消息身份、恢复一致性与后台轮询

## 对外接口

### 正文进度

`ChatTaskStore.appendAssistantProgress(command)` 接收：

- 权威范围：`ownerId`、`sessionId`、`taskId`、`operationId`。
- fencing：当前认领得到的 `leaseToken`，且租约必须尚未过期。
- CAS：`expectedRevision` 与追加前的 `textOffset`。
- 内容：非空 `delta`；`textOffset` 使用 JavaScript UTF-16 code unit 长度。

成功返回 `outcome: 'committed'`、完整 `SessionMessageDto` 和本次追加前偏移；修订冲突返回 `conflict`，取消、任务终态、租约不匹配或过期返回 `fence_rejected`。同一 task 的助手消息通过 `(owner_id, task_id)` 保持唯一，首次进度即获得稳定 message ID，后续正文和预览复用该 ID。

调用方必须在进度提交成功后才发布 `text_delta`，并使用返回消息构造相同的 `message_id`、item identity、`item_revision` 和 `text_offset`。Agent/T06 不得另写消息 Repository。

### 最终完成

`ChatTaskStore.completeAssistantOutput(command)` 接收同一组权威范围、当前 `leaseToken`、`expectedRevision`，以及最终 `content`、类型化 `chatPreviews` 和上下文 `contextMessages`。

PostgreSQL 实现在一个数据库事务中完成：

1. 锁定并复核 task、operation、session、owner、运行态和未过期租约；
2. 新建或更新同一条 task assistant message；
3. 保存正文、预览附件、上下文快照和消息修订；
4. 更新任务终态与 `result_message_id`，清除租约；
5. 写入唯一生命周期 outbox 通知。

空正文并不代表空结果：只要 `chatPreviews` 有内容仍会保存助手消息。重复完成返回 `already_completed` 和原消息，不新增消息、预览 ID 或完成通知。取消或失租后的旧执行返回 `fence_rejected`。

### 恢复读取

- `listSessionMessages(ownerId, sessionId)`：memory/PostgreSQL 都返回共享 `SessionMessageDto`，包含数据库 `sequence`、`status`、`revision` 及真实 task/operation/model/reasoning 关系，不返回聊天 metadata。
- `listSessionChatPreviews(ownerId, sessionId)`：从稳定助手消息的持久化附件恢复预览及其 message/task/operation 关联。
- `ToolOperationStore.listSessionToolViews(ownerId, sessionId)`：只从工具确认与执行回执表投影共享 `SessionToolView`；审批、撤销权限按权威状态和期限实时计算，不读取聊天 metadata，也不泄露参数、完整结果或 undo payload。

## 增量迁移

新增 `1788519000000-align-chat-message-runtime.ts`，未覆盖或改写任何历史迁移：

- `session_messages.revision integer not null default 1`，附正整数约束；
- `(owner_id, task_id)` 上仅针对 task assistant message 的部分唯一索引。

迁移不会删除表、清空聊天或重写历史消息。若存量库已存在违反稳定身份约束的重复 task assistant message，索引创建会显式失败并要求人工核对，不会静默删除历史记录。

## 一致性与故障证据

- memory 单测：稳定 ID、UTF-16 偏移、revision CAS、空正文预览、重复完成、取消 fencing、owner 隔离。
- pg-mem 事务测试：最终消息、附件、任务终态和 lifecycle outbox 同提交；非法附件回滚；取消后拒绝旧提交。
- 真实 PostgreSQL：迁移后的进度提交、空正文预览、连接重建后的正文/附件恢复、唯一助手消息与唯一完成 outbox 均通过。
- 工具恢复：安全白名单投影、owner 隔离、状态/期限权限重算、公开 version 随状态变化递增。
- outbox：claim 失败和 fail-recording 失败都被单轮捕获，下一轮可继续处理，不产生进程级未处理拒绝。
- WS：订阅授权期间的 unsubscribe/disconnect 通过 socket/channel generation fencing，旧授权完成后不能重新激活订阅。
