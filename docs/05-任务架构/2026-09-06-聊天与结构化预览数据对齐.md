## 5. 执行者应实现的最小契约

以下名称为统一目标。T01 将它们落实到共享类型、schema、解析器及 fixture 后，其他组只消费契约，不各自起名。

### 5.1 输入、模型与身份

- `SubmitTextInputPayload.output_mode?: 'chat' | 'structured_preview'`，缺省 chat。
- 正式前端只提交缺省 chat，不提供输出模式手动开关。Agent 在普通 chat 中根据明确行动意图决定是否调用无副作用预览工具；普通问答不调用，意图不明确时先追问，不使用关键词规则。
- `structured_preview` 必须携带 `preview_kind:'action'`；普通 chat 不携带 preview_kind。显式模式仅作为确定性 API/测试入口，继续强制生成至少一个合法 action 预览。
- 普通 chat 可完成为零个预览，或一个及以上通过共享 Schema 的 action 预览；所有预览均必须保持 `unconfirmed`、`applied=false`，不得触发正式业务写入。
- `request_analysis:true` 与 structured_preview 组合返回 422；单独的既有分析请求保持稳定 501。不能为了演示删掉 501 并伪造 AnalysisRun。
- 该模式、类型、model/reasoning 都纳入请求幂等内容及受理任务记录；恢复读取受理快照，不读后来修改的全局设置。
- 增加 `ResolvedModelSelection`：`model_config_id:string; reasoning_level:ReasoningLevel`。受理结果的 `resolved_model` 必填并与任务保存值一致。
- 模型列表除既有公开字段，增加必填 `default_reasoning_level`；`reasoning_levels` 是真实可提交集合。前端禁止自行追加 off 或假造 medium。
- 认证使用现有 `AccountPublicUser`；本地 owner 等于已认证 user.id，不采用 username 作为隔离键。

### 5.2 消息、卡片与状态

- 新共享 `SessionMessageDto`：必填 `id/session_id/sequence/role/content/status/created_at`；真实存在时返回 `task_id/operation_id/model_config_id/reasoning_level`。status 统一为现有 pending/streaming/complete/failed/cancelled；reasoning 直接引用共享枚举。
- REST `created_at` 保持 ISO 字符串，ChatItem 的时间保持 Unix 毫秒；转换只做一次。消息 sequence、context_revision、WS channel sequence 不相互转换。
- ChatItem `revision` 是服务端分配的正整数修订；同一 item 的真实变化递增，重发不递增。
- ID 规则：任务助手 item 为 `task:${task_id}:assistant`；runtime 为 `task:${task_id}:runtime`；工具为 `tool:${tool_call_id}`；审批为 `approval:${confirmation_id}`；预览为 `preview:${preview_id}`；普通历史消息为 `message:${message_id}`。真实资源 message_id 单独保存，不使用 item ID 冒充数据库 UUID。
- text_delta 保留 data 字符串，增加展示关联元信息 `item_id/item_revision/message_id/text_offset`；text_offset 是追加前正文的 JavaScript UTF-16 code unit 长度，两端一致。其他修改展示 item 的事件携带对应 item_id/item_revision；纯控制/通知事件不假造这些字段。
- 共享 `TaskState → ChatItemStatus` 穷尽映射；runtime payload 的 state 引用 TaskState，不能 string 任意值。工具权威状态另有映射，不等同 TaskState。

### 5.3 快照与实时事件的一致性

采用**持久可恢复内容＋逐项修订合并**，避免新建独立通用事件溯源平台。

1. 当前任务首次产生可展示输出时，确保稳定助手 message_id；同任务后续正文写同一消息。纯附件也允许生成该消息。
2. 正文进度与修订必须先写入运行数据，再推送对应可见 delta；可批量合并 delta，但不能先发而没有可恢复内容。最终正文、预览、任务完成和可靠通知由同一 fenced 提交协调。
3. 真实工具审批/执行卡从工具权威记录按版本投影；不能靠旧 metadata pending 值恢复审批资格。
4. REST 返回完整可恢复 items。revision 来自持久记录/权威工具版本，不在读取时使用 Date.now 或随机生成。
5. 前端开始恢复时缓冲相关事件；按 item ID/revision 合并快照，再应用较新事件。快照中不存在的新本地/实时 item 不因旧快照晚到被删除。本期会话内容不提供任意硬删除 item 的新能力。
6. 收到旧/相同 item_revision 直接去重；较新 delta 仅当 text_offset 等于当前正文长度时追加；缺口触发 REST 对账，不猜正文、不跨频道直接比较 sequence。
7. task_state 的终态与本地网络结果未知分离；只有权威终态进入吸收态。提交断线使用原 operation/input ID 查询/幂等重试。
8. 旧重放事件缺新增关联字段时，受控回退为 REST 恢复；不能生成“看似真实”的 revision。同步升级本仓客户端和服务端，不为无限期旧客户端增加兼容层。

T03 必须用真实 PostgreSQL 证明“持久变更与对应修订/通知的提交顺序”，不能仅在 DTO 增加 revision 字段就标记本项完成。新增迁移限于聊天/运行字段，禁止清空现有迁移历史。

### 5.4 结构化预览

首版采用 `ChatItem.type='structured_preview'`，payload 为以下 `ChatPreviewV1`。它与既有 candidate/approval 类型并存，不能复用 candidate_id 或 confirmation_batch_id。

```ts
interface ChatPreviewV1 {
  schema_version: 1;
  preview_id: string;
  kind: 'action';
  confirmation_status: 'unconfirmed';
  applied: false;
  source_refs: Array<{ kind: 'original_record' | 'chat_message'; id: string }>;
  content: {
    title: string;
    description?: string;
    planned_at?: string;
    deadline_at?: string;
    timezone?: string;
    priority?: 'low' | 'medium' | 'high';
    confidence: number;
    uncertainty?: string;
    risk_summary?: string;
  };
  warnings: Array<{ code: string; path?: string; message: string }>;
}
```

约束：title 1–200 字符，description/uncertainty/risk_summary 各最多 2000 字符，confidence 为 0–1；单任务最多 20 个预览、公开附件整体最多 64 KiB；拒绝额外字段。时间若出现必须是有效带偏移的 RFC3339，时区使用有效 IANA 名称；没有依据时省略时间并说明不确定性，不替用户捏造截止日。以上限制由共享 schema 和后端共同验证，前端只提供提前反馈。

模型只提供内容和可选来源引用建议；preview_id、owner/session/task/message 关系、confirmation_status、applied 由服务端生成。来源必须存在且属于当前 owner；首版只允许当前受理输入对应的 original_record/chat_message，避免假 RAG 来源。

生产方式：`emit_chat_preview` 专用无外部副作用输出工具 → schema/来源/长度/时间校验 → 当前运行内收集 → fenced 完成提交时写助手消息附件。不直接从普通正文中抓 JSON 当结果，不赋予工具业务 Repository，不调用 createCandidateBatch。工具必须为运行级实例/闭包，禁止单例跨用户共享预览数组。

现有 TypeBox/验证方式可以复用，不增加结构化输出框架。校验失败最多允许一次受预算约束的纠正；没有有效工具输出时返回明确的 `STRUCTURED_PREVIEW_INVALID` 或 `STRUCTURED_PREVIEW_MISSING`，不生成成功空卡片。失败详情只含安全字段路径/错误码，不保存或打印 offending value。

**首版不增加新业务 WS 事件。** 正文仍流式，结构化预览在完成提交后由 done 或 task_state completed 触发 GetChatSession 读取。事件必须在提交之后可见；刷新/重启同样读取这个结果。这样不用伪造 candidate/analysis/batch 引用，也不需要新的预览详情服务。

卡片显示“未确认预览，未创建行动”，支持展开与复制安全可见内容。现有接受/修改/拒绝/稍后处理若保留，必须明确为本地预览意图且产生真实可见反馈；本期不新增决定 API、不把本地意图改成 applied:true，不承诺本地编辑跨设备/重启保存。用户授权保存的是已生成预览，不自动扩展为完整确认工作流。

## 7. 完成的定义

对齐文档完成 ≠ contracts 已修改 ≠ 联调已通过。当前实际状态仍以审计报告为准。

本阶段代码验收需证明：真实账户登录 → 发送 → 模型和推理选择一致 → Agent 返回正文/合法 action 预览 → 聊天持久化 → 前端展示 → 刷新与单实例重启恢复；期间正式业务/确认表不变，跨 owner 不泄露，重复提交不重复结果，取消/失租的旧执行不能提交。

真实 Provider 开发冒烟和真实 PostgreSQL 是用户本次“跑通”的交付项；不宣称生产验收。Android/iOS 全面真机、正式业务确认、RAG、多实例压测仍不扩入本阶段。若环境或凭据缺失，执行者必须明确报告阻塞和已完成部分，不能用 mock 替代真实联调。

## 8. 收口结果（2026-09-06）

- D01–D20 的本期实现与共享契约已落地；公开模式、预览 Schema、任务状态和数据库枚举不再由各层手写镜像。
- 结构化预览由真实 Provider 经无副作用输出工具生成，保存到助手消息附件；恢复时重新执行共享 parser，损坏附件不会伪装成成功卡。
- ChatTask 使用第 23 条迁移提供的持久正整数 revision；生命周期可见变化递增，纯 lease heartbeat 不递增。
- lease heartbeat 只续租，不改变 `updated_at` 或公开 revision；REST/WS 投影不会因不可见心跳产生伪更新。
- 预览写入继续严格拒绝非法集合；历史恢复按持久顺序逐项隔离损坏、重复、超数量或累计超 64 KiB 的附件，并复制通过校验的值，避免调用方修改污染同集合的其他结果。
- 独立 PostgreSQL 16 验证 23 条迁移 up → down → up、前 22 条到第 23 条增量升级，以及 11 个真实库文件 38 项用例。恢复用例逐表比较 11 张正式业务、确认和派生表的行数与稳定摘要；新增 A10 真实库用例证明会话修改与幂等账本同事务回滚、重试只写一次。
- 开发测试账户的真实 DeepSeek 预览为 `completed / unconfirmed / applied=false`；后端实际重启后经 REST 回读，共享 ChatItem 校验通过，相关 ID、revision 与脱敏 payload hash 可关联。
- 本结论不包含 A06/A09、Android 真机或 14 个 moderate 传递依赖；旧 Agent WS 已按后续明确指令整体退役。
