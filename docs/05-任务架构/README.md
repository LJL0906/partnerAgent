# 任务架构文档

> 本目录集中收纳为一次性开发任务服务的技术架构与交付说明。

## 定位

任务架构文档负责把已确认的业务和架构基线转换为队员可执行的任务包，包含目标、非目标、技术方案、依赖顺序、文件边界和验收标准。

本目录不是产品需求或长期架构的权威源，不复制大段需求。如果任务产生长期有效的新决策，必须同步回写对应权威文档：

- 业务不变量与 P0 决策：`docs/01-项目/P0决策收口文档.md`；
- 当前状态与下一步：`docs/01-项目/开发交接说明.md`；
- 产品规则：`docs/02-需求/`；
- 长期技术方案：`docs/03-技术草案/`。

## 命名与状态

- 文件名使用 `YYYY-MM-DD-任务名.md`。
- 页眉必须标明 `待开始 / 进行中 / 待验收 / 已完成 / 已取消`。
- 完成时在原文档记录实际验证、偏差和对应提交，不再新建重复总结。
- 完成后的文档只作实施记录，当前进度仍以开发交接说明为准。
