# Agent 安全与可靠性修复

## 问题复现

1. 敏感信息扫描只匹配普通文本表达式，JSON 字符串中的引号边界以及 Unicode 转义键（如 `{"pass\u0077ord":"hunter2"}`）可绕过检测。
2. Agent 首次外发进入隐私审批时，Pi Agent 会把 Gateway 的审批异常转换成普通 assistant error，调度层因此无法进入 `waiting_privacy_decision`；消息重建产生的新时间戳也会改变许可指纹。
3. 单次运行写满 256 条追踪后，结束事件被直接丢弃，清理定时器不会注册，运行索引持续驻留。
4. Provider 内部重试不会逐次经过外发检查；重试退避取消、Provider 静默结束或迭代器抛错时，外层流也可能得到错误状态或无法结束。

以上问题均先以失败回归用例锁定，再实施修复。

## 最小修复

- 敏感信息扫描器对确认是 JSON 对象或数组的字符串执行受现有限额约束的递归扫描；脱敏器按同一路径结构化脱敏并重新序列化，覆盖密码、密钥、令牌和 Unicode 转义键。
- 审批指纹排除 Pi 重建消息时生成的 `timestamp`，但继续包含正文、模型、来源及任务上下文。相同语义请求可消费一次许可；正文或模型改变会生成新审批。
- Gateway 审批错误通过预算流回传给 `PiAgentService`，可靠 Agent 入口能够产出 `privacy_decision_required` 并以 `waiting_privacy_decision` 结束本次运行。
- Provider 重试次数固定为 0，重试统一由 `ModelGatewayService` 管理。每次尝试重新构建真实外发载荷、执行敏感信息检查并写审计；首个流事件出现后不再重放。
- 禁止可能在审批后改写载荷的 `fetch` 和 `onPayload` Provider hook。审批等待期间使用已经扫描的请求快照，避免正文被异步改写后外发。
- 追踪最多保留 256 条，第 256 条专门保留结束摘要；结束事件无论是否达到上限都会安排 5 分钟后的运行索引清理。
- 为取消、静默结束和迭代器异常补充终止事件，避免包装流悬挂。

## 后续结构化输出入口

后续结构化输出应继续从 `PiAgentService` 进入，并通过 `startAgentRunTrace` 与 `createBudgetedAgentStream` 创建运行。模型调用、格式纠正重试和模型切换都必须调用 `ModelGatewayService.createStreamFunction`；不得直接导入 Provider 或调用 `streamSimple`。这样每一次外发都同时受运行预算、Model Gateway、敏感信息检查和审计约束。

## 废弃别名与无调用代码证据

- `ConfirmationCenterService` 在删除前全仓仅有自身导出定义，没有 import、依赖注入、测试或命令行调用，因此移除该废弃别名，保留实际使用的 `ExternalToolApprovalService`。
- `EgressPolicyGateway` 的生产引用仅为模块 provider 和 `ModelGatewayService` 内部依赖，没有模块外消费者，因此从 `ModelGatewayModule.exports` 移除，但保留 provider 与实现。
- Provider 包导入和生产代码中的 `streamSimple` 调用均只存在于 `model-gateway.service.ts`，证明当前生产模型调用只有一条 Gateway 出口。其余看似未直接引用的追踪查询、保留策略、旧 WebSocket 路由和命令行入口仍有运行时或框架用途，未删除。
