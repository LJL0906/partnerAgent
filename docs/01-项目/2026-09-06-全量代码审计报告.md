### A01：构建失败，当前代码无法通过既有发布检查

位置：[chat-task.store.ts:75](E:/project/partnerAgent/apps/partner-agent-backend/src/local-core-api/chat-task.store.ts:75)、[typeorm-chat-task.store.ts:403](E:/project/partnerAgent/apps/partner-agent-backend/src/local-core-api/typeorm-chat-task.store.ts:403)、[memory-chat-task-helpers.ts:110](E:/project/partnerAgent/apps/partner-agent-backend/src/local-core-api/memory-chat-task-helpers.ts:110)、[chat-item-adapter.ts:122](E:/project/partnerAgent/apps/partner-agent-backend/src/local-core-api/chat-item-adapter.ts:122)、[message-content.tsx:76](E:/project/partnerAgent/apps/partner-agent-frontend/src/features/chat/components/messages/message-content.tsx:76)。

`SessionMessageView` 要求 `sequence`，但两种存储映射未返回该字段，连带 `database.module.ts:69` 注入工厂类型不兼容；`messageStatus()` 的声明允许 undefined，却返回给不接受 undefined 的 `ChatItemStatus`。前端表格使用当前 React Native 类型不支持的 `accessibilityRole="table"/"row"/"cell"`。

**影响与证据：** 本轮完整 build 失败，后端 4 条、前端 3 条诊断。现有 CI 在测试之前运行 build，因此这也是 CI 阻断，不能将本次单测通过理解为可部署。

### A02：JSON 形式的聊天密码可以漏过禁止外发策略

位置：[sensitive-data-scanner.ts:221](E:/project/partnerAgent/apps/partner-agent-backend/src/model-gateway/sensitive-data-scanner.ts:221)、[egress-policy.gateway.ts:371](E:/project/partnerAgent/apps/partner-agent-backend/src/model-gateway/egress-policy.gateway.ts:371)。

聊天内容是字符串。发送合成样例 `{"password":"Abc123xyz"}` 时，字段扫描看不到字符串内部的 JSON 字段；文本正则又不接受 `password` 后面的结束引号。

**最小复现：** 对真实 `SensitiveDataScanner.scan({messages:[{role:'user',content:'{"password":"Abc123xyz"}'}]})` 调用，返回 `ok:true, findings:[], categories:[]`。网关对空敏感类别放行，所以 ask/block 或禁止 password 类别也无法拦截这种文本。复现没有向真实模型发送内容。

**影响：** 用户粘贴 JSON 配置、接口示例等常见输入时，敏感值可能以明文外发。同类 api_key/secret 文本规则也应一起检查。

**修复与验收：** 扫描和脱敏同时覆盖带引号键值、代码块等表达；完成脱敏后复扫。增加“真实聊天字符串包含 JSON”的网关用例，验证 block/ask/redact，不能用结构化对象测试替代。

### A03：外发审批恢复改变指纹，批准后可能再次等待批准

位置：[egress-policy.gateway.ts:320](E:/project/partnerAgent/apps/partner-agent-backend/src/model-gateway/egress-policy.gateway.ts:320)、[pi-agent.service.ts:119](E:/project/partnerAgent/apps/partner-agent-backend/src/agent/pi-agent.service.ts:119)。

普通隐私等待恢复会再次 `agent.prompt(message)`。当前 pi-agent-core 给新用户消息生成 `Date.now()` 时间戳，默认转换保留该字段；网关将整个 `context.messages` 纳入审批指纹。相同正文恢复后时间戳不同，原 ready_allow/ready_redact 因指纹失配作废。

**最小复现：** 真实 Gateway＋MemoryEgressDecisionStore，首次 timestamp=1000，批准 allow，再以同正文 timestamp=2000 调用，输出：`first=pending_user_decision; second=pending_user_decision; sameFingerprint=false; prior=invalidated`。

**修复与验收：** 指纹排除不改变外发语义的运行元数据，或持久恢复同一已受理消息；必须保留正文、工具结果、模型等实质绑定。新增真实 PiAgent＋Gateway 的“提交→批准→恢复→只外发一次”集成测试，包括重启恢复。

### A04：Web 跨标签页切换账户后，刷新保留旧账户聊天

位置：[auth-store.ts:91](E:/project/partnerAgent/apps/partner-agent-frontend/src/features/auth/auth-store.ts:91)，刷新应用令牌在同文件 120 行。

标签页一登录 A 并展示聊天，标签页二登录 B 后共享 Cookie 变为 B。标签页一刷新取得 B token 时，`applyAccount()` 只检查 generation，不比较 owner、不触发账户 teardown；旧聊天和会话 scope 留在内存。

**最小复现：** 内存转译真实 auth-store/chat-store，模拟 Cookie 刷新返回 B，结果为 `authUser=B, session=A-private-session, messages=[A confidential message], teardowns=0`。

**影响：** 界面身份为 B，却展示 A 聊天；后续请求与本地状态、WS 身份可能不一致。这是客户端账户隔离缺口，未发现因此突破后端所有权校验。

**修复与验收：** 认证状态保存权威 owner；接受不同 owner 的令牌前终止旧请求/流、清空账户运行态、重建 scope。验收真实 Web 双标签页换号与令牌刷新。

### A05：迟到的 REST 快照覆盖实时消息，正文前缀丢失

位置：[use-chat.ts:91](E:/project/partnerAgent/apps/partner-agent-frontend/src/features/chat/use-chat.ts:91)、[chat-session-snapshot.ts:28](E:/project/partnerAgent/apps/partner-agent-frontend/src/features/chat/chat-session-snapshot.ts:28)、[chat-store.ts:253](E:/project/partnerAgent/apps/partner-agent-frontend/src/store/chat-store.ts:253)。

恢复请求只检查是否还是同一个会话，没有比较该会话的新事件进度。较早读取的快照晚到时，`replaceItems` 整体替换并重置助手消息引用。

**最小复现：** `beginTask → text_delta("已收到完整前缀") → applyChatSessionSnapshot({id:"s",items:[]}) → text_delta("后缀")`。真实 store 输出从 `["已收到完整前缀"]` 变为 `["后缀"]`。

**影响：** 订阅恢复、回前台等正常时序可丢正文或卡片；正常 done 也不保证再做一次最终修复。

**修复与验收：** REST 快照与 WS 事件建立可比较水位，恢复期间缓冲并重放快照之后的事件。测试必须控制“快照先读取、delta 先到达、HTTP 后返回”的顺序，以及多次恢复请求交错。

### A06：确认撤销返回成功，但业务状态、时间和敏感标记没有恢复

位置：[confirmation-transaction.persistence.ts:388](E:/project/partnerAgent/apps/partner-agent-backend/src/local-core-api/confirmation-transaction.persistence.ts:388)。

`SubmitConfirmationBatch → applyUndo → restoreObject → restoreDomain` 已取得 before 快照，但 goal/action 只更新 title，其他正式对象只恢复 content。

**复核证据：** 调用实际 `restoreObject`，输入包含 description、execution_status、deadline 的 action 快照，捕获领域 SQL 只有 `update actions set title=$3 where user_id=$1 and id=$2`。

**影响：** 已确认修改的状态、描述、截止日期没有撤回，接口仍成功且版本递增；fact/memory 的 is_sensitive、confidence、domain_status 也不恢复。触发前提是存在合法确认候选和可撤销操作，不表示尚未接通的业务生成器已经上线。

**修复与验收：** 按领域白名单恢复完整快照；真实 PostgreSQL 验证 update→undo 每个业务字段和生命周期，补齐当前确认测试未覆盖的 undo 分支。

### A07：Outbox 轮询未处理拒绝，数据库瞬时错误可终止后端进程

位置：[chat-task-outbox.relay.ts:28](E:/project/partnerAgent/apps/partner-agent-backend/src/local-core-api/chat-task-outbox.relay.ts:28)、[tool-control-outbox.relay.ts:31](E:/project/partnerAgent/apps/partner-agent-backend/src/tools/tool-control-outbox.relay.ts:31)，生产启动入口 [ws-v1.service.ts:89](E:/project/partnerAgent/apps/partner-agent-backend/src/ws-v1/ws-v1.service.ts:89)。

两种 relay 的 start/interval 都丢弃 `runOnce()` Promise。claim 抛错时只有 finally，没有 catch；投递失败后 `outbox.fail()` 再失败也可向外拒绝。生产模块会启动它们，仓库没有兜底的 unhandledRejection 处理。

**最小复现：** Node 24.20.0 子进程调用真实 ChatTaskOutboxRelay.start，替身 claim 抛模拟数据库错误，进程退出码 1，后续 100ms 存活标记未执行。

**影响：** 暂时断库、连接池错误等会升级为整个后端退出，打断所有连接；Compose 自动重启不能替代正确的单轮失败处理。

**修复与验收：** 在后台任务边界捕获单轮异常、记录脱敏错误并允许后续轮询；失败回执本身失败也要覆盖。用 claim/fail 故障注入断言进程存活和下一轮恢复。

### A08：设置页 selector 每次创建新对象，违反稳定快照要求

位置：[profile.tsx:47](<E:/project/partnerAgent/apps/partner-agent-frontend/src/app/(tabs)/profile.tsx:47>)。

页面使用 `useAuthStore(state => ({status, username, expiresAt, errorMessage}))`。Zustand 5 的已安装实现直接将结果提供给 React `useSyncExternalStore`，这里没有 shallow 比较或结果缓存。

**证据边界：** 静态可确认快照引用不稳定；本地 React Compiler 同形代码编译只提升 selector 函数，仍返回新对象，不能自动消除此问题。本次没有在真实浏览器观察页面崩溃，因此“无限更新/maximum update depth”是由该调用链推导的运行风险，而非已录制的 UI 现象。

**修复与验收：** 改用独立字段 selector 或 `useShallow`。必须客户端挂载设置页并验证登录状态变化；纯 settings-model 或服务端静态渲染测试不足。

### A10：会话修改命令没有 operation 幂等去重

位置：[local-core-application.service.ts:180](E:/project/partnerAgent/apps/partner-agent-backend/src/local-core-api/local-core-application.service.ts:180)、[local-core-application.service.ts:205](E:/project/partnerAgent/apps/partner-agent-backend/src/local-core-api/local-core-application.service.ts:205)。
