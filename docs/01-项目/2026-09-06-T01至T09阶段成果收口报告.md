## 1. 收口结论

T01–T09 的本期目标已经形成可构建、可测试、可恢复的统一链路：前端通过共享契约提交 `structured_preview/action`，Agent 只能调用无副作用预览工具，后端在 fenced 事务中校验并保存助手消息附件，PostgreSQL 重启后由 REST 恢复同一 message/task/preview 关联。预览始终为 `unconfirmed`、`applied=false`，未调用 `SubmitConfirmationBatch`，11 张正式业务、确认和派生表在自动化与真实 Provider 抽样中均保持零变化。

## 3. 统一契约与实现边界

- `@partner-agent/contracts` 是 `ChatOutputMode`、`ChatPreviewKind`、预览 JSON Schema、任务状态、ChatItem ID 与跨端 DTO 的唯一公开来源。
- 前端不再手写服务端状态/输出模式；后端工具 schema 与运行时 parser 消费同一共享定义；数据库枚举由共享类型派生。
- 预览只保存在 `session_messages.metadata_json.chat_previews`。没有新增 Action、Candidate、AnalysisRun 或预览业务表，也没有新增旧版 REST/WS 兼容旁路。
- 权威完成边界只接受 `chat + 0 preview` 或 `structured_preview/action + >=1 valid preview`。非法组合返回固定安全错误并由 runner 失败收口；恢复时逐附件重验，损坏项不会伪装为成功卡。
- ChatTask 第 23 条迁移新增持久正整数 revision；创建为 1，可见生命周期变化递增，纯 lease heartbeat 不递增。REST runtime 与 WS lifecycle 使用同一 revision。
- 正式业务数据仍只能经现有 `SubmitConfirmationBatch` 事务写入。本期没有调用或扩展该入口。
