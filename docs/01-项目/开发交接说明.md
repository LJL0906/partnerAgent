## 1. 项目边界

紫灵AI 是个人长期信息管理与行动辅助产品。当前代码已经完成可持久化聊天和阶段 0 安全可靠性基础，但尚未形成 Action 候选、确认、正式写入、执行和撤销的产品闭环；也不代表事实、目标、提醒或长期记忆纵切已经实现。

必须遵守以下边界：

- `pi/` 仅允许作为本地参考仓库，不纳入本仓库，也不修改后提交；
- 产品代码只通过 npm 包使用 Pi；
- `.env`、API Key、本地数据和构建产物不得提交；
- Pi 内部事件必须转换为产品契约后才能发送给前端；
- RAG 和 Agent 只能提供依据或候选，不能绕过确认中心写入正式事实、目标、行动或长期记忆。

当前检出目录中没有实际 `pi/`，但根 `.gitignore` 已保留 `/pi/` 保护规则。

## 5. 共享契约

包名：`@partner-agent/contracts`

对外 v1 契约：

| 方向            | 事件                    | 用途                                                   |
| --------------- | ----------------------- | ------------------------------------------------------ |
| 客户端 → 服务端 | `/api/v1/*`             | 提交 Command 和 Query，共 36/37 个路由                 |
| 客户端 → 服务端 | `subscribe/unsubscribe` | 订阅 `task/operation/session/user:self` 频道           |
| 服务端 → 客户端 | `agent_event`           | 推送 `ServerPushEventV1`，使用 `snake_case/event_type` |

旧 `chat/cancel/resume_session` 是 deprecated 兼容通道，新客户端不再依赖它们。文字输入通过 `POST /api/v1/inputs/text`，任务取消通过 `POST /api/v1/tasks/cancel`，会话读取通过 `GET /api/v1/chat-sessions/:sessionId`。

Command body 使用：

```json
{
  "operation_id": "UUID",
  "client_source": "web",
  "request_fingerprint": "sha256:...",
  "payload": { "text": "你好", "input_id": "input-123" }
}
```

客户端通过 HTTP Bearer 或 Socket.IO `handshake.auth.token` 发送 HS256 JWT。服务端只使用 JWT `sub` 作为可信用户标识，并要求令牌包含 `exp`；会剥离 body/query 中的 `user_id/userId`。

任务取消也使用 Command 信封：

```json
{
  "operation_id": "UUID",
  "client_source": "web",
  "request_fingerprint": "sha256:...",
  "payload": { "task_id": "task-123" }
}
```

服务端 v1 事件均包含：

```json
{
  "schema_version": 1,
  "event_id": "event-123",
  "channel": "task:task-123",
  "sequence": 1,
  "event_type": "text_delta",
  "session_id": "session-123",
  "timestamp": 1788494400000,
  "data": "文本增量"
}
```

详细频道和事件联合类见 `packages/contracts/src/events.ts`。

## 6. 会话模型

`SessionManager` 通过 `SESSION_STORE=memory|postgres` 选择进程内存或 PostgreSQL：

- 每个用户最多保存 `MAX_SESSIONS_PER_USER` 个会话，默认 100；不同用户的限额互不影响；
- 每个会话最多保存最近 100 条 user/assistant 消息；
- 已存在会话只能由 JWT `sub` 对应的 owner 访问，跨用户访问统一按“会话不存在”拒绝；
- 每个正式 ChatTask 使用已提交的 session 消息快照创建独立 Agent 实例，后入队消息不会污染当前任务上下文；
- PostgreSQL 模式通过原子认领、lease/fencing 和创建顺序保证同一 `sessionId` 严格串行，旧 worker 的晚到写入不能覆盖新 fence；
- 同一 Socket 可以同时管理不同会话；
- 正式 v1 取消按 `taskId` 和 owner 生效，不以 Socket 连接作为任务身份；
- Socket 断开不取消已受理任务；
- LISTEN 重连后按本机已投递 position 对活跃 stream 主动 catch-up；客户端重连仍可按持久频道水位重放，游标失效时通过任务和会话 REST 查询恢复；事件同时受 count 与 age 配置约束并由后台分批清理；
- 新会话首次连接只订阅 `user:self`；在 REST 创建会话并返回权威引用后，才增量订阅 session/task/operation，并立即读取 TaskStatus 与 ChatSession 对账；
- 不允许为绕过首次订阅失败而放宽后端对不存在 session 的所有权校验，否则可能产生跨用户预订阅泄露。

限制：内存模式在服务重启后会丢失；数据库模式可以恢复 queued/running、隐私等待和工具审批等待任务，但网络分区下 Provider 调用本身仍不保证 exactly-once；当前只有完整回合裁剪、没有摘要压缩；尚未提供正式登录或 HTTP 令牌签发接口。LISTEN 重连 catch-up 只覆盖本实例活跃订阅，游标超过保留窗口仍返回 `recovery_required`，REST 始终是权威恢复源。

## 7. 工具模型

已接入只读工具：

```text
get_current_time
```

该工具无输入参数，返回服务器 ISO 8601 时间。当前权限与边界：

- 无副作用只读工具允许自动执行；
- 自动只读工具结果只进入当前 Agent 回合；需要批准的外部工具会持久化脱敏结果快照，以支持批准/拒绝后重启续推；
- 模型只能看到工具公开名称、描述、参数 Schema 和筛选后的结果；
- 前端工具事件只包含工具名、调用 ID 与成功状态；
- 不向前端透传 Pi 原始 result、参数、堆栈、密钥或环境变量；
- `tool-registry` 按 `riskLevel`(read_only/low/medium/high) 分级；`high` 必须 `requiresConfirmation`；
- **正式业务工具只生成 Candidate/Batch，不直接写正式对象**；正式对象（Goal/Action/Fact/Memory/Decision/Situation/Reminder）只能经 `SubmitConfirmationBatch` 生效；
- 外部系统副作用用独立的 **Tool Approval**（`confirm_tool_execution`/`dismiss_tool_execution`/`undo_tool_execution`），与正式 `ConfirmationBatch` 严格区分；
- 外部副作用执行中进程崩溃会进入 `indeterminate`，系统不自动重放；运维人员使用 `npm run tool:reconcile --workspace @partner-agent/backend -- ...` 在本机按固定结论核对并写脱敏审计，原失败任务不恢复；
- 审计记录 requester、session、tool、operation/call ID、脱敏摘要、结果和时间；
- 值级脱敏覆盖 Bearer/JWT/API Key、内部路径和异常文本，不只按字段名脱敏。
