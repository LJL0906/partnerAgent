### 1.2 未强行修复

两条保留链为：

- `expo-router@57.0.19` → `query-string@7.1.3` → `decode-uri-component@0.2.2`，对应 3 个 package entries；
- Expo / `@expo/*` config、plugin、prebuild、splash 链 → `xcode@3.0.1` → `uuid@7.0.3`，对应 11 个 package entries。

曾验证把叶子包覆盖为 `decode-uri-component@0.5.0`，实际会使 `query-string@7` 抛出 `TypeError: decodeComponent is not a function`，因此已经撤回；把 xcode 的 uuid 跨声明范围覆盖到 11.1.1 也会使依赖树 invalid，同样撤回。自动 fix 均建议与 SDK 57 不兼容的主版本或整体降级。当前处置是：

- 保留 Expo 57，不执行强制修复或整体降级；
- 保留 14 个 moderate package entries，按上述两条根链登记风险；
- 跟踪 Expo Router 上游迁移到兼容 `query-string >= 9.5.1` 的 SDK 57/后续正式版本；
- Native 外部 URL 入口通过 `+native-intent.ts`、Web 初始 URL 通过自定义入口，在交给 Expo Router 前限制长度和百分号转义数量并拒绝畸形编码；异常输入安全回退到 `/auth`。这是本地边界缓解，不把上游公告写成已消除。
- `xcode@3.0.1` 当前源码仅调用 `uuid.v4()`；公告覆盖的 v3/v5/v6 buffer 写入路径在该上游包中不可达，且该链只用于构建配置。继续保留审计告警并跟随 Expo 上游，不做越界 override。

1. 当前仍有 14 个 moderate package entries，归并为 Expo Router/query-string 与 Expo config/xcode 两条根链；没有 SDK 57 声明范围内已验证的上游修复，后续升级仍需重跑边界和 prebuild 回归。

3. Web 与 Native 已增加 Router 前输入边界，仍需跟随 Expo Router 将 query-string/decode-uri-component 升到安全兼容版本；部署层也应继续限制异常超长 URL。
4. Android 模拟器恢复已通过，真机键盘、发送和恢复仍未验收；Web 通过不能替代 Native 真机结论。
5. Expo Web 开发服务器在长时间、多轮热更新/重载后仍观察到 Windows `EMFILE`；重启 Metro 可恢复，但现有 watchFolders/maxWorkers 收敛未证明彻底消除该开发态问题。
6. Android 验证依赖当前 Compose 镜像与前端契约同步；运行旧镜像会明确触发快照格式错误，交接时必须执行 migration-gated rebuild，而不是仅重启旧容器。
7. 旧 Agent WS 与设计令牌候选需由对应入口负责人确认后逐项退役，不能按目录清理。
