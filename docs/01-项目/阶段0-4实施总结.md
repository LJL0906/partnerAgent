# 紫灵AI 阶段 0–4 实施总结

> 实施日期：2026 年 9 月 4 日
> 范围：基线验证、Monorepo 迁移、共享契约、会话模型、首个只读工具。

## 1. 总体结果

本次任务将原有单体 NestJS 后端整理为 npm workspaces Monorepo，并在不修改 Pi 源码、不提交密钥的前提下，完成了可复用的 WebSocket 契约、按会话隔离的 Agent 生命周期和最小只读工具闭环。

最终链路：

```text
测试客户端
  ↓ Socket.IO + sessionId
NestJS AgentGateway
  ↓ 产品级事件转换
PiAgentService
  ├── SessionManager（内存会话与历史）
  ├── ModelGatewayService（模型选择）
  └── get_current_time（只读工具）
        ↓
      工具结果返回模型上下文
```

## 2. 阶段完成情况

### 阶段 0：基线验证

- 完成依赖安装、构建、单测、e2e 和 lint；
- 原始基线为 3 个单测文件、3 个测试和 1 个 e2e；
- 所有命令退出码为 0；
- 没有为基线修复修改业务代码。

### 阶段 1：Monorepo 基础迁移

- 创建根 `package.json` 和 npm workspaces；
- 将后端迁移到 `apps/partner-agent-backend/`；
- 后端包名改为 `@partner-agent/backend`；
- 建立根 `package-lock.json`；
- 根 `.gitignore` 覆盖依赖、构建产物、环境文件和日志；
- 根目录和后端独立构建/测试均通过；
- 真实 WebSocket 模型对话由用户截图确认成功。

### 阶段 2：共享契约

- 创建 `@partner-agent/contracts`；
- 抽取 WebSocket 事件常量、请求类型和 Agent 事件类型；
- 后端移除 WebSocket 通道名硬编码；
- contracts 先于后端构建，支持干净环境从根目录构建；
- 增加契约运行时测试并生成 `.d.ts`。

### 阶段 3：会话模型

- 新增内存 `SessionManager`；
- Agent 按 `sessionId` 复用；
- 支持同一 Socket 多会话并发；
- 支持按会话精确取消；
- Socket 重连可恢复消息历史；
- 增加会话并发、取消隔离和历史恢复测试；
- 测试客户端增加会话 ID 编辑和加载能力。

### 阶段 4：只读工具

- 接入 `get_current_time`；
- 使用当前 Pi Agent 版本要求的 TypeBox Schema 和 `execute()` 接口；
- 工具执行结果以标准 ToolResult 返回模型；
- 前端收到规范化工具开始/完成事件；
- 原始工具结果和 Pi 内部事件不直接暴露给前端；
- 自动化测试覆盖“模型调用工具 → 工具返回结果 → 模型生成回复”的完整循环。

## 3. 关键决策

| 主题 | 当前决策 | 后续演进 |
| --- | --- | --- |
| 包管理 | npm workspaces | 规模需要时再引入任务编排工具 |
| 会话存储 | 进程内存 | 迁移数据库 |
| 会话限额 | 全局 100 个 | 认证后改为按用户限额 |
| 消息窗口 | 最近 100 条 | 改为 token 预算与摘要压缩 |
| Agent 生命周期 | 按 `sessionId` 复用 | 支持持久化重建与分布式锁 |
| 取消粒度 | 会话当前请求 | 可进一步引入 requestId |
| 工具权限 | 只读工具自动执行 | 写工具必须进入确认中心 |
| 工具结果 | 不落库 | 需要时增加脱敏审计记录 |
| 前端事件 | 产品级规范化事件 | 正式前端消费 contracts 包 |

## 4. 安全与数据边界

- 没有修改或纳入 `pi/`；
- 没有提交 `.env` 或 API Key；
- 不允许 Agent 或 RAG 绕过确认中心写正式业务数据；
- 工具不读取环境变量、密钥、用户标识或本地文件；
- 工具参数和 Pi 原始结果不直接发送给前端；
- 当前工具无副作用，因此不需要实时确认。

## 6. 已知限制

- 后端进程重启后会话历史丢失；
- 尚无认证和会话所有权校验；
- 同一会话只允许一个进行中请求；
- 上下文只按消息条数截断，没有摘要压缩；
- `test-client.html` 是静态验证工具，不是正式前端；
- 本地检出中没有 `pi/` 参考目录，但忽略规则仍保留；
- 真实工具调用需刷新测试页并由外部模型自主选择工具。

## 7. 后续建议

下一阶段应优先建立确认中心和工具权限框架，随后再考虑数据库会话、正式前端和写工具。任何事实、目标、行动或长期记忆写入都必须具备明确确认、权限校验、审计和撤销能力。
