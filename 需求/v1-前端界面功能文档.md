> 状态：前端信息架构与 UI 基调工作基线
>
> 基于：`个人助手项目交接文档.md`、`v1-详细子需求交叉整合.md` 及 v1 核心子需求

## 1. 产品界面定位

个人助手不是通用聊天机器人，而是围绕“记录 → 理解 → 确认 → 执行 → 复盘”的个人智能层。

前端负责：

- 输入：文字、语音、图片、网页链接、文件。
- 展示：对话、分析结果、目标、行动、记忆、处境、建议、摘要和提醒。
- 编辑：用户可理解、可修改的草稿和候选内容。
- 确认：收集用户的明确确认意图。
- 设备适配：录音、附件、通知、解锁和本地保护。

前端不负责：

- 直接写业务数据库。
- 直接调用外部模型、OCR、语音识别或 Embedding 服务。
- 根据模型文本自行判定正式对象是否创建。
- 绕过确认中心变更目标、行动、记忆、决策或处境。

## 4. 功能模块详细要求

### 4.1 应用访问保护

**页面：** 解锁页、重新验证弹窗、自动锁定提示。

**功能：**

- 设备解锁、生物识别或应用密码。
- 应用进入后台后自动锁定。
- 解锁失败、重试和重置提示。

**版本：** v1.0。

### 4.2 助手对话

**页面：** 会话列表、对话页、消息详情。

**功能：**

- 打开应用后直接输入，不要求先选择数据类型。
- 展示用户消息、助手回复、处理中状态和失败状态。
- 消息发送使用输入级幂等标识，重复网络重试不重复创建记录。
- 每条回复显示实际成功的供应商和 Model ID；自动切换过程默认折叠。
- 可从回复进入建议详情、依据展开和确认中心。

**不应出现：** 把模型生成文本直接显示成“目标已创建”或“行动已完成”。

**版本：** v1.0。

### 4.3 多模态输入

**输入类型：** 文字、语音、图片、网页链接、文件。

**功能：**

- 文本编辑和发送。
- 录音、停止、取消、重新录音。
- 语音转写结果的编辑和确认发送。
- 图片、文件和链接预览。
- 上传进度、原始保存状态、解析状态和失败原因。
- 解析失败时允许保留原始附件并重试解析。

**关键状态：** 草稿、录音中、转写中、待确认转写、上传中、已保存、解析中、解析失败、可重试。

**规则：** 语音转写未经用户确认，不得进入正式原始记录、分析、记忆、行动或 RAG。

**版本：** v1.0 提供输入、保存和状态展示；深度解析放 v1.1。

### 4.4 结构化分析结果

**展示内容：**

- 内容摘要
- 事实
- 问题
- 目标候选
- 行动候选
- 截止时间
- 现实限制
- 长期记忆候选
- 决策候选
- 需要确认的内容

**交互：**

- 多事项拆分为多个候选卡片。
- 卡片按类型分组，可展开、编辑、取消选择。
- 查看原始记录和来源。
- 查看分析运行状态、重新分析和历史分析结果。
- 进入确认中心统一处理。

**规则：** 分析结果、候选和正式对象必须有明显视觉区分。

**版本：** v1.0。

### 4.5 确认中心

**页面：** 待确认列表、批次详情、候选详情、处理结果。

**候选类型：** 创建或修改目标、行动、长期记忆、决策、处境关键字段、行动结果和状态变更。

**交互：**

- 默认选中但不视为确认。
- 查看来源、状态、可信度、风险和敏感标记。
- 单项取消、编辑、确认、拒绝、暂不处理、删除、标记识别错误。
- 一次提交多个不同类型的候选。
- 提交前显示变更摘要。
- 提交成功显示正式写入结果。
- 整批失败保持候选可重试。
- 版本冲突显示当前数据并允许重新生成变更意图。

**风险规则：** 高风险行动、敏感记忆和重要处境变更必须有额外提示，不能被“全部确认”静默处理。

**版本：** v1.0。

### 4.6 今日与每日行动摘要

**内容：**

- 今天需要完成的行动。
- 进行中的行动。
- 即将到期和已过期行动。
- 当前最重要目标。
- 今日优先行动建议。
- 待确认内容。
- 当前风险和阻碍。

**快捷操作：** 查看行动、开始、完成、延期、暂时搁置、稍后提醒、进入确认中心。

**规则：** 摘要只展示和收集操作意图，不直接修改正式对象；每天最多一份摘要。

**版本：** v1.0。

### 4.7 行动管理

**页面：** 行动列表、行动详情、行动结果、变更历史。

**列表筛选：** 待开始、进行中、暂时搁置、已完成、已取消、已过期、今天、即将到期、关联目标、已归档。

**详情信息：**

- 行动内容、执行状态、计划状态、时效状态。
- 截止时间、提醒设置、关联目标。
- 来源记录、现实限制、执行结果。
- 创建时间、更新时间和状态变更历史。

**操作：** 开始、完成、延期、搁置、恢复、取消、修改截止时间、设置提醒、记录结果、归档、删除。

**规则：** 执行状态和时效状态分开表达，例如“进行中（已过期）”；所有正式变更仍通过确认规则。

**版本：** v1.0。

### 4.8 目标管理

**页面：** 目标列表、目标详情、目标进展、关联行动、变更历史。

**详情信息：**

- 目标内容、状态、优先级、截止时间。
- 当前进展和关联行动。
- 现实限制、相关记忆、决策、原始来源。
- 来源依据、创建时间和状态历史。

**操作：** 修改、暂停、恢复、完成、放弃、修改截止时间、创建关联行动、复盘、归档、删除。

**规则：** 行动全部完成不会自动完成目标；目标过期不会自动改变正式状态。

**版本：** v1.0。

### 4.9 提醒中心

**提醒类型：** 精确截止提醒、用户手动提醒、过期集中提醒、待确认提醒、每日摘要、每周复盘。

**操作：** 完成、延期、搁置、查看行动、稍后提醒、关闭本次提醒、关闭单条或全部待确认提醒。

**规则：** 只有日期没有具体时间的行动进入摘要，不自动生成精确提醒；逾期行动每天最多集中提醒一次。

**版本：** v1.0 提供基础提醒。

### 4.10 事实与长期记忆

**页面：** 事实列表、长期记忆列表、敏感记忆分组、详情、冲突处理、过期记忆。

**展示：** 内容、来源、时间、可信度、当前／过期状态、用户确认状态、敏感标记和使用限制。

**操作：** 修正、标记识别错误、确认保存、更新、处理冲突、标记过期、删除、查看来源。

**规则：** 事实不能自动升级为长期记忆；旧记忆保留并标记过期；敏感记忆单独分组并显著提示。

**版本：** v1.0 基础能力；复杂合并放 v1.1。

### 4.11 当前处境

**内容：** 重要目标、进行中目标、行动及状态、截止时间、现实限制、当前问题、最近变化、风险阻碍和最近决策。

**页面：** 当前处境、字段详情、来源依据、用户修正、待确认变化、历史版本。

**规则：** 处境是聚合快照，不是新事实来源；影响重要决策的关键字段需要进入确认中心。

**版本：** v1.0 基础查看；完整历史分析放 v1.1。

### 4.12 建议与 RAG 依据

**建议展示：**

- 一个最推荐行动和一至两个备选行动。
- 推荐原因、成本、风险和信息缺口。
- 目标冲突和优先级建议。
- 过去类似行动结果。
- 采纳、拒绝和拒绝原因。

**依据展示：** 默认折叠“本次参考”，展开后显示相关目标、行动、记忆、原始记录、历史结果、来源时间、状态、可信度、确认状态、敏感标记和待确认标识。

**空结果：** 明确告知没有找到相关记录；推测标为推测；引导补充信息或重新建立记录。

**规则：** RAG 只提供依据，不直接修改正式对象；过期记忆普通建议排除，历史复盘可使用并标识历史状态。

**版本：** v1.0 基础建议和依据展示。

### 4.13 每周复盘与决策记录

**复盘内容：** 完成和未完成行动、延期／过期／搁置、目标进展、未完成原因、计划与实际差异、建议效果、目标调整、记忆更新和下周行动。

**决策字段：** 决策内容、当时目标、可选方案、选择理由、限制、预期结果、验证时间、实际结果和复盘结论。

**规则：** 统计内容可直接展示；新行动、目标调整、记忆更新、决策记录和处境变更进入确认中心。

**版本：** v1.0 可提供基础入口和基础复盘；完整体验放 v1.x。

### 4.14 模型设置

**页面：** 模型列表、模型编辑、连接测试、调用状态。

**配置项：** 供应商、Base URL、API Key、Model ID、默认模型、列表排序、跨供应商自动切换。

**交互：**

- 模型拖动排序，决定失败后的尝试顺序。
- 设置中测试连接。
- 发送前选择本次模型和推理等级。
- API Key 默认遮挡，不能进入日志和导出。

**版本：** v1.0。

### 4.15 隐私与安全

**设置项：**

- 自动脱敏后发送。
- 发送前查看并确认。
- 检测到敏感信息时禁止发送。
- 应用锁和自动锁定。
- 敏感记忆显示策略。

**外发确认弹窗：** 展示敏感类别、受影响来源、处理方式、脱敏预览、取消和确认发送。

**规则：** 身份证件、银行卡、密码、API Key 和密钥不得以未脱敏值发送给外部模型；重试和切换模型时重新检查。

**版本：** v1.0。

### 4.16 数据导出

**页面：** 导出配置、导出预览、任务列表、结果详情。

**范围：** 原始记录、结构化对象、来源关系、附件、目标、行动、事实、记忆、决策、处境和历史版本；待确认、过期、软删除、聊天展示和调用记录可选。

**格式：** Markdown、JSON、原始文件压缩包。

**流程：** 选择范围 → 选择格式 → 预览数量和敏感信息 → 设置密码／保护 → 确认生成 → 查看进度 → 获取结果。

**规则：** API Key 和其他凭证永远排除；未完成临时包不可交付；导出只读且不改变业务数据。

**版本：** v1.0。

### 4.17 通用状态与系统状态

所有异步页面统一支持：

- 初始加载、骨架屏、空状态。
- 处理中、后台排队、已完成。
- 失败原因摘要、重试、取消和补偿状态。
- 版本冲突、来源删除、索引不完整、依据不足。
- Local Core、模型连接、后台任务和索引健康状态。


### 4.18 统一页面骨架与术语

所有页面固定使用同一套 App Shell：

1. 顶部标题区。
2. 顶部右侧确认中心入口和待确认数量角标。
3. 页面内容区。
4. 统一底部导航：`助手 / 今日 / 执行 / 记忆 / 我的`。
5. 统一底部安全区、页面边距和操作反馈。

页面只允许改变标题、筛选、业务内容和页面级操作；导航位置、标题层级、主按钮样式、状态颜色、卡片圆角、页面边距和内容密度保持一致。

产品术语固定如下，不在不同页面使用同义词替换：

| 统一术语 | 禁止混用 |
|---|---|
| 行动 | 任务、待办、事项、计划 |
| 目标 | 计划目标、项目目标、愿望 |
| 候选 | 草稿、预测结果、建议对象 |
| 确认中心 | 审批、审核、发布 |
| 事实 | 信息点、资料项 |
| 长期记忆 | 用户画像、知识点、偏好库 |
| 当前处境 | 工作台状态、上下文面板 |
| 来源 | 依据来源、引用记录、出处（作为标题时统一使用“来源”） |

### 4.19 统一组件与交互

全局复用组件：

- 页面标题栏。
- 确认中心入口。
- 底部导航。
- 状态标签。
- 候选卡片。
- 行动行和目标摘要卡。
- 来源组件。
- 建议卡片和“本次参考”折叠面板。
- 异步任务状态。
- 空状态、错误状态、重试按钮。
- 二次确认弹窗和 Toast 操作结果。

同一组件只通过内容和状态变体变化，不为单个页面重新设计一套按钮、卡片或状态颜色。

统一交互规则：

- 对话页只展示“待确认候选”，确认事务成功后才显示正式对象结果。
- 今日页展示权威行动和提醒，完成、延期、搁置只提交变更意图。
- 执行页展示正式目标和行动，所有状态变更进入确认流程。
- 确认中心提交成功后返回来源页，并刷新相关对象、摘要和提醒。
- 确认失败显示“失败原因 + 重试 + 返回”，不得伪造成功状态。
- 所有详情页面按“标题与状态 → 核心信息 → 时间与优先级 → 关联对象 → 来源与依据 → 历史记录 → 操作”顺序组织。

### 4.20 中文文案基线

页面只使用统一中文短标签，避免同一功能出现中英文混排或不同译法：

```text
助手 / 今日 / 执行 / 记忆 / 我的
待确认 / 今日优先 / 进行中 / 即将到期
查看行动 / 进入确认中心 / 本次参考 / 查看依据
目标候选 / 行动候选 / 长期记忆 / 编辑 / 拒绝 / 暂不处理 / 确认选中
行动 / 目标 / 截止时间 / 完成 / 延期 / 搁置
```

Model ID、供应商名称、Base URL 等技术字段保留原始技术命名；除此之外，面向用户的功能名称默认使用中文。
## 5. UI 主题基线：晨雾青・智能陪伴

### 5.1 主题关键词

```text
清新 · 轻盈 · 安静 · 有秩序 · 智能但不冰冷
```

### 5.2 色彩

- 页面底色：暖白 `#F8FBFA`。
- 主色：清透青绿 `#23B7A3`，用于主按钮、完成和确认。
- 辅助色：雾蓝 `#5B8DEF`，用于链接、信息和依据。
- 智能强调：柔和靛蓝 `#7667E8`，只用于 AI 状态和思考等级。
- 警示色：清晰橙 `#F29B58`，用于到期、风险和待处理。
- 错误色：柔和珊瑚红 `#E97979`，用于失败和阻止。
- 正文：深蓝灰 `#213547`；次级文字 `#6C7A86`。
- 卡片：纯白 `#FFFFFF`，边框使用极浅蓝灰，不使用脏灰块。

### 5.3 视觉原则

- 大面积留白，减少视觉噪音。
- 圆角卡片和细线图标，避免厚重拟物。
- 轻微渐变只用于 AI 状态或重点摘要，不大面积铺色。
- 使用状态标签、时间线和进度环传达信息。
- 重要操作使用一个明确主按钮，避免多主色竞争。
- 不使用土黄、棕色、脏灰、荧光色、强烈霓虹和过度赛博朋克效果。
- 文字优先保证可读性，敏感内容不做完整明文展示。

### 5.4 组件基线

- 12～16 px 圆角卡片。
- 8 px 间距基准，形成清晰节奏。
- 主按钮采用青绿色实心；次按钮使用白底描边。
- 状态标签采用浅色底加深色文字，不使用纯红／纯绿大面积填充。
- AI 生成内容使用细微靛蓝标记；用户确认后的正式对象使用青绿色标记。
- “待确认”使用橙色小面积提醒，不把整张页面染成警示色。
- 来源依据采用可折叠抽屉或展开面板。

## 6. 关键用户流程

### 6.1 输入到正式对象

```text
输入文字／语音／附件
→ 保存原始记录
→ 分析中
→ 展示结构化结果和候选
→ 用户编辑或取消候选
→ 进入确认中心
→ 用户明确确认
→ 正式创建目标／行动／记忆等对象
→ 返回结果并显示来源
```

### 6.2 建议到行动

```text
助手给出推荐行动
→ 展开查看原因、风险和依据
→ 用户采纳
→ 形成行动候选
→ 用户确认
→ 正式行动创建
```

### 6.3 行动到复盘

```text
查看今日摘要／提醒
→ 完成、延期或搁置操作
→ 形成状态变更意图
→ 确认后写入
→ 周期性生成复盘
→ 新行动、目标、记忆和决策再次进入确认中心
```

## 7. 统一交互与状态规则

1. 候选、正式对象、历史对象和删除对象必须视觉区分。
2. 默认选中、卡片展示、关闭页面和编辑草稿都不等于确认。
3. 目标、行动、记忆、决策和处境的正式变更必须可追溯到确认操作。
4. 所有对象详情都应支持查看来源和状态历史。
5. 业务状态、时效状态、任务状态、投递状态和生命周期状态不可混用。
6. 原始记录、分析结果、候选和正式对象不可相互覆盖。
7. 异步任务失败时，优先保留已成功保存的原始内容，并提供重试。
8. 敏感信息在编辑、摘要、通知、依据、日志和外发场景采用不同展示策略。
9. 客户端只向 Local Core 提交命令或查询，不直接操作权威数据。
