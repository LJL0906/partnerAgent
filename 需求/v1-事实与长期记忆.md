## 1. 文档目的与范围

本文件定义 v1 中“从用户历史里知道了什么”和“允许在未来持续依赖什么”的边界，避免把模型抽取、用户确认、检索召回和正式业务写入混为一谈。

本文件覆盖：

- 事实与长期记忆的定义、来源、可信度和生命周期；
- 自动抽取、用户明确表达与助手推断的标记规则；
- 长期记忆的确认、更新、冲突、相似合并、删除与恢复；
- 事实和记忆参与 RAG、敏感信息处理及决策复盘的范围；
- 与原始记录、确认中心、决策记录、处境模型的责任边界。

本文件不决定：具体数据库字段类型、可信度数值或阈值、文本分块和 Embedding 实现、敏感识别器与脱敏格式、复杂编辑/合并交互和跨设备同步。上述内容在本文件中均保留为待决策项，不得因本文件而静默冻结。

## 2. 核心对象与共同原则

### 2.1 对象关系

```text
原始记录 / 外部材料
        ↓ 自动分析
事实（带来源、可信度、表达方式和状态）
        ↓ 用户确认
长期记忆（可持续用于未来个人理解）
        ↕ 关联但不替代
决策记录 / 行动结果 / 处境模型
```

- **原始记录**保留用户当时的输入，是追溯和重新分析的基础。
- **事实**是从来源中抽取出的、与用户有关的陈述；可以自动保存和受限检索，但不天然代表“当前有效”或“用户已确认”。
- **长期记忆**是用户确认后允许在未来持续使用的正式对象；必须能回溯到至少一条事实或原始记录。
- **决策记录**保存一次具体选择、当时条件和结果；**决策经验记忆**是从多个决策或复盘中沉淀出的可长期复用认识。两者必须关联，不能相互替代。
- **处境模型**是当前正式对象的聚合快照，不是新的事实或记忆来源，不能反向覆盖源对象。

### 2.2 共同原则

1. 原始记录、事实、长期记忆、检索索引分层保存；结构化对象是权威，索引只是可重建的派生数据。
2. 模型和后台任务只能产生分析结果、事实、候选项和建议；只有 Local Core 能依据用户确认写入或变更正式长期记忆。
3. 每条事实和记忆都必须保留来源、发生/观察时间、当前状态、可信度、确认状态、敏感标记及关键变更历史。
4. 不因“被抽取”“被检索”“被模型重复提及”而自动提高可信度、升级为用户确认事实或长期记忆。
5. 任何外部模型请求都必须在上下文组装后、请求发出前经过统一敏感信息处理钩子。

## 3. 关键问题与答案

### 问题 1：事实和长期记忆到底有什么区别？

**推荐答案：** 事实是“有来源的陈述记录”，长期记忆是“经用户确认、可在未来持续使用的个人理解”。前者解决可追溯地保留信息，后者解决长期稳定地理解用户；二者不能互相替代。

```text
“我最近在准备考证”
→ 可自动形成事实：近期正在准备考证
→ 若用户确认其会长期影响规划
→ 才形成长期记忆：当前阶段的长期目标/现实限制与考证有关
```

**已确认边界 / 待决策项：**

- **已确认：** 事实可自动提取并保存，带来源和可信度；长期记忆必须经用户确认后保存。并非所有事实都要成为记忆，所有记忆都应能追溯到事实或原始记录。
- **已确认：** 普通建议优先使用当前有效的长期记忆；事实可作为补充证据，但其状态和可信度必须随上下文传递。
- **待决策：** 事实是否在少数高风险场景下需要独立确认，以及哪些事实类型默认不进入检索。

**验收标准：**

- 同一条原始记录可产生多个事实，但不会自动创建长期记忆。
- 任何长期记忆均能看到至少一条来源事实或原始记录。
- 在界面、导出和 RAG 依据中，事实与长期记忆可被明确区分。

### 问题 2：自动抽取的事实可信度如何定义，能否当作真相？

**推荐答案：** 可信度是“该陈述在当前证据下可被参考的程度”，不是系统对客观真相的宣告。自动抽取必须分别记录来源强度、抽取把握和时效/冲突状态；低可信度或有争议事实只能谨慎参考。

建议将可展示的可信度分为“高 / 中 / 低 / 未评估”，并至少由以下信息支撑：

```text
来源强度：用户明确表达 / 用户材料直接陈述 / 助手抽取或推断 / 外部材料
抽取把握：模型对文本与事实表述是否一致
证据情况：单一来源 / 多个相互支持来源 / 存在冲突来源
时效状态：近期观察 / 已久未确认 / 已过期 / 有争议
```

可信度不应只由模型分数决定；用户明确否认、来源被删除、出现更晚且冲突的表达，都必须影响状态或可信度说明。

**已确认边界 / 待决策项：**

- **已确认：** 事实必须有来源，且保存可信程度、来源类型、首次出现时间、最后确认或观察时间、状态和敏感标记。
- **已确认：** 重要建议不能把未经确认的抽取事实包装成用户确认结论；低可信度信息在重要决策中必须提示可能过期或不确定。
- **待决策：** 高、中、低的具体计算规则、模型阈值、人工修正入口和不同事实类型的默认初始等级。

**验收标准：**

- 自动产生的每条事实均可查看来源、表达方式、可信度和状态。
- 系统不会仅因同一模型多次抽取到同一事实而把它标记为用户确认。
- 用低可信度或有争议事实支持重要建议时，建议依据会明确显示不确定性。

### 问题 3：如何区分用户明确表达、助手抽取和助手推断？

**推荐答案：** 三者必须独立标记，且不得相互升级：用户原话或可直接等义转述属于“用户明确表达”；从原话中做字段化整理属于“助手抽取”；跨语句、上下文或概率判断得出的结论属于“助手推断”。

```text
用户明确表达： “我不想再接需要频繁出差的工作。”
助手抽取：     长期偏好：避免频繁出差的工作
助手推断：     用户当前职业选择可能优先考虑远程岗位
```

助手抽取即使表述合理，也不能被标为用户明确表达；助手推断不得被当作稳定偏好、现实限制或决策依据的唯一来源。

**已确认边界 / 待决策项：**

- **已确认：** Fact 与 Memory 都需要保存“是否用户明确表达”“是否助手推断”或等义来源类型；未经确认的抽取事实不能标为用户确认事实。
- **已确认：** 助手可提出记忆候选和追问，但不得绕过确认中心把推断写为正式长期记忆。
- **推荐补齐：** 对用户明确说出“请记住 / 以后按此处理”的内容，可把该表达作为保存意图；仍需留下明确确认操作记录，而不是仅凭模型判断其意图。
- **待决策：** 是否为“直接等义转述”提供用户可见的证据片段，以及用户对来源类型的手动改标范围。

**验收标准：**

- 同一事实能显示其是用户明确表达、助手抽取还是助手推断。
- 将助手推断保存为长期记忆时，确认卡片会明确显示“助手推断”，而非暗示用户曾直接说过。
- 用户指出“这不是我的意思”后，该事实或候选不会在相同来源基础上反复以同样方式提出。

### 问题 4：哪些事实可以自动保存，哪些变更必须确认？

**推荐答案：** 来源明确、影响有限的事实可以自动保存为“可参考事实”；只要会改变未来对用户的长期理解、覆盖当前记忆、影响正式对象或成为重要建议唯一依据，就必须进入确认中心。

自动保存不等于自动生效为长期结论。自动事实至少处于“抽取”或“可参考”状态，并保留其来源和可信度。

**已确认边界 / 待决策项：**

- **已确认：** 事实可自动抽取和保存；长期记忆候选、保存长期记忆、使旧记忆过期、影响正式目标/行动/处境模型的事实变更，都必须经过确认中心。
- **已确认：** 待确认内容不得自动升级为正式目标、行动或长期记忆，也不能作为已确认事实使用。
- **推荐补齐：** 当自动事实将作为重要决策或高风险建议的唯一关键依据时，系统应先请求用户核实，或改用低风险建议并说明信息不足。
- **待决策：** 事实的保留期限、批量确认方式，以及“重要决策”的具体风险分级。

**验收标准：**

- 普通输入后可以产生事实记录，但不会出现未经确认的长期记忆。
- 可能使现有记忆过期或改变现实限制的事实，会生成带影响说明的确认候选。
- 后台任务只能产生事实/候选，不会直接写入长期记忆。

### 问题 5：保存长期记忆时，确认应确认什么？

**推荐答案：** 用户确认的对象应是“准备长期使用的记忆表述及其影响”，不是笼统确认一段模型分析。确认卡片至少展示内容、类型、来源摘要、表达方式、可信度、敏感性、当前状态和与已有记忆的关系。

```text
记忆候选
→ 用户查看原始依据与助手标记
→ 确认 / 修改后确认 / 拒绝 / 暂不处理 / 标记识别错误
→ Local Core 创建正式长期记忆、来源关系、变更记录和索引任务
```

**已确认边界 / 待决策项：**

- **已确认：** 保存长期记忆是强制确认边界；默认全选不等于确认；修改后的候选只有明确提交才生效。
- **已确认：** 敏感长期记忆必须单独分组、明显标记，不能因“确认全部”而无提示保存。
- **推荐补齐：** 确认卡片中必须显式展示“用户明确表达 / 助手抽取 / 助手推断”，并在推断类候选上显示低风险提示。
- **待决策：** 记忆候选有效期、再次提醒间隔，以及直接使用聊天命令确认时是否省略独立卡片。

**验收标准：**

- 用户可从记忆确认项查看至少一条来源及其时间。
- 用户修改候选内容后，系统只保存修改后的版本，并记录确认操作。
- 未确认、暂不处理、拒绝的候选均不会参与“当前有效长期记忆”集合。

### 问题 6：记忆会如何过期、冲突和更新？

**推荐答案：** 不直接覆盖旧记忆。新信息与当前记忆冲突时，先生成新的记忆候选；用户确认后，旧记忆标记为“过期”或“不再适用”，新记忆成为当前有效版本，并保留两者的来源与先后关系。

```text
发现冲突或明确失效条件
→ 保留旧记忆及其来源
→ 创建新记忆候选并展示冲突内容
→ 用户确认
→ 旧记忆过期 / 不再适用
→ 新记忆有效
→ 更新索引与变更历史
```

“过期”表示它曾经成立但不应再用于当前普通建议；不等于错误或删除。“有争议”表示存在冲突信息但尚未由用户确认当前结论。

**已确认边界 / 待决策项：**

- **已确认：** 旧记忆不直接覆盖；冲突时保留历史，确认后将旧记忆标记为过期或不再适用；普通建议只用当前有效记忆，历史复盘可以读取过期记忆。
- **推荐补齐：** 仅因长时间未见新信息，不自动把记忆改为过期；系统最多标记“建议复核”。只有用户确认的新信息、记忆自带明确有效期，或用户手动操作，才改变当前有效状态。
- **待决策：** 各类记忆的默认复核周期、自动识别冲突的相似度规则、过期与“不再适用”的最终状态枚举。

**验收标准：**

- 新旧冲突记忆可同时查看，且能看到各自来源、状态和先后关系。
- 当前建议不会使用已过期记忆作为当前限制或偏好；历史复盘可按场景引用它并标注历史状态。
- 用户未确认冲突时，旧记忆不会被静默改写或删除。

### 问题 7：多来源记忆如何保存和更新可信度？

**推荐答案：** 一条记忆应支持多个来源关系，而不是把多个记录拼成无法追溯的一段文本。来源之间可以是支持、补充、冲突或替代关系；来源增加只增强可解释性，不自动改变记忆内容、确认状态或当前状态。

```text
记忆：当前阶段更适合在本地工作
来源 A：用户明确表达，2026-08-xx
来源 B：行动结果，2026-09-xx
来源 C：助手推断，待确认
```

可信度展示应能说明“为何可参考”，而非只给一个不可解释的分数。互相支持的独立来源可提高参考价值；冲突来源必须使记忆进入有争议或更新候选流程。

**已确认边界 / 待决策项：**

- **已确认：** 长期记忆需要来源关系集合；事实和索引记录也必须保留来源、时间、可信度、确认与敏感状态。
- **推荐补齐：** 自动添加的支持来源应标为“尚未改变记忆正文的补充证据”；若补充来源会改变表述、类型或结论，必须生成候选并确认。
- **待决策：** 多来源可信度的计算模型、何种来源视为独立证据、来源失效后是否自动降低可信度。

**验收标准：**

- 一条长期记忆可关联多条事实、原始记录、决策或行动结果。
- 用户能够区分支持来源与冲突来源，且删除一条来源不会抹除其他来源关系。
- 新增来源不会在没有确认的情况下改变已确认记忆的正文或状态。

### 问题 8：相似记忆是否自动合并？

**推荐答案：** v1 不自动合并正式长期记忆。系统可以识别相似或重复候选、提示可能关联，并支持将来源挂到已有记忆；需要改写、合并或删除任何正式记忆时，必须由用户确认。

这是为了避免把“相近但范围不同”的偏好、经历或限制错误压缩为一个结论，也符合 v1.0 将复杂记忆合并后置的范围约束。

**已确认边界 / 待决策项：**

- **已确认：** 复杂记忆合并属于 v1.1 或后续；相似记忆的复杂合并不自动执行，合并需要用户确认。
- **推荐补齐：** v1 只提供三种最小处理：保留为独立记忆、作为已有记忆的补充来源、生成“建议合并”候选。系统不得自动删除其中任一条。
- **待决策：** 相似度阈值、合并后的历史展示方式、批量去重与反向拆分能力。

**验收标准：**

- 输入与已有记忆相似时，系统可提示关联但不自动改变或删除既有记忆。
- 用户确认合并前，原记忆、候选和来源均保持完整可追溯。
- v1 的普通流程不会依赖复杂自动合并才能正常检索和建议。

### 问题 9：记忆删除、归档、恢复和彻底删除如何处理？

**推荐答案：** 对长期记忆区分归档、软删除和彻底删除；删除只影响该记忆的日常使用，不自动删除来源记录、事实、目标、行动或决策。恢复是对软删除/归档状态的反向变更，不是重新生成一条无来源的记忆。

```text
归档：保留历史，默认不参与日常界面和普通建议
删除：进入删除状态，不参与日常建议和普通 RAG
恢复：恢复原对象、来源和历史状态；必要时提示重新确认有效性
彻底删除：物理清除本地记忆对象及其可清除派生索引，需要二次确认
```

已删除原始记录的正文不再参与检索，但此前已确认的记忆可继续保留，来源展示为“原始记录已删除”。彻底删除后不承诺恢复。

**已确认边界 / 待决策项：**

- **已确认：** 默认软删除，彻底删除需二次确认；删除父对象不自动删除关联对象；删除原始记录不自动删除已确认记忆。
- **已确认：** 被删除的记忆不参与日常建议；最近的重要操作建议支持撤销，撤销通过新的反向操作保留历史。
- **推荐补齐：** 恢复过期或有争议的记忆时，恢复其删除前状态，不自动改为有效；若用户希望重新用于当前建议，应生成复核/更新候选。
- **待决策：** 软删除保留期限、撤销入口保留时间、彻底删除是否保留不可逆的最小审计摘要。

**验收标准：**

- 删除长期记忆后，该记忆不再被普通 RAG 和日常建议召回。
- 删除记忆不会删除其原始记录或其他正式对象；删除原始记录也不会自动删除记忆。
- 从软删除恢复后，记忆的稳定标识、来源和关键变更历史保持可追溯；彻底删除后不能恢复正文或索引内容。

### 问题 10：事实和长期记忆在 RAG 中分别能做什么，不能做什么？

**推荐答案：** RAG 的目标是为当前问题提供“少量、相关、带状态的依据”，不是把全部历史或所有记忆送给模型。长期记忆用于持续的个人理解；事实和原始记录用于补充证据、澄清时间和处理不确定性。

```text
普通建议优先：
当前目标 + 当前行动 + 当前有效限制 + 当前有效长期记忆
+ 相关行动结果 + 决策/复盘结果 + 最近相关记录

按需补充：
相关事实（带可信度）+ 原始记录证据

仅限特定场景：
待确认内容（显式标记）+ 过期记忆（历史复盘）
```

RAG 不得：把待确认内容当用户确认事实、把过期记忆当当前约束、把低可信度推断作为重要决定的唯一依据、使用已删除原始记录正文，或通过检索直接写回/更新任何事实和长期记忆。

**已确认边界 / 待决策项：**

- **已确认：** RAG 采用“结构化条件筛选 + 关键词/语义检索 + 模型综合判断”；结构化数据优先，原始记录作为补充和证据；不默认读取全部历史。
- **已确认：** 待确认内容可以召回但必须带状态；普通建议排除过期记忆，历史复盘可使用；找不到记录必须明确说明，推测必须标记为推测。
- **已确认：** 每条检索结果需要携带来源类型、来源记录、发生时间、当前状态、可信度、确认状态和敏感标记；对外不发送内部 ID、路径或数据库字段。
- **待决策：** 召回数量、排序权重、分块策略、Embedding 实现、事实在普通问题中的默认权重。

**验收标准：**

- 普通建议使用的记忆可追溯到“当前有效 + 已确认”的状态，不会默认为全历史检索。
- 历史复盘引用过期记忆时，用户能看到它当时的状态和时间。
- 检索无结果时，回复明确说明没有相关记录，而不会虚构个人历史。
- 一次 RAG 或模型调用不会改变任何事实、记忆、目标或行动的正式状态。

### 问题 11：敏感事实和敏感记忆如何处理？

**推荐答案：** 本地保存与外部使用严格分离。用户确认后可在本地保存敏感长期记忆，但必须单独分组、明显标记；任何外发上下文（包括 RAG 结果和模型重试）都先经过敏感策略，再按用户模式脱敏、要求查看确认或阻止发送。

v1 强制识别的敏感类别是身份证件、银行卡、密码、API Key 和其他密钥。敏感标记不改变对象的来源与生命周期，但会影响确认展示、检索展示、访问和外发处理。

**已确认边界 / 待决策项：**

- **已确认：** 敏感长期记忆可在用户确认后本地保存；不得因“确认全部”而无提示保存；外部模型永远不能看到未脱敏敏感值。
- **已确认：** 敏感信息钩子覆盖用户输入、RAG 结果、长期记忆、处境模型、附件解析、每日摘要、周复盘、后台任务和重试请求；默认模式为自动脱敏后发送。
- **推荐补齐：** 敏感记忆仅在当前任务确有必要时参与本地检索；用户查看“本次参考”时也应展示敏感标识，避免把敏感内容伪装成普通依据。
- **待决策：** 误报/漏报处理、稳定占位符规则、单次放行机制、本地数据库与原始附件的额外加密方式。

**验收标准：**

- 敏感记忆保存前有明显提示，且不能被普通批量确认无提示写入。
- 同一敏感记忆即使被 RAG 召回，外发请求中也只存在策略允许的脱敏版本，或请求被阻止。
- 模型调用日志不保存完整敏感上下文、完整 RAG 结果或原始模型输出。

### 问题 12：决策记录、决策经验和长期记忆是什么关系？

**推荐答案：** 决策记录保存“一次选择发生了什么”；决策经验记忆保存“从已确认的选择和结果中长期学到了什么”。决策经验必须能够回指一个或多个决策记录、行动结果或复盘结论，不能脱离证据变成模型自行编写的人格标签。

```text
重要选择
→ 用户确认保存决策记录
→ 行动执行与结果
→ 复盘形成经验候选
→ 用户确认后保存为“决策经验”长期记忆
```

在建议中，具体决策记录适合回答“上次类似问题发生了什么”；决策经验适合回答“长期看来哪些选择标准更有效”。二者都只能作为依据的一部分，不能替代用户当前目标、限制和最新信息。

**已确认边界 / 待决策项：**

- **已确认：** 重要决策可由助手建议建立记录，用户确认后保存；决策记录包含当时目标、方案、理由、限制、预期、实际结果和复盘结论等可用信息。
- **已确认：** “决策经验”是长期记忆类型之一；完整决策复盘属于 v1.1 或后续增强，但 v1 可保留基础决策与结果来源。
- **推荐补齐：** 从一次结果自动生成的只能是决策经验候选；避免把偶然成功/失败直接固化为长期规律。经验候选应说明样本范围与不确定性。
- **待决策：** 决策的重要性判断、复盘触发条件、经验有效性复核周期，以及决策经验的细分类型。

**验收标准：**

- 决策经验长期记忆可查看关联的决策、行动结果或复盘来源。
- 系统不能在没有用户确认的情况下，把一次模型建议或一次行动结果直接写成长期决策经验。
- 用户询问建议依据时，可区分“具体历史决策”与“从历史沉淀的经验”。

## 4. 最小生命周期与状态规则

### 4.1 事实生命周期

```text
原始记录 / 外部材料
→ 自动抽取
→ 抽取 / 可参考
→（新证据）补充、降低可信度或进入有争议
→（用户确认且适合长期使用）生成长期记忆候选
→ 已过期 / 错误 / 已删除
```

- **抽取：** 生成但尚未充分验证的事实。
- **可参考：** 来源和内容足以作为普通上下文补充，但不等于用户确认。
- **有争议：** 与其他来源冲突，或用户尚未确认当前版本。
- **过期：** 曾经成立但不宜作为当前事实；仍可用于历史解释。
- **错误：** 用户明确指出识别错误；相同依据不得反复产生同样候选。
- **已删除：** 进入删除状态；不参与普通检索。

### 4.2 长期记忆生命周期

```text
事实 / 原始记录
→ 记忆候选（待确认）
→ 用户确认
→ 当前有效
→ 复核提示 / 有争议
→ 过期或不再适用
→ 归档 / 删除
→ 恢复（回到删除前状态）
→ 彻底删除（不可恢复）
```

- 候选、有效、过期、有争议、归档/删除等业务与生命周期状态应可区分表达，避免把“已过期”误当作“已删除”。
- 与已有记忆冲突时，新的内容先作为候选存在；用户确认前，旧记忆保持原状态。
- 建议复核不是自动过期；复核结果必须由用户确认或可追溯的明确有效期触发。

### 4.3 状态与索引一致性

结构化对象变化后，Local Core 在同一确认或删除事务中写入对象、来源关系和关键变更历史，并登记索引更新任务。索引更新失败不回滚已确认的业务对象；重建索引以结构化对象和仍可访问的原始记录为输入。

## 5. 已确认边界汇总

以下规则已由现有需求、架构或存储基线确认，本文件不得改变：

1. 原始记录自动保存；事实可自动抽取；长期记忆必须用户确认后写入。
2. 模型、客户端和后台任务都不能绕过 Local Core 与确认中心直接写入正式长期记忆。
3. 每条事实/记忆保留来源、时间、可信度、表达方式、确认状态、当前状态和敏感标记。
4. 用户明确表达、助手抽取、助手推断必须区分，未经确认的内容不得伪装为用户确认事实。
5. 冲突记忆不直接覆盖；旧记忆保留并标记过期或不再适用，新记忆另存为新版本。
6. 普通建议只使用当前有效记忆；历史复盘允许使用过期记忆，并应保留历史语境。
7. RAG 结构化筛选优先，原始记录作为补充证据；待确认内容必须显式标记，不能作为已确认事实。
8. 索引不是权威事实源；索引必须可回指来源对象并携带状态、可信度、确认和敏感信息。
9. 敏感长期记忆可确认后本地保存，但所有外发上下文必须先经过敏感处理钩子。
10. 默认软删除，彻底删除二次确认；删除记忆不删除来源，删除原始记录不删除已确认记忆。
11. 复杂记忆合并后置，v1 不自动合并正式记忆。
12. 决策经验是可确认的长期记忆类型，必须能关联具体决策、行动结果或复盘依据。

## 7. 验收标准

### 7.1 事实与来源

- 用户发送内容后，系统可自动保存带来源的事实；事实可标识用户明确表达、助手抽取或助手推断。
- 任何事实均能查看来源、时间、可信度、状态和敏感标记。
- 用户标记事实错误后，系统保留纠错状态，且不在相同依据上反复提出同一结论。

### 7.2 记忆确认与更新

- 长期记忆只能由用户明确确认的候选创建；默认选中、模型推断或后台任务均不构成确认。
- 确认卡片能展示记忆内容、类型、来源、可信度、表达方式、敏感提示和冲突/相似关系。
- 冲突更新保留旧记忆和来源，新记忆另建；未确认前旧记忆不被静默覆盖。
- 相似记忆在 v1 至多提示关联或产生合并候选，不自动合并和删除。

### 7.3 生命周期、删除与恢复

- 当前有效、过期、有争议、归档、删除等状态在查询和检索中有明确区别。
- 普通建议不使用过期或已删除记忆作为当前依据；历史复盘可使用过期记忆并标明历史状态。
- 删除记忆不会级联删除原始记录、事实、目标、行动或决策；软删除可恢复，彻底删除需要二次确认且不可恢复。

### 7.4 RAG、敏感信息与决策经验

- RAG 上下文能携带来源、时间、状态、可信度、确认和敏感标记，且不暴露内部 ID、路径和数据库字段。
- 待确认内容、低可信度事实和助手推断不会被呈现为已确认事实；它们不能作为重要建议的唯一关键依据。
- 敏感记忆在本地可按确认规则保存，但每次外发均经敏感处理；外发内容不含未脱敏敏感值。
- 决策经验记忆能追溯到至少一条决策记录、行动结果或复盘结论；一次建议或单次结果不会自动成为长期经验。

## 8. 与其他子需求的边界

- **《v1-原始记录与结构化存储》：** 定义原始记录、Fact、Memory、来源关系、索引和事务的基础存储边界；本文件补充事实可信度、记忆生命周期、更新与合并规则。
- **《v1-确认中心》：** 定义候选、批次、命令、幂等、风险和撤销；本文件规定哪些事实/记忆操作必须进入确认以及确认项需要展示的业务信息。
- **《v1-RAG 与处境模型》：** 负责检索分块、召回、排序、上下文格式和处境模型细节；本文件只规定事实与记忆可被怎样使用、哪些状态不得作为当前依据。
- **《v1-目标与决策辅助》：** 负责建议与决策流程；本文件只规定决策记录和决策经验如何成为可追溯的长期信息。
- **《v1-数据导出》：** 负责导出格式和加密；导出至少应保留事实/记忆的内容、来源、状态、时间、确认、可信度和敏感元数据，并遵守敏感导出规则。

## 9. 自问自答后的默认决策汇总

1. 事实是有来源的陈述，长期记忆是经用户确认、可持续用于个人理解的正式对象。
2. 自动抽取的可信度代表可参考程度，不代表系统宣告真相；不得仅因模型重复提及而自动升格。
3. 用户明确表达、助手抽取和助手推断必须分开保存与展示。
4. 事实可自动保存；保存、覆盖、过期、合并或删除长期记忆均不得绕过用户确认。
5. 记忆冲突采用“新候选 + 用户确认 + 旧记忆过期”的版本化方式，不直接覆盖历史。
6. 多来源通过来源关系集合保留支持、补充、冲突或替代信息；补充证据不自动改写已确认记忆正文。
7. v1 不自动合并相似正式记忆，复杂合并后置；仅提示关联或产生待确认候选。
8. 归档、软删除、恢复和彻底删除分开处理；删除不级联删除来源或其他正式对象。
9. RAG 只在场景相关的最小范围内使用事实和记忆；当前有效已确认记忆优先，过期记忆限历史复盘，待确认内容显式降级。
10. 敏感记忆可在本地确认保存，但任何外发上下文必须脱敏、确认或阻止，不得传出未脱敏值。
11. 决策记录保存具体历史，决策经验保存经确认的长期学习；二者关联且都不能代替当前用户意图与现实限制。
