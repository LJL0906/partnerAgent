# v1 技术选型方案

> 状态：已确认的 v1 全栈技术选型基线
>
> 决策日期：2026 年 9 月 4 日
>
> 适用范围：个人助手 v1 的移动客户端、业务后端、Agent Runtime、AI/RAG、数据库、文件存储、后台任务、知识库和部署方式。
>
> 对应架构：[`v1-技术架构总览.md`](./v1-技术架构总览.md)
>
> 对应整合：[`v1-详细子需求交叉整合.md`](./v1-详细子需求交叉整合.md)

## 1. 选型总览

v1 采用以下全栈技术路线：

```text
移动客户端：Expo + React Native + TypeScript + Expo Router + expo-dev-client
业务后端：NestJS + TypeScript
主 Agent Runtime：pi-agent-core
模型适配：pi-ai
AI/RAG 服务：Python + FastAPI
RAG/文档集成：LangChain
复杂 AI 工作流：LangGraph（限定场景使用）
主数据库：PostgreSQL + pgvector
附件与导出文件：私有核心主机本地文件系统
后台任务：PostgreSQL BackgroundJob + NestJS Scheduler / Worker
知识库：Obsidian 单向 Markdown Adapter
部署：Docker Compose 私有核心主机
```

## 2. v1 运行形态

v1 采用：

```text
单用户
+ 用户可控的私有核心主机
+ Expo 移动客户端
+ NestJS 业务核心
+ PostgreSQL 主数据库
+ Python AI/RAG 服务
```

运行关系：

```text
Expo 移动 App
        ↓ HTTPS / 私有网络
NestJS Business Core / Local Core
        ↓
PostgreSQL + pgvector
        ↓
Python FastAPI AI/RAG Service
        ↓
外部模型和其他外部服务
```

部署位置：

```text
用户自有电脑
家用小主机
NAS
用户控制的私有服务器
```

部署方式：

```text
Docker Compose
```

v1 的“本地优先”表示：

```text
核心业务数据优先保存在用户控制的私有核心主机
```

手机和电脑作为客户端访问同一个私有核心主机。v1 不提供多个核心之间的同步和同步冲突处理。

## 3. 移动客户端选型

### 3.1 技术

```text
Expo
React Native
TypeScript
Expo Router
expo-dev-client
```

### 3.2 客户端职责

- 文字输入。
- 语音录音、转写展示和语音发送确认。
- 图片、网页链接和文件选择。
- 聊天界面和 Agent 流式事件展示。
- 结构化分析结果和确认卡片。
- 目标、行动、记忆、建议、摘要、提醒和复盘页面。
- 模型配置和当前模型选择。
- 应用访问保护交互。
- 本地通知展示和点击导航。
- 导出入口。
- 调用 NestJS Command / Query 接口。

### 3.3 客户端边界

客户端不得：

- 直接访问 PostgreSQL。
- 直接访问 pgvector。
- 直接调用 Python AI/RAG 服务。
- 直接调用外部模型或外部解析服务。
- 直接修改正式目标、行动、记忆、决策或状态。
- 自行拼装完整 RAG 上下文。
- 根据模型自然语言判断正式对象是否已经生效。

## 4. 业务后端选型

### 4.1 技术

```text
NestJS
TypeScript
```

NestJS 作为：

```text
业务控制平面
Local Core
API 层
应用编排层
领域服务层
正式业务事务层
```

### 4.2 业务后端职责

NestJS 负责：

```text
API 和访问保护
会话与消息
原始记录和附件元数据
分析运行和结构化结果
候选项与确认批次
目标、行动、事实、长期记忆和决策
状态机和版本控制
来源关系与关键变更记录
RAG 查询编排
上下文组装
外发敏感信息策略
Pi Agent 适配
Python AI 服务调度
后台任务
提醒计划与提醒实例
每日摘要和每周复盘任务
导出任务
Obsidian 适配
```

### 4.3 业务后端写入边界

正式业务对象的创建、更新、状态变更、删除和撤销必须由 NestJS 负责校验和事务写入：

```text
用户确认
→ NestJS 校验
→ PostgreSQL 事务
→ 正式对象生效
```

Python AI 服务、Pi Agent、RAG、提醒和后台任务不得直接写入正式业务对象。

## 5. Agent Runtime 选型

### 5.1 pi-agent-core

```text
主交互 Agent Runtime
```

负责：

- Agent Loop。
- 多轮上下文处理。
- Tool Calling。
- 工具参数校验。
- 工具执行生命周期。
- 流式 Agent 事件。
- 运行取消。
- 工具结果回传。
- 当前 Agent 运行状态。

### 5.2 pi-ai

```text
模型供应商适配层
```

负责：

- Provider / Model 抽象。
- 多供应商模型调用。
- 流式和非流式调用。
- Tool Calling 协议适配。
- Reasoning / Thinking 参数映射。
- 模型能力信息。
- 请求取消。
- 模型响应归一化。

### 5.3 项目自有适配层

NestJS 中保留项目自己的适配接口：

```text
AgentRuntime
ModelGateway
ToolRegistry
AgentEventMapper
ExternalDataEgressPolicy
ConfirmationCoordinator
```

业务模块不得直接依赖 Pi 的内部状态和类型。

### 5.4 Agent 工具分层

#### 只读工具

```text
search_records
get_current_context
get_goal_context
get_action_context
retrieve_evidence
get_suggestion_evidence
```

#### 提议型工具

```text
propose_action
propose_goal_change
propose_memory
propose_decision
propose_reminder_change
```

#### 正式写入

正式业务写入不作为普通 Agent Tool 暴露，统一通过：

```text
SubmitConfirmationBatch
```

### 5.5 Agent 正式边界

Pi Agent 可以：

```text
读取上下文
调用只读工具
提出候选
生成建议
生成摘要和复盘
输出流式事件
```

Pi Agent 不可以：

```text
直接创建 Action
直接修改 Goal
直接保存 Memory
直接写入 Decision
直接删除对象
直接修改提醒计划
直接提交正式业务事务
```

## 6. Python AI / RAG 选型

### 6.1 技术

```text
Python
FastAPI
LangChain
LangGraph
```

### 6.2 Python AI Service 职责

- RAG 检索执行。
- Embedding。
- Rerank。
- 文档解析。
- 图片、网页和文件深度解析任务。
- 结构化输出辅助处理。
- 复杂 AI 任务。
- 长时间、可暂停、可恢复的 AI 工作流。

### 6.3 LangChain 使用边界

LangChain 用于：

```text
Retriever 集成
Embedding 集成
Reranker 集成
文档加载和解析集成
Prompt 辅助
结构化输出辅助
基础 AI Chain
```

LangChain 不负责：

```text
正式业务状态
确认中心
PostgreSQL 正式事务
目标/行动状态机
正式对象删除和撤销
```

### 6.4 LangGraph 使用边界

LangGraph 限定用于复杂 AI 工作流：

```text
多阶段资料研究
长时间运行的 AI 任务
需要暂停和恢复的 AI 任务
v1.1 附件深度解析
复杂周复盘
多节点、多分支、多工具 AI 流程
```

LangGraph 只保存和管理 AI 工作流状态：

```text
Graph State
Checkpoint
Interrupt
```

产品正式状态仍由 NestJS 和 PostgreSQL 管理：

```text
Goal
Action
Memory
Decision
ConfirmationBatch
ReminderPlan
```

## 7. 数据库选型

### 7.1 技术

```text
PostgreSQL
pgvector
```

### 7.2 PostgreSQL 职责

PostgreSQL 是 v1 的主数据库和正式业务权威源，保存：

```text
用户和设备
聊天会话和消息
原始记录
附件元数据
分析运行
结构化分析
候选项
确认批次
用户确认操作
目标
行动
行动结果
事实
长期记忆
决策记录
建议与建议效果
处境快照
提醒计划和提醒实例
后台任务
索引更新任务
导出任务
来源关系
关键变更记录
ModelCallLog
SensitivePolicyLog
```

### 7.3 pgvector 职责

pgvector 保存：

```text
Embedding
向量索引
向量检索所需的派生字段
```

pgvector 属于派生检索层，不是：

```text
正式业务对象的唯一存储
确认中心
业务状态机
来源关系的唯一存储
```

### 7.4 数据权威关系

```text
PostgreSQL 结构化业务数据 = 权威源
原始文件 = 原始证据
全文/向量索引 = 可重建派生数据
```

## 8. 文件存储选型

### 8.1 v1 技术

```text
私有核心主机本地文件系统
```

### 8.2 文件存储职责

保存：

```text
图片
音频
上传文件
原始附件
导出文件
解析临时文件
备份文件
```

PostgreSQL 保存文件元数据：

```text
attachment_id
storage_key
content_hash
content_type
byte_size
source_record_id
parse_status
lifecycle_status
```

### 8.3 文件访问边界

- 文件访问必须经过 NestJS 权限和生命周期校验。
- 物理路径不能暴露给客户端、用户来源展示或外部模型。
- 删除、导出和解析都必须使用稳定附件标识。
- 原始附件和解析结果分层保存。

## 9. 后台任务选型

### 9.1 技术

```text
PostgreSQL BackgroundJob
+ NestJS Scheduler / Worker
+ Python FastAPI AI Task API
```

### 9.2 任务类型

```text
输入分析
附件解析
附件补充分析
重新分析
建议生成
行动结果提取
每日摘要
每周复盘
明确截止时间提醒
过期行动集中提醒
待确认提醒
处境刷新
索引更新和重建
导出
```

### 9.3 任务状态

通用任务状态：

```text
未登记
排队中
执行中
成功
失败
已取消
```

独立记录：

```text
是否可重试
是否等待隐私决定
是否部分成功
重试次数
最近错误
幂等键
结果引用
```

### 9.4 任务边界

```text
任务成功 ≠ 目标完成
任务成功 ≠ 建议被采纳
任务成功 ≠ 记忆已确认
任务成功 ≠ 提醒已处理
```

后台任务不能绕过确认中心产生正式业务副作用。

### 10.1 技术

```text
Obsidian

Obsidian Adapter
```

### 10.2 v1 使用方式

```text
PostgreSQL 正式数据
→ ExportJob
→ Markdown
→ Obsidian Vault
```

```text
稳定业务标识
对象类型
当前状态
创建和更新时间
来源引用
确认状态
归档/删除状态
目标和行动关联

```

### 10.3 导入边界

后续导入遵循：

```text
Obsidian Markdown
→ 外部原始记录
→ 分析
→ 候选

→ 正式对象
```

Obsidian 内容不能直接改写正式目标、行动、记忆或决策。

## 11. 统一安全架构

### 11.1 外发策略

所有离开私有核心主机的数据都经过：

```text
最终载荷组装
→ External Data Egress Policy
→ 脱敏 / 等待隐私决定 / 阻止
→ 外部适配器
```

覆盖：

```text
pi-ai 模型请求
Python AI 服务的外部请求
Embedding
语音识别
OCR
网页解析
第三方工具
```

### 11.2 强制识别类别

```text
身份证件
银行卡
密码
API Key 和其他密钥
```

### 11.3 日志边界

日志拆分为：

```text
AnalysisRun
ModelCallLog
SensitivePolicyLog
AgentRunTrace
BackgroundJob
ChangeHistory
```

不得保存：

```text
API Key
Authorization Header
完整敏感明文
完整外发载荷
完整 RAG 上下文
完整模型原始输出
未审查的 Agent Session 全量内容
```

## 13. 技术选型验收

技术选型进入实现前，需要验证：

1. Expo development build 可以连接 NestJS API。
2. NestJS 可以稳定集成 pi-agent-core 和 pi-ai。
3. Pi Agent 的只读工具和提议型工具可以正常运行。
4. Agent 流式事件可以转换为项目自己的事件协议。
5. Agent 取消不会破坏 AnalysisRun 和 BackgroundJob 状态。
6. PostgreSQL 可以保存确认中心事务、版本和来源关系。
7. pgvector 可以与结构化过滤和全文检索协作。
8. NestJS 可以调用 Python FastAPI AI Service 并接收结构化候选。
9. Python AI 服务无法直接写入正式业务对象。
10. External Data Egress Policy 可以覆盖 Pi、Python 和其他外部服务。
11. 本地文件系统可以支持附件保存、解析、删除和导出。
12. PostgreSQL BackgroundJob 和 NestJS Scheduler 可以支持摘要、提醒、复盘和补偿。
13. Obsidian Markdown 导出可以保留稳定标识、来源和状态。
14. Docker Compose 可以启动并恢复私有核心主机服务。
