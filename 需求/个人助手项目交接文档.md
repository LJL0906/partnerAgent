## 3. 一句话产品目标

> 不重新制造一个通用聊天机器人，而是利用现有大模型，构建一个属于用户自己的个人智能层：持续理解用户的目标、处境、知识、决策和执行结果，并帮助用户做出下一步行动。

## 4. 产品定位和服务对象

- 第一阶段只服务用户本人，用于个人使用验证。
- 未来再考虑产品化，不为多用户和通用人群提前扩大范围。
- 不自行训练基础模型。
- 不重复建设通用聊天、通用搜索、语音识别、OCR 等底层能力；优先使用现成模型、服务和框架。
- 手机和电脑都需要提供基础使用入口，重要性接近。

## 5. 核心价值排序

```text
行动执行
> 决策辅助
> 个人记忆
> 复盘成长
> 知识整理
```

产品不是单纯的知识库。知识、记忆、处境和历史结果都应服务于更好的决策和执行。

## 6. 核心闭环

```text
用户输入文字、语音或附件
→ 保存原始记录
→ 自动理解和结构化提取
→ 识别目标、问题、行动、限制和记忆候选
→ 结合当前处境和历史记录判断优先级
→ 给出细粒度的下一步行动
→ 用户确认后创建或修改正式对象
→ 跟踪执行
→ 生成每日行动摘要、到期提醒和每周目标复盘
→ 根据实际结果更新记忆、决策经验和处境理解
```

统一原则：

```text
模型负责提出候选和建议
→ 用户确认
→ 系统才执行正式写入或状态变更
```

### 7.1 v1.0：核心验证闭环

默认冻结为：

```text
应用访问保护
模型配置和测试连接
文字输入
语音转文字并由用户确认
原始记录
结构化分析
目标候选和行动候选
统一确认中心
目标和行动状态追踪
基础长期记忆
基础 RAG
每日行动摘要
截止时间提醒
数据导出
建议依据展示
```

v1.0 的主要验证目标是：能否让用户持续记录、确认和执行行动，并感受到助手越来越贴近个人处境。

### 7.2 v1.x：已确认但后置的增强

```text
图片、网页链接和文件的深度解析

更完整的处境模型历史分析
复杂记忆合并
更丰富的主动行为
```

v1.0 可以接收并保存图片、网页链接和文件；解析失败不能影响原始附件保存。深度解析默认放到 v1.1。

每周目标复盘是已确认的产品能力；具体生成和交互细节可在架构和子需求拆分阶段确定，核心 v1.0 先保证每日摘要和到期提醒。

### 7.3 v2 或更后续

```text
服务器数据库

同步冲突处理

语音唤醒
视频理解
自动模型路由
多用户和产品化
```

### 7.4 前端界面与 UI 基线

前端界面已形成独立基线文档：[`v1-前端界面功能文档.md`](./v1-前端界面功能文档.md)。后续前端设计、iAgent 视觉稿、组件实现和页面验收都必须以该文档为准，不得根据单张设计稿临时改变产品结构。

已确认的统一规则：

```text
固定导航：助手 / 今日 / 执行 / 记忆 / 我的
全局入口：待确认 + 数量角标
核心闭环：助手输入 → 分析 → 候选 → 确认中心 → 正式行动
统一主题：晨雾青・智能陪伴
统一术语：行动、目标、候选、确认中心、事实、长期记忆、当前处境、来源、建议、分析
```

所有设计稿必须保持：

- 同一套 App Shell、页面边距、圆角、字号、间距和底部导航。
- 同一套状态标签、候选卡片、行动行、来源组件和操作栏。
- 面向用户的功能文案使用统一中文，不擅自混用英文或同义词。
- 正式对象、候选、历史对象、删除对象和异步状态有明确视觉区分。
- 不使用脏灰、灰褐、土黄、棕色、脏绿、荧光色、大面积黑色或过度赛博朋克。
- 设计稿先表达真实功能和页面跳转，再表达装饰性视觉效果。

## 8. 输入与用户交互

### 8.1 入口

打开 App 后直接：

```text
发送文字消息
或
开启语音输入
```

用户不需要先选择“记录、目标、任务、记忆”等类型。

### 8.2 语音

```text
点击语音输入
→ 录音
→ 转换成文字
→ 用户检查和修改
→ 用户确认发送
→ 助手开始分析
```

语音识别文字未经用户确认，不得发送、提取记忆或创建行动。

### 8.3 支持的输入类型

- 文字
- 语音
- 图片
- 网页链接
- 文件上传

附件默认：

```text
先保存原始附件
→ 再异步解析
→ 解析失败不影响保存
→ 解析结果作为原始记录的附属分析
```

### 8.4 结构化提取

需要识别：

```text
内容摘要
事实
问题
目标
可能的行动
截止时间
现实限制
长期记忆候选
需要用户确认的内容
```

一段输入包含多个事项时：

```text
自动拆分多个目标、问题和行动
→ 统一展示
→ 用户可逐项取消或修改
→ 一次确认
→ 分别创建正式对象
```

普通闲聊和一般问题不强制展示结构化卡片；仅当识别出目标、行动或记忆候选时展示。

## 9. 确认中心

结构化结果默认全部选中，用户可以：

- 展开查看
- 逐项取消
- 修改内容
- 一次确认多个不同类型的变更

确认后：

- 正式目标才创建。
- 正式行动才创建。
- 长期记忆才保存。
- 决策记录才保存。
- 行动状态才变更。

未确认内容：

```text
暂存为待确认内容
→ 下次打开 App 时提醒
→ 用户也可进入待确认列表处理
```

待确认内容支持：

```text
确认
修改后确认
拒绝
暂不处理
删除
标记识别错误
```

未确认内容永不自动升级为正式目标、行动或长期记忆。

默认提醒策略：首次打开提醒；用户选择“暂不处理”后当天不重复提醒，后续再按间隔提醒；用户可以关闭单条或全部提醒。

## 10. 核心数据对象

### 10.1 原始记录

每次用户发送的内容都自动形成一条原始记录。文字、语音转写、图片、网页链接和文件属于该记录的内容或附件。

聊天是外层容器：

```text
聊天会话
├── 用户消息 → 独立原始记录
├── 助手回复
└── 结构化分析结果
```

原始记录和结构化分析结果自动保存；正式目标、行动和记忆必须确认后才创建或写入。

### 10.2 事实

事实是从原始记录中提取出的、与用户相关但尚未必然长期有效的陈述。

```text
事实：自动提取并保存，带来源和可信度
长期记忆：经过确认，允许未来持续使用
```

所有长期记忆都应有事实或原始记录作为来源，但不是所有事实都会成为长期记忆。用户明确指出事实识别错误时，应标记为“错误”，避免在相同依据下反复提出。

### 10.3 目标

- 一个目标可以包含多个行动。
- 目标需要独立状态。
- 目标完成不能仅由行动全部完成自动决定，需用户确认或由助手提出确认。

初步目标状态：

```text
规划中
进行中
已完成
已暂停
已放弃
已过期
```

### 10.4 行动

- 行动输出默认细化到可以立即开始的下一步。
- 行动可以独立存在，也可以关联目标。
- 一个行动可以关联多个目标。
- 创建行动和修改行动状态必须用户确认。

初步行动状态：

```text
待确认
待开始
进行中
已完成
已延期
暂时搁置
已取消
```

完成规则：

```text
助手识别可能完成
→ 询问用户
→ 用户确认
→ 标记已完成
```

行动完成结果有则保存、无则留空。每周统一复盘，不在每个行动完成后立即打断用户。

状态含义：

- 延期：仍要做，但截止日期调整。
- 过期：截止日期已到，尚未完成，也尚未决定下一步。
- 暂停 / 搁置：暂时不做，未来可能恢复。
- 放弃 / 取消：明确不再继续。

### 10.5 长期记忆

候选类型包括：

- 个人基本信息
- 长期偏好
- 长期目标
- 现实限制
- 重要经历
- 能力与资源
- 价值观和判断标准
- 决策经验

每条记忆保留：

```text
记忆内容
来源
创建时间
最后确认时间
可信程度
是否由用户明确表达
是否由助手推断
确认状态
当前状态
```

记忆冲突时：

```text
旧记忆标记为过期
→ 保存新的当前记忆
→ 保留旧记忆和来源
```

普通建议只使用当前有效记忆；历史复盘允许读取过期记忆。

### 10.6 决策和复盘

助手识别到重要选择时，可以建议建立决策记录；用户确认后保存。

决策字段有则保存、无则留空：

```text
决策内容
当时目标
可选方案
选择理由
当时限制条件
预期结果
计划验证时间
实际结果
复盘结论
```

### 10.7 个人处境模型

处境模型是由多个正式数据对象聚合生成的当前状态快照，不是新的事实来源。

至少包含：

```text
当前重要目标
进行中的目标
行动及状态
截止时间
已确认现实限制
当前问题
最近重要变化
风险和阻碍
最近重要决策
```

助手自动生成，用户可以查看和修正；影响重要决策的关键字段需要确认。每次输入后检查是否影响处境，有变化才生成新版本。确认后的版本用于日常建议和历史复盘。

## 11. RAG 和建议依据

### 11.1 检索流程

```text
结构化条件筛选
+ RAG 关键词 / 语义检索
+ 模型综合判断
```

结构化数据优先，原始记录作为补充和证据。

默认上下文：

```text
当前目标
+ 当前行动
+ 截止时间
+ 当前有效限制
+ 相关长期记忆
+ 相关历史结果
+ 最近相关记录
```

不默认读取全部历史。

### 11.2 RAG 内容范围

主要检索：

- 原始记录
- 已确认长期记忆
- 目标
- 行动及执行结果
- 决策及复盘结果

待确认内容可以检索，但必须带有“待确认”标记，不能当作已确认事实。过期内容普通建议排除，历史复盘时允许检索。

### 11.3 来源和依据

检索结果携带：

```text
内容
来源类型
来源记录
发生时间
当前状态
可信度
是否用户确认
是否敏感
```

用户默认看到折叠的“本次参考”，展开后查看目标、行动、记忆、历史结果和不确定信息。

不向模型暴露原始记录 ID、数据库主键、内部路径和数据库字段名。

### 11.4 找不到记录

```text
没有找到相关记录
→ 明确告诉用户
→ 推测必须标记为推测
→ 询问用户是否补充或重新建立记录
```

## 12. 行动和决策建议

助手默认：

- 给出一个最推荐行动，并提供 1～2 个备选行动。
- 说明推荐原因，并支持展开查看依据。
- 发现目标冲突时明确指出并给出优先级建议，不自动修改目标。
- 信息不足时先给低风险临时建议，说明缺少的信息。
- 涉及金钱、人员、工作安排、重要文件等外部影响时说明成本和风险。
- 参考过去类似行动的执行结果，避免重复失败模式。
- 用户拒绝建议时询问原因，提供替代行动，并记录本次未采纳情况。
- 不未经确认修改目标、创建行动或保存长期记忆。

建议效果区分：

```text
建议已提出
→ 用户采纳 / 创建行动
→ 用户开始执行
→ 行动完成或中断
→ 记录结果
→ 周复盘判断建议效果
```

评价可以是：有效、部分有效、无效、无法判断。

## 13. 每日摘要、提醒和复盘

### 每日摘要

默认包括：

- 今天需要完成的行动
- 即将到期或已过期行动
- 当前最重要目标
- 今日优先行动建议
- 待确认内容

每天固定时间生成一次；当天没有生成时，用户当天第一次打开 App 补生成。

### 提醒

- 有明确截止时间的行动自动提醒。
- 用户可以手动设置提醒。
- 只有日期没有具体时间的行动进入每日摘要，不自动精确提醒。
- 行动延期后取消旧提醒，按新时间重新提醒。
- 逾期行动每天集中提示一次，不高频催促。

提醒支持：

```text
完成
延期
搁置
查看行动
稍后提醒
关闭本次提醒
```

### 每周复盘

参考所有相关信息：

- 完成和未完成行动
- 延期、过期和搁置情况
- 目标进展
- 未完成原因
- 实际花费时间
- 计划和实际差异
- 建议是否有效
- 是否需要调整目标
- 是否需要更新长期记忆
- 下周最重要行动

复盘提出的调整、记忆更新、决策记录和新行动都必须用户确认。

默认按用户时区、固定星期和时间生成；未生成时下次打开 App 补生成；用户可以跳过本周，跳过后不重复强提醒；没有有效行动或目标变化时生成简短提示即可。

主动行为频率上限：

```text
每天最多 1 份行动摘要
每个明确提醒时间最多提醒 1 次
逾期行动每天最多集中提醒 1 次
每周最多 1 次目标复盘
```

## 14. 模型接入和切换

### 14.1 配置

每个模型配置：

```text
供应商名称
Base URL
API Key
Model ID
```

- 可以配置多个模型。
- API Key 保存在本地加密存储中，后期需要同步到服务器数据库。
- 设置中提供测试连接。
- 模型列表显示供应商名称和 Model ID。
- 模型列表支持手动拖动排序。
- 当前列表顺序决定失败后的重试顺序。

### 14.2 选择

用户可以在发送消息前选择模型和推理思考等级；系统记住上次主动选择的模型。一次消息处理默认使用一个选中的模型，不按任务类型自动路由。

区分：

```text
默认模型：设置中的长期默认值
本次消息模型：发送前选择，只影响当前消息
实际处理模型：最终成功生成答案的模型
```

自动切换成功不改变用户默认模型。

推理等级统一为：

```text
关闭
低
中
高
```

当前消息临时选择的抽象等级在重试时保持一致；模型不支持时不得静默降级。

### 14.3 失败和重试

默认流程：

```text
当前模型失败
→ 同一模型自动重试 1 次
→ 仍失败时按列表顺序尝试其他模型
→ 不循环、不重复尝试已失败模型
→ 全部失败后提示用户
```

自动处理的错误：网络暂时不可用、超时、限流、服务暂时不可用和临时网关错误。

不自动把同一请求切换到其他模型的错误：API Key 无效、权限错误、Model ID 不存在、输入格式不支持、模型能力不支持、上下文超限、内容安全拒绝和用户主动取消。

跨供应商自动切换默认需要用户在设置中明确开启；未开启时不跨供应商自动切换。每条回复显示实际成功的供应商和 Model ID，切换过程默认简洁、可展开查看。

### 14.4 失败结果

```text
原始用户记录：始终保存
模型失败结果：不进入正式结构化数据
部分生成内容：只作为临时内容
只有最终成功且用户确认后，才进入正式目标、行动或记忆
```

## 15. 敏感信息和本地保护

### 15.1 敏感信息范围

第一期识别：

- 身份证件
- 银行卡
- 密码
- API Key 和其他密钥

### 15.2 外发规则

```text
个人助手本地接收原始内容
→ 原始内容可不脱敏保存
→ 组装任何外部模型请求前，通过统一钩子检查完整外发内容
→ 按隐私模式提醒或脱敏
→ 脱敏后继续发送
```

检查范围包括：用户消息、RAG 结果、长期记忆、处境模型、附件解析结果、工具参数和每次模型重试请求。

默认隐私模式是“自动脱敏后发送”；产品设置同时预留：

```text
自动脱敏后发送
发送前查看并确认
检测到敏感信息时禁止发送
```

敏感信息允许在用户确认后写入长期记忆，并单独分组、明显标记，不能因“确认全部”而无提示保存。外部模型永远不能看到未脱敏值。

### 15.3 本地保护

第一期必须支持：

- 应用登录或设备解锁
- 导出文件加密或设置密码

暂未确认本地数据库和原始附件是否额外加密。

## 16. 数据保存和导出

### 保存策略

```text
v1：优先本地保存
后期：服务器数据库和同步
```

本地数据层同时保留：

```text
原始记录 / 文档
+ 结构化数据
+ RAG 检索索引
```

删除原始记录后，已确认的目标、行动和记忆不自动删除；原始来源显示为“已删除”，结构化对象保留必要来源摘要。

### 归档和删除

```text
归档：保留，可在历史中查看，默认不参与日常界面
删除：进入删除状态，不参与日常建议
彻底删除：从本地数据中物理清除
```

默认软删除，彻底删除需要二次确认；删除父对象不自动删除关联对象；最近一次重要操作建议支持撤销。

### 导出

支持：

- Markdown
- JSON
- 原始文件压缩包
- 导出加密或设置密码

不得把 API Key 放入普通导出数据包。完整导出默认包括原始记录、结构化对象、来源关系和附件；聊天展示、待确认内容、过期对象和基础调用记录可以作为可选项。

## 18. 当前默认决策与架构边界

以下产品边界仍然有效：

- 前端功能与视觉规范以 [`v1-前端界面功能文档.md`](./v1-前端界面功能文档.md) 为唯一基线；设计稿不得擅自新增一级导航、改写中文术语或绕过确认中心。

- 附件 v1.0 先接收、保存、关联和导出，深度解析后置到 v1.1。
- 用户确认是正式写入和状态变更的统一门槛。
- 前端页面和设计稿遵循 [`v1-前端界面功能文档.md`](./v1-前端界面功能文档.md) 的统一信息架构、中文术语、组件和“晨雾青・智能陪伴”主题。
- 原始记录、结构化数据和检索索引分层保存。
- 所有外部服务请求经过统一外发敏感信息策略。
- 模型选择透明，自动切换不改变用户默认模型。
- 产品逻辑不能依赖某个固定模型供应商。
- 单用户、不做公开 SaaS、多租户和复杂跨核心同步。

以下全栈技术架构已经确认，并以 `需求/v1-技术架构总览.md` 和 `需求/v1-技术选型方案.md` 为准：

```text
移动端：Expo + React Native + TypeScript + Expo Router + expo-dev-client
业务后端：NestJS + TypeScript
主 Agent Runtime：pi-agent-core
模型适配：pi-ai
AI/RAG 服务：Python + FastAPI
RAG/文档集成：LangChain
复杂 AI 工作流：LangGraph（限定使用）
主数据库：PostgreSQL + pgvector
附件：私有核心主机本地文件系统 + Storage 抽象
后台任务：PostgreSQL BackgroundJob + NestJS Scheduler
知识库：Obsidian 单向 Markdown Adapter
部署：Docker Compose 私有核心主机
```

v1 采用的部署画像是：

```text
Expo 手机客户端
→ 用户自有电脑 / 家用小主机 / 私有服务器
→ NestJS Business Core
→ PostgreSQL + pgvector + 私有文件存储
→ Python AI/RAG 服务
```

这里的“本地优先”表示数据优先保存在用户控制的私有核心主机，不再表示手机和电脑各自维护独立权威副本。v1 不承诺手机离线时完整可用，也不实现多个核心之间的同步和冲突处理。

### Agent 底座边界

```text
Pi Agent Core：主交互 Agent Loop、Tool Calling、流式事件、取消
Pi AI：模型供应商适配
NestJS：业务状态、确认中心、权限、事务、正式写入
PostgreSQL：正式业务权威数据
```

Pi、LangChain 和 LangGraph 都不能直接写入正式 Goal、Action、Memory 或 Decision；正式业务变更必须经过确认中心和 NestJS 事务。

### 外发和安全边界

任何离开私有核心主机的载荷，包括模型、Embedding、语音识别、OCR、网页解析和第三方工具请求，都必须经过：

```text
最终载荷组装
→ External Data Egress Policy
→ 脱敏 / 提醒等待 / 阻止
→ 外部适配器
```

### 仍然不是 v1 的内容

```text
多用户和多租户
公共云 SaaS
多个私有核心之间的同步
同步冲突处理
Obsidian 双向自动同步
Redis/BullMQ 高可用任务集群
Kubernetes 和多区域部署
```
