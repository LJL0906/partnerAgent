## 1. 文档目的与总原则

本文件回答的核心问题是：

```text
用户如何在不丢失原始依据、正式对象、关系、状态与附件的前提下，
导出自己可读、可核验、可为未来迁移准备的数据，
同时避免把凭证、临时内容或派生索引误当成应交付数据？
```

导出不是新的业务数据源，也不是跨设备同步机制。它应忠实表达导出时刻的权威数据快照；原始记录、分析结果、候选项、正式对象和检索索引仍遵循既有分层：

```text
原始内容不可被分析结果替代
分析结果不可被候选项替代
候选项不可被正式对象替代
正式对象不可被检索索引替代
所有可导出的派生数据都必须能够回指来源
```

下文每个问题均按“关键问题 → 推荐答案 → 已确认边界／本轮采用规则／待决策项 → 验收标准”组织。这里的“本轮采用规则”是本子需求为后续实现准备的默认方案；具体加密格式、密码规则、包内目录结构、压缩库和实现技术均不在本文锁定。

## 2. 导出目标、范围与三种交付形式

### 关键问题 1：v1 导出要解决什么问题，Markdown、JSON 和原始文件压缩包分别承担什么角色？

**推荐答案：** 同一次导出可以按用户选择生成一种或多种交付形式；三者互补，不互相冒充。

| 交付形式 | 面向对象 | 应覆盖的内容 | 不应被误认为 |
| --- | --- | --- | --- |
| Markdown | 用户阅读、人工核对、长期留档 | 导出说明、范围、对象摘要或正文、关键状态、稳定标识、来源引用、附件引用和缺失说明 | 可单独恢复全部二进制附件或替代机器可读关系数据 |
| JSON | 未来恢复、迁移、程序核验 | 结构化对象、稳定标识、关系、版本、生命周期状态、关键时间、导出清单和原始文件关联元数据 | 数据库文件、检索索引快照或任何凭证的载体 |
| 原始文件压缩包 | 保留附件、原始音频及其他可访问原始文件 | 原始文件实体及与 JSON 中附件标识相对应的关联信息 | 以文件名、物理路径或压缩包位置替代稳定附件标识 |

**已确认边界：**

- v1 需要支持 Markdown、JSON 和原始文件压缩包；完整导出默认覆盖原始记录、结构化对象、来源关系和附件。
- 原始记录、结构化数据和检索索引同时保留，但索引是可重建派生层，不能作为导出的唯一或权威恢复依据。
- 附件先保存原始内容、再异步解析；解析失败不影响原始附件保存。
- API Key 不得进入普通导出包；基础模型调用日志仅允许按既有最小元数据边界作为可选内容。

**本轮采用规则：**

1. 导出必须写明交付形式、导出时间、范围条件、是否包含历史／待确认／调用记录、是否包含原始文件，以及每类内容的包含、排除或不可用原因。
2. JSON 是保存完整关系语义的主载体；Markdown 必须保留足以人工定位的稳定标识与来源引用，但不要求复刻全部机器字段。
3. 原始文件压缩包必须以附件稳定标识与 JSON 元数据关联；展示名称、媒体类型、大小、内容哈希（如已有）可用于核验，但都不能替代附件标识。
4. 派生检索索引、可重建缓存、供应商协议载荷、数据库内部路径和临时分析中间物不属于普通导出内容。

**待决策项：**

- 是否提供“单一综合包”与“分别下载三种形式”两种交付方式，以及默认勾选组合。
- Markdown 的正文展开粒度、富媒体引用展示方式和大体量数据的分页／分卷交互。
- 是否在 v1 让用户选择导出基础调用日志，及其具体字段和保留周期。

**验收标准：**

- 用户可明确选择 Markdown、JSON、原始文件压缩包中的一种或多种，结果不会把未选择的形式伪装为已生成。
- JSON 能表达同一导出范围内的对象、关系、状态和关键时间；Markdown 能据稳定标识定位其对应对象；原始文件能据附件标识重新关联。
- 缺少原始文件、被排除内容或不可访问内容会在导出说明中明确标示，不以空文件或失效路径冒充成功交付。

### 关键问题 2：默认导出范围如何兼顾数据完整性、日常可读性与用户选择？

**推荐答案：** 提供“完整数据导出”和“按范围导出”两类意图。完整数据导出优先保障用户对本地可访问核心数据的可携带性；按范围导出用于日期、对象类型、状态或会话等明确筛选。两类导出都必须形成不可歧义的范围快照。

**已确认边界：**

- 完整导出默认包括原始记录、结构化对象、来源关系和附件。
- 聊天展示内容、待确认内容、过期对象和基础调用记录可以作为可选项。
- v1 本地优先、每台设备独立运行，不承诺手机与电脑之间实时一致，也不因导出自动建立同步。

**本轮采用规则：**

1. “完整”表示导出时仍可访问的核心用户数据及其必要关系，不表示导出数据库、缓存、索引、模型配置凭证或临时工作文件。
2. 默认完整范围包含：原始记录及其附件、分析结果与来源关系、已正式写入的事实／长期记忆／目标／行动／决策／处境模型等对象，以及这些对象的关键变更与版本关系。
3. 已归档的正式对象属于仍可访问的用户数据：完整导出应保留它们，并明确其归档状态；按范围导出可将归档状态作为筛选条件。
4. 待确认候选、已过期对象、聊天展示消息和基础调用记录默认以可选范围呈现；一旦选中，必须随对象一起导出其确认或生命周期状态，不能把候选写成正式事实。
5. 软删除内容默认不输出原文、附件内容或分析内容；若导出范围需要维持仍存活对象的来源链路，只能输出不含被删除内容的关系状态说明。彻底删除后已物理清除的正文和原始文件绝不重新生成或从索引恢复。
6. 范围筛选导致关系另一端未被完整导出时，导出结果必须标明“范围外”“已删除”“已彻底删除”或“当前不可访问”等状态，不能制造看似完整的断链。

**待决策项：**

- 已过期对象是否在“完整”模式默认包含，还是始终需要显式勾选。
- 软删除后是否保留可单独导出的最小删除摘要，以及其保留周期和用户可见字段。
- 日期范围的时间语义、会话筛选交互和大规模导出时的数量上限。

**验收标准：**

- 完整导出至少覆盖上游已确认的原始记录、结构化对象、来源关系和附件，不把索引当作唯一数据来源。
- 用户选择仅导出某一范围时，包内清晰可见范围条件及每类对象数量；跨范围关系不会静默丢失语义。
- 归档、待确认、过期、软删除和彻底删除状态在导出结果中可区分；彻底删除内容不会重新出现。

## 3. 稳定标识、来源关系与历史版本

### 关键问题 3：导出如何使对象、来源关系和历史版本在不同格式中可核验、可迁移？

**推荐答案：** 以既有业务对象的稳定标识为锚点，不以数据库主键、文件路径、显示标题或导出时序号作为跨格式关系依据。导出新增的任务标识、包标识和文件引用只服务本次交付，不能替代业务对象身份。

**已确认边界：**

- 正式对象必须具备稳定标识、创建时间、更新时间、当前状态和来源关系。
- v1 不采用完整事件溯源，但保留关键变更历史、版本关系、来源关系、软删除状态和必要操作历史。
- 新分析结果不能静默覆盖已确认正式对象；候选、正式对象和确认操作均有版本／幂等边界。

**本轮采用规则：**

1. JSON 对每个导出对象至少保留对象类型、稳定标识、对象版本或版本关系、创建／更新时间、生命周期状态、导出时可访问性和来源关系；字段命名及具体结构留待实现设计。
2. 来源关系须能表达“由原始记录产生”“由分析结果提出”“由候选经确认写入”“关联附件”“被后续版本替代”等业务语义，并指向两端稳定标识或明确的不可访问状态。
3. 正式对象的历史版本与关键变更关系应随完整导出保留，且区分当前、历史、已过期、已作废、归档和删除等状态；不得以当前版本覆盖旧版本后再把旧版本导出为当前事实。
4. 重新分析产生的多个分析结果、同一附件的多个解析尝试、被取消后未来再次提出的候选，均保留各自标识和关系；只有当前解析状态可以作为当前展示结论，不能抹去历史关系。
5. Markdown 应把来源展示为可读引用，并附稳定标识；JSON 必须保留可机器处理的关系，不依赖 Markdown 文本反向解析。

**待决策项：**

- 各对象版本号、变更记录和关系记录的精确字段、兼容策略与保留周期。
- 是否允许按用户选择隐藏历史正文但保留版本关系摘要。
- 当源对象被彻底删除时，最小关系说明是否保留、保留哪些非内容字段。

**验收标准：**

- 同一对象在 Markdown、JSON 和原始文件包中的引用可通过稳定标识相互核对，不依赖本地路径或显示名称。
- 当前版本、历史版本、归档和删除状态不会相互混淆；未导出或不可访问的来源不会被伪造为有效来源。
- 使用 JSON 可还原对象间的来源与版本拓扑，不需要读取检索索引或模型调用原始载荷。

### 关键问题 4：原始记录、附件、解析结果、分析结果和候选如何一起导出而不混淆层级？

**推荐答案：** 按既有分层完整表达：原始记录是长期追溯核心，附件从属于原始记录，解析结果和分析结果是派生层，候选项是待确认层，正式对象是确认后的业务层。任何一层都不得冒充另一层。

**已确认边界：**

- 每次用户确认发送的内容形成原始记录；确认前语音转写、音频临时文件和临时文本不进入正式原始记录与长期索引。
- 一条原始记录可关联多个附件和多次分析运行；附件解析失败不删除原始附件。
- 分析结果内部可有多个独立候选；未确认候选不得当作已确认事实或正式对象使用。

**本轮采用规则：**

1. 原始记录导出其确认后正文、稳定标识、时间、生命周期状态及附件关系；语音原始音频仅在本地实际保留且被选中导出时进入原始文件压缩包。
2. 附件导出元数据、所属原始记录、解析状态、原始文件可用性和解析结果关系；原始文件本体只进入原始文件压缩包，不把物理路径写入用户数据或关系依据。
3. 解析结果与分析结果均标注其来源对象、运行／结果状态、版本和当前性；失败或部分成功只导出必要状态和经既有规则处理的错误摘要，不以失败结果覆盖原始内容。
4. 候选项只有在用户显式选择“包含待确认内容”时才输出；其确认状态必须原样表达为待确认、已确认、已修改后确认、已取消或已过期，且和相应确认批次、分析结果、正式对象关系保持可追溯。
5. 用户修改后确认的正式对象必须以用户确认后的内容为准，同时保留其来自原始记录、分析结果和确认批次的关系；不把错误的模型中间版本写成正式对象正文。

**待决策项：**

- 原始音频在 v1 的长期保留策略，以及图片、网页链接、文件的格式、大小和权限限制。
- 是否将解析失败的详细诊断作为可选技术记录导出，以及其脱敏与长度限制。
- 待确认候选导出时的默认勾选、再次导入后的可处理语义和过期策略。

**验收标准：**

- 一个原始记录关联多个附件和多次分析运行时，导出后仍可辨识全部关系与当前状态。
- 附件解析失败时，原始附件仍可按附件标识找到；导出不会用空解析结果替代原始附件。
- 未确认、取消或过期候选不会在任何交付形式中被标示为已创建的目标、行动或长期记忆。

## 4. 敏感内容、凭证与导出预览

### 关键问题 5：本地可保存的敏感内容如何进入导出，API Key 又如何被排除？

**推荐答案：** 导出是用户对自己的本地数据的交付，不等同于外发模型请求；敏感业务内容可在用户明确范围内导出，但必须可见风险、可选择保护方式。API Key、Authorization Header、访问令牌、私钥及其他用于认证或取得权限的凭证属于绝对排除项，不因“完整导出”或加密／密码保护而进入普通导出包。

**已确认边界：**

- v1 必须识别身份证件、银行卡、密码、API Key 和其他密钥等敏感类别的外发风险。
- 本地完整内容可按既有规则保存；对外模型发送前必须经过统一敏感信息处理。该规则不把本地导出误变为模型外发。
- 基础调用日志不保存完整上下文、完整 RAG 结果、完整模型原始回复、API Key 或凭证头。
- 导出需要支持加密或设置密码，API Key 不得进入普通导出包。

**本轮采用规则：**

1. 导出预览必须显示选中范围是否含有敏感标记内容、敏感内容所在对象类别的数量或风险提示，以及基础调用日志是否被选择；预览默认不为了提示风险而展开敏感明文。
2. 业务数据中的敏感正文、附件或已确认敏感记忆，不因其敏感标记自动被静默改写、脱敏或遗漏；用户在本地明确选择范围并确认风险后，导出应忠实保留其所选的可访问数据。是否纳入导出由用户范围选择和保护选项决定。
3. API Key、认证头、访问令牌、私钥和同类凭证无论存放在模型配置、安全存储、日志、缓存还是任务记录中，均不得写入 Markdown、JSON、原始文件压缩包、预览、错误提示或临时可交付文件。
4. 如包含基础调用日志，只能输出已确认允许的最小元数据和脱敏错误摘要；不得输出完整模型上下文、完整 RAG 结果、完整供应商回复、内部路径、数据库字段名或不必要敏感原文。
5. 敏感外发确认与本地导出确认是不同问题：导出操作不能替代外发策略，也不能授予对外部模型的任何放行权限。

**待决策项：**

- 敏感内容的默认选中策略、风险提示文案、是否需要额外二次确认，以及本地访问保护失效时的行为。
- 敏感命中、脱敏策略记录和基础调用日志的具体导出字段与保留周期。
- 数据库、原始附件和敏感长期记忆的额外静态加密及密钥管理方式。

**验收标准：**

- 用户在导出预览中能得知所选范围包含敏感内容及其风险，而预览本身不会无必要泄露敏感明文。
- 任意选择组合、成功包、失败记录和临时文件中均不能检出 API Key、认证头、访问令牌、私钥或同类凭证。
- 选择基础调用日志时，结果只含允许的基础元数据和经过处理的错误摘要，不含完整模型载荷或完整 RAG 上下文。

### 关键问题 6：导出预览需要确认什么，何时才允许开始生成？

**推荐答案：** 先生成本地预览和范围快照，再由用户明确发起导出。预览用于发现漏选、范围过大、敏感风险、附件缺失和保护选项不符合预期，不承担业务对象变更功能。

**已确认边界：**

- 用户确认是正式业务变更的统一门槛；导出不创建、修改或确认目标、行动、记忆等正式对象。
- 删除和彻底删除需要遵循既有生命周期与确认边界；导出不能恢复被彻底删除内容。

**本轮采用规则：**

1. 预览至少展示：交付形式、范围条件、各类对象数量、附件数量与不可访问数量、是否含归档／历史／待确认／过期／软删除关系说明、是否含敏感标记内容、是否含调用记录、以及加密或密码保护是否启用。
2. 用户确认开始导出时，系统保存本次请求的范围快照；后续源数据变化不应悄然改变同一任务的导出内容。
3. 预览中对“完整”“范围外”“已删除”“彻底删除后不可用”“附件不存在”“解析失败”等状态使用不同表述，避免让用户把关系存在误解为内容仍可导出。
4. 预览确认只确认导出范围与交付方式；它不改变候选状态、不执行删除、不更改归档状态，也不构成隐私外发确认。

**待决策项：**

- 预览中是否展示预计大小、生成耗时、文件数或其他成本提示。
- 导出前敏感内容的二次确认交互、默认保护选项和取消后的保留策略。
- 大规模导出时预览的异步加载、分页和无障碍交互细节。

**验收标准：**

- 用户可在开始前核对范围、状态、附件可用性、敏感风险和保护选项；取消预览不会创建交付文件或修改业务数据。
- 导出完成的内容与已确认范围快照一致；任务开始后新增、删除或更新的数据不会混入同一快照。
- 预览和导出任务均不改变候选、确认批次、正式对象、删除或归档状态。

## 5. 导出任务、幂等与失败恢复

### 关键问题 7：如何保证重复点击、客户端超时或任务恢复时不会生成语义混乱的导出？

**推荐答案：** 将导出视为本地持久化任务，而非一次不可追踪的文件写入。一次用户已确认的导出请求应拥有稳定操作标识、范围快照和任务状态；对同一操作的查询或重试必须幂等。

**已确认边界：**

- Local Core 是本地业务权威边界；后台任务需要持久化、支持幂等并在应用重新打开后补偿执行。
- 确认中心已确立“同一操作标识重试必须幂等”“同一标识但不同内容应拒绝”“版本冲突不得静默覆盖”的原则。
- 索引更新失败不回滚已经成功的正式对象；同理，导出不应把派生索引失败误判为权威数据丢失。

**本轮采用规则：**

1. 每次经预览确认的导出请求建立任务标识、范围快照、保护选项快照、目标交付形式和状态；同一任务重试复用同一快照，不能重新读取“最新全部数据”。
2. 同一操作标识且请求内容相同：返回已有进度、已生成结果或继续恢复，不重复生成互相矛盾的多个结果；同一标识但范围或保护选项不同：拒绝复用，并要求建立新任务。
3. 导出任务只读取权威数据与可访问原始文件，不写回或改变原始记录、分析结果、候选、正式对象、关系、版本、归档和删除状态。
4. 成功状态只在全部被选交付物达到可交付且导出清单可核验后写入；允许部分交付的具体产品策略必须在任务结果中明确标示，不能把部分文件当完整成功。
5. 应用中断、客户端断连或重启后，任务可按持久化状态恢复查询、继续、重试或安全终止；恢复不能绕过原范围快照和凭证排除规则。

**待决策项：**

- 导出任务的精确状态集合、并发数量、超时、重试次数、重试退避、结果保留时长及取消入口。
- 同一范围多次独立导出的命名、覆盖与历史交付保留策略。
- 原始文件缺失时是允许“带缺失清单的部分成功”还是要求整个任务失败。

**验收标准：**

- 用户重复提交同一已确认导出，或客户端超时后使用原操作重新查询／重试，不会产生不同范围或重复语义的导出结果。
- 同一操作标识携带不同范围或保护选项时被明确拒绝，不静默覆盖前一任务。
- 任务恢复后仍使用原快照；任何失败或取消均不会影响原始业务数据。

---

### 关键问题 8：生成失败、取消、附件缺失和临时文件如何处理？

**推荐答案：** 以“最终交付物可验证、临时材料不可误交付、失败原因可追踪”为原则。生成中的中间文件不是导出结果，不能被预览页、导入流程或用户误当作完整包使用。

**已确认边界：**

- 原始记录保存、附件保存、解析任务和索引任务的失败边界彼此独立；附件解析失败不删除原始附件，模型失败不删除原始记录。
- 日志错误摘要应经脱敏和长度限制，且不暴露 API Key、内部路径、数据库字段名或不必要敏感原文。

**本轮采用规则：**

1. 临时文件、分段结果、未完成压缩包和中断时产生的中间材料均标记为不可交付，不在普通导出列表展示，也不得成为可导入来源。
2. 临时材料的访问保护不得弱于最终导出所选择的保护等级；完成、取消或最终失败后应清理或使其不可访问，同时保留不含敏感明文的最小任务状态与错误摘要。
3. 若附件、正文或历史来源在快照读取时不可访问，任务应记录对象稳定标识、不可用类别和原因；不得以占位的伪内容替代，也不得从 RAG、索引或缓存回填已删除内容。
4. 失败后的重试以同一范围快照和任务语义继续；用户若希望纳入之后修复、恢复或新增加的数据，应建立新的导出请求并重新预览。
5. 用户取消任务时，已完成但尚未可验证的交付物不得被标记成功；取消不会反向删除任何源对象或改变其状态。

**待决策项：**

- 临时材料的保留时长、清理触发时机和异常退出后的清理补偿方式。
- 附件缺失、空间不足、保护设置失败、目标不可写、校验失败等错误的用户提示与可重试分类。
- 是否支持在失败后下载只含清单和错误说明的诊断包。

**验收标准：**

- 导出中断或取消后，用户看不到被标记为成功的残缺包；临时文件不会作为正式交付物或导入来源。
- 原始附件缺失、解析失败或正文被删除时，导出能说明对应稳定标识与状态，而不伪造内容或恢复已彻底删除数据。
- 失败记录不含 API Key、凭证、内部路径或不必要敏感原文；重试不改变已冻结的范围。

## 6. 加密或密码保护

### 关键问题 9：导出包如何支持加密或密码保护，同时不提前锁死具体安全技术？

**推荐答案：** v1 提供由用户明确选择的加密或密码保护能力，并在预览与结果中清楚说明保护是否启用及其适用交付物；安全能力定义为产品要求，不把任何具体格式、算法、密码长度、密码复杂度、密钥派生方式、包内目录结构或压缩实现写入本需求。

**已确认边界：**

- 导出需要支持加密或设置密码。
- 本地数据库和原始附件是否采用额外静态加密，以及导出文件的具体加密格式和密码规则，均尚未确认。
- API Key 不得因启用加密或密码保护而被允许进入普通导出包。

**本轮采用规则：**

1. 导出预览与最终结果必须明确每个交付物是否受所选保护覆盖；不得出现“界面显示已保护、实际某个附属文件未受保护”的静默降级。
2. 用户设置的密码、恢复材料或任何等价秘密不得写入导出内容、任务日志、错误摘要、Markdown、JSON、原始文件压缩包或普通配置导出。
3. 保护设置失败、用户取消设置或系统无法确认保护覆盖范围时，不得把原本要求受保护的内容以未保护形式标记为成功交付。
4. 加密或密码保护解决的是导出文件离开应用后的访问保护，不改变敏感内容是否被选入范围的事实，也不改变 API Key 等凭证的绝对排除边界。

**待决策项：**

- 加密格式、密码规则、密钥管理、遗忘密码后的恢复能力、保护适用范围和兼容策略。
- 是否允许未设置保护的导出、何时强制风险提示或二次确认，以及对含敏感内容的默认策略。
- 多文件交付时保护信息如何呈现、是否需要单独校验每个交付物的保护状态。

**验收标准：**

- 用户能在开始前和完成后确认每个交付物是否处于所选保护之下。
- 密码、密钥及等价秘密不会出现在任何普通导出、日志、错误消息或预览中。
- 保护配置无法完成时，系统不会将需保护的导出伪报为成功，也不会因保护选择而放行 API Key 等凭证。

## 7. 导入与迁移边界

### 关键问题 10：导出是否等于 v1 已承诺的导入、恢复、跨设备同步或服务器迁移？

**推荐答案：** 不等于。v1 的导出首先保障数据可读、可核验并为未来迁移保留足够语义；完整导入、跨设备同步、服务器数据库迁移和冲突合并不因本文件自动纳入 v1.0 交付范围。

**已确认边界：**

- v1 每台设备独立运行一套本地核心，不做云端后端和跨设备同步。
- 业务逻辑与存储方式分离，后续可以增加服务器和同步能力。
- JSON 应保留稳定标识、关系、来源、状态和关键时间；原始附件应通过标识和元数据重新关联，为导出和未来服务器化保留空间。

**本轮采用规则：**

1. JSON 与原始文件压缩包是未来导入／迁移的候选输入，不是当前 v1 自动执行导入的承诺；Markdown 仅用于阅读和人工核对，不能作为恢复关系的唯一依据。
2. 后续任何导入或迁移都必须先验证导出清单、数据版本、关系完整性、附件关联和保护状态，再预览拟写入范围；不得把导入直接当作“覆盖本地全部数据”。
3. 导入必须尊重导出中的稳定标识、来源、版本、删除和归档状态：能保留时保留，发生冲突时显式报告；不得静默把旧版本升级为当前版本、把待确认候选转正式对象，或把删除内容重新激活。
4. 无法保持原稳定标识的未来迁移，必须保存可追溯的旧标识映射与关系映射；映射规则、冲突解决与多设备合并另行定义。
5. 导出不包含模型配置凭证、缓存或索引，因此未来导入后需要按本地规则重新配置模型、重建索引或重新执行可重建派生工作，不能据此推断数据不完整。

**待决策项：**

- v1 是否提供同设备恢复入口，以及恢复与未来正式导入之间的产品边界。
- JSON 的模式版本、兼容窗口、校验方式、冲突预览和错误修复交互。
- 跨设备、服务器迁移、标识冲突、附件去重、部分导入和撤销导入的完整规则。

**验收标准：**

- 文档、预览和结果不会把导出描述为已实现跨设备同步或自动恢复。
- JSON 和原始文件关联包含未来迁移所需的稳定标识、关系、状态和关键时间，不依赖本地数据库路径或检索索引。
- 后续导入设计若采用本导出数据，必须能识别版本不兼容、附件缺失、关系断裂和对象冲突，并阻止静默覆盖。

## 8. 本轮边界汇总

### 已确认边界

- v1 支持 Markdown、JSON、原始文件压缩包，以及导出加密或密码保护。
- 完整导出默认覆盖原始记录、结构化对象、来源关系和附件；聊天展示、待确认内容、过期对象和基础调用记录可选。
- JSON 需要保留稳定标识、关系、来源、状态和关键时间；原始附件可通过标识与元数据重新关联。
- 原始记录、分析结果、候选项、正式对象和索引分层；索引可重建，不取代权威数据。
- 默认软删除，彻底删除需二次确认；删除原始记录不自动删除已确认正式对象，已彻底删除内容不得被导出或恢复。
- 附件先保存再解析，解析失败不影响原始附件保存；候选和正式对象不得混淆。
- API Key 不得进入普通导出包；基础调用日志不保存完整上下文、完整 RAG 结果、完整模型原始回复或凭证。
- v1 本地优先，不承诺跨设备同步；导出为未来迁移保留数据语义，但不自动承诺完整导入。

### 本轮采用规则

- 以稳定业务标识、来源关系、版本关系和生命周期状态组织可核验快照。
- 完整导出包含可访问核心数据和必要历史关系；归档对象保留状态，待确认／过期／日志按可选范围处理；删除内容不伪造、不恢复。
- 先预览范围、风险、附件可用性和保护选项，再冻结任务快照；导出只读，不改变业务状态。
- 导出任务持久化并按操作标识幂等；同一标识不同请求被拒绝；失败、取消和临时材料不得生成伪成功交付。
- 保护能力必须覆盖用户已选交付物，密码或等价秘密不得进入任何普通导出或日志；API Key 始终排除。
- 未来导入必须显式校验、预览和处理冲突，不能静默覆盖或把候选转为正式对象。

### 待决策项

- 导出交付形式的默认组合、包内目录结构、文件命名、分卷与大体量交互。
- 已过期和软删除内容的默认范围、最小删除摘要及保留周期。
- 调用日志、解析失败诊断、敏感内容预览与二次确认的具体字段和交互。
- 导出任务状态、重试、并发、临时文件清理、部分成功和结果保留策略。
- 加密格式、密码规则、密钥管理、未保护导出策略和兼容方式。
- JSON 模式版本、同设备恢复、正式导入、服务器迁移、跨设备同步与冲突合并规则。
- 具体数据库、文件存储、压缩库、实现语言和客户端／本地核心接口细节。

## 9. 总体验收标准

后续实现本子需求时，至少应满足：

1. **格式与完整性：** 可生成用户所选的 Markdown、JSON 和原始文件压缩包；三种形式通过稳定标识和导出清单保持一致，JSON 不依赖索引或本地路径才能表达关系。
2. **范围与状态：** 完整导出包含原始记录、结构化对象、来源关系和附件；归档、历史、待确认、过期、软删除、彻底删除和不可访问状态均有不混淆的表达。
3. **关系与版本：** 原始记录、附件、解析结果、分析结果、候选、确认批次和正式对象可沿来源关系追溯；当前与历史版本不会相互覆盖或误标。
4. **附件与失败：** 原始附件可按附件标识重新关联；解析失败、附件缺失或原文不可访问有明确说明，不会丢失仍存在的原始文件，也不会伪造或恢复已删除内容。
5. **敏感与凭证：** 预览呈现敏感风险但不无必要暴露明文；API Key、认证头、访问令牌、私钥和其他凭证在任何导出、预览、日志、错误摘要和临时文件中均被排除。
6. **预览与只读性：** 用户在生成前能确认范围、数量、状态、附件可用性、可选日志和保护选项；导出或取消不会修改任何候选、确认、正式对象、删除或归档状态。
7. **任务可靠性：** 同一操作的重试幂等、同一标识不同内容拒绝、快照不漂移；中断、失败、取消和临时文件不会形成伪成功或可误导导入的残缺交付物。
8. **保护与边界：** 支持加密或密码保护并明确覆盖范围；不锁定具体格式或规则；保护失败不静默降级。
9. **迁移准备：** 导出不会被宣传为跨设备同步或完整导入已实现，但 JSON 与原始文件关系为未来显式校验、预览和冲突处理的迁移设计保留基础。
