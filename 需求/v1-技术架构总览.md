# v1 技术架构总览

> 状态：已获产品侧确认，作为 v1 技术架构基线
>
> 基线日期：2026 年 9 月 3 日
>
> 适用范围：个人助手 v1.0 核心闭环

## 1. 文档目的

本文档将已经确认的产品约束转换为 v1 技术架构边界，明确：

- v1 的运行形态；
- 客户端与本地核心服务的职责边界；
- 数据分层与数据流向；
- 模型调用链路和失败重试边界；
- RAG 检索、索引和依据展示链路；
- 敏感信息拦截位置；
- 后台任务、提醒和补偿执行机制；
- 后续详细子需求需要继续决策的内容。

本文档不定义具体编程语言、数据库产品、模型接入框架或文件格式；这些内容属于后续技术选型和详细子需求阶段。

## 2. 已确认的 v1 技术约束

以下内容已经采纳，后续实现不得违反：

### 2.1 产品和数据边界

- v1 只服务单个用户本人。
- 手机和电脑都提供基础使用入口。
- v1 优先本地保存。
- v1 不实现服务器数据库、多设备同步和同步冲突处理。
- 每台设备可以独立运行一套本地数据；不承诺手机和电脑之间实时一致。
- 原始记录、结构化数据和检索索引同时保留，三者不互相替代。
- 每次用户发送的内容自动形成一条原始记录。
- 正式目标、行动和长期记忆只能在用户确认后创建或写入。
- 未确认候选保存为待确认内容，不得当作已确认事实或正式对象使用。
- 默认软删除；彻底删除需要二次确认。
- 删除原始记录不自动删除已经确认的目标、行动和长期记忆。
- 旧记忆不直接覆盖，冲突时保留历史并标记为过期或不再适用。

### 2.2 输入和附件

- 支持文字、语音、图片、网页链接和文件上传。
- 语音转写必须先展示给用户检查和确认，确认前不得发送、分析、提取记忆或创建行动。
- 附件先保存原始内容，再异步解析。
- 附件解析失败不能影响原始附件保存。
- v1 重点保证附件接收、保存、关联和导出；深度解析属于 v1.1 优先增强。

### 2.3 模型

- 使用现成的模型接入框架，不自行实现完整供应商体系。
- 模型通过供应商名称、Base URL、API Key 和 Model ID 配置。
- 支持多个模型，用户手动选择当前模型。
- 单次消息默认使用发送时选中的模型，不按任务类型自动路由。
- 当前模型失败后，按模型列表当前顺序尝试其他模型。
- 当前消息选择的推理思考等级在所有重试模型中保持一致。
- API Key 保存在本地安全存储中。
- 只保留基础模型调用记录，不保存完整模型输入上下文和原始输出作为详细调用日志。

### 2.4 RAG 和建议

- RAG 采用结构化条件筛选加关键词或语义检索，再由模型综合判断。
- 结构化数据优先，原始记录作为补充和证据。
- 普通建议默认使用当前有效记忆；历史复盘允许读取过期记忆。
- 待确认内容可以参与检索，但必须带有待确认状态，不能作为已确认事实直接使用。
- 检索结果携带来源类型、来源记录、发生时间、当前状态、可信度、确认状态和敏感标记。
- 建议依据默认折叠展示，用户可以展开查看本次参考内容。
- 找不到相关记录时必须明确告知用户；如需推测，必须标记为推测。

### 2.5 敏感信息和本地保护

- 本地完整保存与对外模型发送严格分离。
- 所有外部模型请求，包括普通请求、RAG 请求、后台任务请求和重试请求，都必须在发出前经过敏感信息处理钩子。
- v1 强制识别的敏感类别为身份证件、银行卡、密码和密钥。
- 敏感信息按设置执行提醒或脱敏；脱敏后继续发送。
- 敏感信息经用户确认后可以保存到本地长期记忆。
- 打开助手前需要应用访问保护。
- 数据导出需要支持加密或设置密码。

### 2.6 主动行为

- 每天最多生成一份行动摘要。
- 每个明确提醒时间最多提醒一次。
- 逾期行动每天最多集中提醒一次。
- 每周最多生成一次目标复盘。
- 用户可以关闭本次、稍后处理、暂时不再提醒或调整提醒设置。

## 3. 总体运行形态

v1 采用：

```text
本地优先
+ 单用户
+ 模块化单体
+ 客户端与本地核心服务分层
+ 外部模型统一经本地模型网关访问
```

总体关系：

```text
┌──────────────────────────────────────────────┐
│                  用户                         │
└─────────────────────┬────────────────────────┘
                      │
┌─────────────────────▼────────────────────────┐
│            手机客户端 / 电脑客户端             │
│  输入、展示、确认、列表、设置、平台能力适配     │
└─────────────────────┬────────────────────────┘
                      │ 本地核心接口
┌─────────────────────▼────────────────────────┐
│              Local Core 本地核心               │
│  业务编排、事务写入、状态校验、任务、导出       │
│  模型网关、敏感信息钩子、RAG、数据访问          │
└──────────┬──────────┬──────────┬──────────────┘
           │          │          │
┌──────────▼───┐ ┌────▼─────┐ ┌──▼─────────────┐
│ 本地结构化库  │ │ 原始文件 │ │ 检索索引         │
│ 业务权威数据  │ │ 附件/原文 │ │ 召回/来源指针     │
└──────────────┘ └──────────┘ └────────────────┘
                                  │
                         ┌────────▼────────┐
                         │ 外部模型供应商   │
                         │ 仅接收最小必要、   │
                         │ 已处理的请求      │
                         └─────────────────┘
```

## 4. 客户端与本地核心服务边界

### 4.1 客户端职责

客户端负责：

- 文字输入和消息展示。
- 录音、语音转写结果展示、编辑和确认。
- 图片、网页链接和文件选择。
- 结构化分析、候选项和确认卡片展示。
- 候选项逐项取消、修改和统一确认。
- 目标、行动、记忆、待确认内容和建议依据展示。
- 模型选择、推理等级选择和连接测试界面。
- 模型失败、重试顺序和最终结果展示。
- 应用访问保护交互。
- 系统通知注册、展示和点击后的页面跳转。
- 平台差异适配，例如文件选择器、录音、本地通知和安全存储。

客户端不负责：

- 直接调用外部模型。
- 直接读写业务数据库。
- 自行判断是否可以创建行动或保存记忆。
- 自行执行目标、行动和记忆状态变更。
- 自行拼装完整 RAG 上下文。
- 绕过本地核心的敏感信息处理。

### 4.2 Local Core 职责

本地核心服务负责：

- 原始记录、聊天会话和附件的持久化。
- 分析任务编排和结构化结果保存。
- 候选项和待确认内容管理。
- 确认后的目标、行动、长期记忆、事实和决策写入。
- 目标和行动状态转移校验。
- 当前处境模型生成、版本保存和来源关联。
- 结构化筛选、关键词或语义检索和依据组装。
- 模型配置读取、请求构造、重试和结果校验。
- 敏感信息识别、提醒、脱敏和外发控制。
- 每日摘要、到期提醒、逾期汇总和每周复盘任务。
- 删除、归档、软删除、来源保留和撤销能力。
- Markdown、JSON 和原始文件压缩包导出。
- 基础模型调用日志。

### 4.3 接口原则

客户端通过命令和查询与本地核心交互：

```text
客户端命令
→ 本地核心校验用户意图
→ 本地核心执行事务
→ 更新结构化数据和检索索引
→ 返回正式结果
```

命令表达用户意图，不等于客户端直接修改数据。所有正式写入和状态变更必须在本地核心完成。

手机和电脑可以采用不同的进程模型，但共享同一套业务边界和业务规则：

```text
电脑端：客户端 + 本地核心服务进程
手机端：客户端 + 嵌入式本地核心运行时
```

这两种运行方式是建议的部署形态，不改变 Local Core 的逻辑职责。

## 5. 数据分层

### 5.1 原始数据层

保存用户真实输入和原始附件：

```text
文字
语音转写文本
原始音频
图片
网页链接
上传文件
```

原始数据是追溯、重新分析、导出和证据补充的基础。原始数据不能被结构化分析结果替代。

### 5.2 分析和候选层

每次输入形成一份分析结果，其中可以包含多个独立候选项：

```text
摘要
事实
问题
目标候选
行动候选
截止时间候选
现实限制候选
长期记忆候选
待确认内容
```

候选项独立保存确认状态。候选项不得直接当作正式目标、行动或长期记忆参与正式业务流程。

### 5.3 正式业务对象层

保存经过确认的权威对象：

```text
目标
行动
长期记忆
事实
决策
处境模型版本
建议及建议效果
提醒
```

正式业务对象用于查询、状态追踪、摘要、复盘和正式建议。

### 5.4 检索索引层

索引只负责召回和查询加速，不是业务事实的唯一来源。每条索引结果必须能回指正式对象、分析结果或原始记录，并携带：

```text
来源类型
来源对象
来源记录
发生时间
当前状态
可信度
是否用户确认
是否敏感
是否已删除
```

## 6. 主要数据流

### 6.1 文字输入流

```text
用户输入文字
→ 客户端提交
→ Local Core 立即保存原始记录
→ 创建分析任务
→ 读取当前目标、行动、记忆和相关历史
→ 结构化筛选和 RAG 召回
→ 组装最小必要上下文
→ 敏感信息处理
→ 调用当前模型
→ 必要时按顺序重试其他模型
→ 校验模型结果
→ 保存分析结果和候选项
→ 更新原始记录索引
→ 返回助手回复和确认卡片
```

### 6.2 语音输入流

```text
点击录音
→ 获取音频
→ 使用现成语音转文字能力
→ 客户端展示转写文本
→ 用户修改或确认
→ 用户确认后才提交为可分析消息
→ 保存原始记录
→ 开始结构化分析
```

确认前不得：

- 调用内容分析模型；
- 提取长期记忆；
- 创建或修改行动；
- 写入正式业务对象；
- 将未确认转写当作正式原始记录发送给模型。

### 6.3 附件输入流

```text
用户选择附件
→ Local Core 立即保存原始附件
→ 建立附件与原始记录关联
→ 创建异步解析任务
→ 解析成功：挂载分析结果
→ 解析失败：保留附件并记录失败状态
```

附件解析与原始附件保存必须解耦。

### 6.4 统一确认流

```text
模型提出候选
→ 用户展开查看
→ 用户逐项修改、取消或保留
→ 用户统一确认
→ Local Core 校验确认内容
→ 开启事务
→ 创建或更新正式对象
→ 写入来源关系
→ 更新检索索引
→ 返回操作结果
```

涉及敏感记忆、截止时间重大修改、删除、彻底删除以及可能影响金钱、人员、工作安排或重要文件的行动时，确认界面必须显式展示影响。

## 7. 模型调用架构

所有模型调用统一经过模型网关：

```text
业务任务
→ 分析编排器
→ 上下文组装器
→ RAG 检索器
→ 外部请求构造器
→ 敏感信息策略钩子
→ 模型调用网关
→ 当前模型
→ 失败重试控制器
→ 结果格式校验器
→ 分析结果保存
```

### 7.1 业务任务

v1 至少需要支持：

```text
输入分析
建议生成
每日行动摘要
每周目标复盘
行动结果提取
处境模型更新建议
模型连接测试
```

任务类型用于选择提示词模板、结构化输出格式和基础调用日志类型，但不自动决定使用哪个模型。

### 7.2 模型选择和重试

```text
用户选择当前模型和推理等级
→ 调用当前模型
→ 失败后按既定技术重试策略重试
→ 仍失败则按模型列表顺序尝试其他模型
→ 每次请求重新经过敏感信息处理
→ 全部失败后提示用户
```

重试不得自动改变模型列表排序，也不得改变当前消息选定的推理等级。

### 7.3 结果边界

模型只能产生：

```text
分析结果
候选项
建议
待确认内容
```

模型不得直接产生已经生效的目标、行动、记忆、删除或状态变更。正式写入由本地核心根据用户确认命令完成。

模型返回后需要进行：

- 接入框架格式校验。
- 任务结构化格式校验。
- 必填字段和来源关系校验。
- 推测与确定性表达检查。
- 候选项状态校验。
- 不允许的直接写入意图检查。

## 8. RAG 架构

### 8.1 检索链路

```text
当前问题或后台任务
→ 判断检索场景
→ 结构化条件筛选
→ 关键词或语义召回
→ 去重和来源合并
→ 按状态、时间和可信度筛选
→ 形成少量首轮结果
→ 信息不足时补充检索
→ 生成带来源的上下文
→ 进入敏感信息处理
→ 发送给模型
```

### 8.2 内容范围

普通建议优先使用：

```text
当前目标
当前行动
行动截止时间
当前有效现实限制
当前有效长期记忆
相关行动结果
相关决策和复盘结果
最近相关记录
```

历史复盘可以额外使用：

```text
过期记忆
历史处境模型
过去目标和行动
过去建议效果
历史原始记录
```

待确认内容可以召回，但必须带有待确认状态；已删除原始记录不再检索原文。

### 8.3 依据展示

每次建议需要保留本次使用的依据集合，默认折叠展示。展开后至少能看见：

```text
参考内容
来源类型
发生时间
当前状态
可信度
是否用户确认
```

对外模型上下文不发送内部 ID、本地路径和数据库字段名，只发送完成当前任务所需的最小内容。

## 9. 敏感信息处理架构

### 9.1 强制外发边界

敏感信息拦截点固定在：

```text
上下文组装完成
→ 外部请求发出之前
```

逻辑边界为：

```text
External Request Builder
→ Sensitive Information Policy Hook
→ Model Provider Adapter
```

该钩子必须覆盖：

- 用户本次输入；
- RAG 检索结果；
- 当前目标、行动和处境模型；
- 长期记忆；
- 每日摘要上下文；
- 每周复盘上下文；
- 模型重试请求；
- 所有后台任务模型调用。

### 9.2 本地内容和外发内容

系统必须区分：

```text
本地完整内容
外部模型可发送内容
```

本地可以按照已确认规则保存完整原始内容和敏感长期记忆。外发内容先进行敏感识别，再按设置选择提醒或脱敏，脱敏后继续发送。

### 9.3 日志边界

基础模型调用日志只记录已确认的最小字段：

```text
使用的模型
调用时间
任务类型
是否调用个人记忆
```

不将完整模型请求上下文、完整 RAG 结果和模型原始回复自动复制到调用日志。

## 10. 后台任务架构

后台任务采用持久化任务记录加本地调度器，不依赖只存在于内存中的定时器：

```text
任务定义
→ 持久化任务记录
→ 本地调度器
→ 任务执行器
→ 业务处理器
→ 写回结果
→ 通知适配器
```

### 10.1 v1 任务类型

```text
每日行动摘要
明确截止时间提醒
逾期行动集中提醒
每周目标复盘
待确认内容提醒
附件解析任务
```

### 10.2 幂等约束

后台任务必须能够重复检查而不重复产生正式副作用：

```text
同一天最多一份有效行动摘要
同一个明确提醒时间最多提醒一次
同一周最多一份有效目标复盘
```

任务建议记录以下技术信息：

```text
任务类型
关联对象
计划时间
实际执行时间
任务状态
重试次数
最近错误
幂等键
生成结果引用
通知状态
```

这些是架构建议字段，不等同于已经冻结的产品字段。

### 10.3 移动端补偿执行

由于移动系统可能限制进程存活和精确后台运行，系统区分：

```text
计划执行时间
实际执行时间
通知展示时间
用户打开 App 后补偿执行时间
```

v1 保证 App 运行时可以执行，且用户当天打开 App 时可以检查并补生成错过的摘要或任务。v1 不承诺进程被终止或设备离线时所有后台任务都能精确执行。

## 11. 删除、来源和索引一致性

删除操作遵循：

```text
归档：保留，默认不参与日常界面
删除：进入删除状态，不参与日常建议
彻底删除：从本地数据中物理清除，需要二次确认
```

删除原始记录后：

- 原始记录正文不再被 RAG 检索。
- 已确认目标、行动和记忆不自动删除。
- 结构化对象保留必要来源摘要。
- 来源展示为原始记录已删除。

索引更新必须由本地核心统一驱动，不能由客户端自行修改索引状态。

## 12. 后续服务器化的隔离原则

v1 不实现服务器存储和同步，但本地架构需要避免绑定某一个未来服务器方案：

```text
业务服务
→ Repository / Storage 抽象
→ 本地结构化存储和文件存储
```

后续增加服务器时，优先通过增加远端存储和同步层实现，不改变客户端的确认边界、敏感信息边界和正式对象写入规则。

v1 不提前引入账号体系、同步冲突解决或多用户权限模型。

## 13. 已采纳的架构决策清单

本轮已确认采纳：

1. 每台设备独立运行一套本地核心。
2. 采用本地优先的模块化单体。
3. 客户端不直接访问模型和数据库。
4. 所有业务写入和状态变更由 Local Core 负责。
5. 所有外部模型请求统一经过敏感信息处理钩子。
6. 敏感信息处理覆盖普通请求、RAG、后台任务和模型重试。
7. 原始数据、候选分析、正式对象和检索索引分层保存。
8. RAG 索引不作为权威事实源，检索结果必须可追溯。
9. 后台任务使用本地持久化任务记录，并支持幂等和打开 App 后补偿执行。
10. v1 不做微服务，不做云端后端，不做跨设备同步。
11. 后续服务器化通过存储和同步层扩展，不改变当前业务边界。
