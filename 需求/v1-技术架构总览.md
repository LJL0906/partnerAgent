# v1 技术架构总览

> 状态：已确认的 v1 全栈技术架构基线
>
> 决策日期：2026 年 9 月 4 日
>
> 适用范围：个人助手 v1.0 的移动客户端、业务后端、Agent Runtime、AI/RAG、数据库、附件、任务、知识库和私有部署。
>
> 技术选型：[`v1-技术选型方案.md`](./v1-技术选型方案.md)
>
> 详细整合：[`v1-详细子需求交叉整合.md`](./v1-详细子需求交叉整合.md)

## 1. 架构画像和术语声明

### 1.1 v1 采用的运行形态

v1 采用：

```text
单用户
+ 用户可控的私有核心主机
+ 移动客户端
+ 服务端全栈
+ 结构化数据库权威
+ Agent Runtime 底座
+ 独立 AI/RAG 执行层
```

推荐部署关系：

```text
Expo 移动 App
        ↓ HTTPS / 私有网络
NestJS 业务核心 / API
        ↓
PostgreSQL + pgvector + 私有文件存储
        ↓
Python FastAPI AI/RAG 服务
        ↓
外部模型和可选外部能力
```

核心服务部署在用户自有电脑、家用小主机、NAS 或用户控制的私有服务器上。v1 不默认使用公共云托管。

### 1.2 “本地优先”的新定义

本次全栈选型后，v1 的“本地优先”定义为：

```text
用户数据优先保存在用户控制的私有核心主机
```

不再定义为：

```text
手机和电脑各自独立运行完整核心并各自保存权威副本
```

原因是：

```text
Expo 手机客户端
→ NestJS
→ PostgreSQL
→ Python AI/RAG
```

天然对应“私有核心主机 + 移动客户端”，而不是“每个终端独立本地数据库”。

### 1.3 v1 不做的服务化范围

虽然 v1 从第一版采用完整后端，但仍不做：

- 多用户产品化；
- 公开 SaaS 运营；
- 多租户权限模型；
- 多个私有核心之间的同步；
- 同步冲突合并；
- 公共云作为默认数据托管方；
- Kubernetes 和多区域分布式部署；
- Obsidian 双向自动同步。

### 1.4 手机和电脑产品承诺调整

v1 仍提供：

```text
手机客户端入口
电脑端基础入口或浏览器客户端
```

但两者默认访问同一个用户私有核心主机。v1 不承诺：

- 手机离线时完整可用；
- 手机和电脑各自拥有独立权威副本；
- 私有核心主机离线时移动端仍能完成全部功能；
- 多个核心之间自动同步。

## 3. 服务和模块边界

### 3.1 Expo 移动客户端

负责：

- 文字输入；
- 语音录音、转写展示和发送确认；
- 图片、网页链接和文件选择；
- 聊天展示；
- Agent 流式回复展示；
- 结构化分析结果和候选卡片；
- 确认中心；
- 目标、行动、记忆、建议和复盘页面；
- 模型配置和当前模型选择；
- 应用访问保护交互；
- 本地通知展示和点击导航；
- 导出入口。

不得负责：

- 直接访问 PostgreSQL；
- 直接访问 pgvector；
- 直接调用 Python AI Service；
- 直接调用外部模型或外部解析服务；
- 直接修改正式对象或状态；
- 自行拼装完整 RAG 上下文；
- 自行判断模型自然语言中的“已创建”或“已完成”。

### 3.2 NestJS Business Core

NestJS 是本项目的业务控制平面和 Local Core，负责：

```text
API
应用编排
领域服务
正式业务事务
状态机
确认中心
权限与访问保护
任务调度
外发策略
Pi Agent Adapter
```

业务模块建议包括：

```text
Input
Conversation
RawRecord
Attachment
Analysis
Candidate
Confirmation
Goal
Action
Fact
Memory
Decision
Suggestion
Context
RAG Orchestration
Model Gateway
Egress Policy
Background Job
Reminder
Export
Obsidian Adapter
```

NestJS 负责 PostgreSQL 权威数据的所有正式读写。Python AI Service 不得直接获得正式业务表写权限。

### 3.3 Pi Agent Runtime

Pi Agent Runtime 是主交互 Agent 的底座：

```text
pi-agent-core：Agent Loop、Tool Calling、工具事件、取消和流式运行
pi-ai：模型供应商适配、统一请求、流式输出和能力映射
```

Pi 的职责：

- 运行一次短生命周期智能任务；
- 接收用户任务；
- 调用受限只读工具；
- 调用提议型工具；
- 接收工具结果；
- 生成普通回复、分析结果、建议和候选；
- 推送 Agent 运行事件；
- 响应取消和超时。

Pi 不负责：

- Goal、Action、Memory、Decision 的正式状态；
- ConfirmationBatch 的业务审批；
- PostgreSQL 事务；
- 业务幂等和版本冲突；
- RAG 权威性；
- 外发敏感策略；
- 正式删除和撤销；
- 后台任务调度。

项目必须通过自己的 Adapter 使用 Pi，不允许业务模块直接依赖 Pi 内部类型和调用细节。

### 3.4 Python FastAPI AI Service

Python 服务是 AI/RAG 执行平面，负责：

- RAG 召回和重排；
- Embedding；
- 文档解析；
- v1.1 图片、网页和文件深度解析；
- 复杂 AI 任务；
- 长时间 AI 工作流；
- LangChain 集成；
- 限定场景的 LangGraph 工作流。

Python 服务输入：

```text
任务类型
任务标识
最小必要上下文
已处理或待处理的外发内容
输出约束
```

Python 服务输出：

```text
分析结果
事实或事实候选
建议
目标/行动/记忆/决策候选
摘要
复盘结果
处境更新候选
错误和不确定性说明
```

Python 服务不得：

- 直接创建正式 Action；
- 直接修改 Goal；
- 直接保存长期 Memory；
- 直接执行删除；
- 直接修改 ReminderPlan；
- 绕过 NestJS 的确认、状态机和事务。

### 3.5 LangChain

LangChain 定位为 AI 集成层，用于：

- Retriever；
- Embedding；
- Reranker；
- 文档加载器；
- Prompt 和结构化输出辅助；
- 基础非持久化 AI Chain。

不采用 LangChain Agent 作为本项目的主交互 Agent Loop。主交互 Agent 统一由 Pi Agent Runtime 承担。

### 3.6 LangGraph

LangGraph 只用于复杂、长时、可暂停或可恢复的 Python AI 工作流，例如：

- v1.1 附件深度解析；
- 多阶段网页资料研究；
- 复杂周复盘；
- 需要中途等待用户决定的 AI 工作流；
- 多节点、多分支、多次工具调用的后台任务。

LangGraph 的状态仅是：

```text
AI 工作流状态
```

不是：

```text
Goal / Action / Memory / Decision 的正式业务状态
```

### 3.7 PostgreSQL 和 pgvector

PostgreSQL 是 v1 的主数据库和正式业务权威源，保存：

```text
用户/设备
会话/消息
原始记录
附件元数据
分析运行
结构化分析
候选项
确认批次/确认操作
目标
行动
行动结果
事实
长期记忆
决策
建议/效果
处境快照
提醒计划/提醒实例
后台任务
索引任务
导出任务
来源关系
关键变更记录
模型调用最小日志
敏感策略最小日志
```

pgvector 是 PostgreSQL 内的派生向量检索能力：

```text
PostgreSQL 结构化对象 = 权威数据
全文检索 / pgvector = 可重建派生索引
```

pgvector 不得直接承担：

- 确认中心；
- 正式状态机；
- 业务事实判断；
- 业务对象唯一存储；
- 来源关系唯一存储。

### 3.8 文件存储

v1 默认使用私有核心主机本地文件系统，通过统一 `Storage` 抽象访问：

```text
LocalFileStorage
S3Storage
MinIOStorage
```

PostgreSQL 保存：

```text
attachment_id
storage_backend
storage_key
content_hash
content_type
byte_size
source_record_id
parse_status
lifecycle_status
```

文件系统保存：

```text
图片
音频
上传文件
导出包
解析临时文件
备份文件
```

物理路径不暴露给客户端、用户来源展示或外部模型。

### 3.9 后台任务

v1 默认采用：

```text
PostgreSQL BackgroundJob
+ NestJS Scheduler / Worker
+ Python FastAPI AI Task API
```

不把 Redis/BullMQ 作为 v1 强制依赖。

当需要多 Worker、跨进程高吞吐、复杂延迟队列或水平扩展时，再引入：

```text
Redis
+ BullMQ
```

即使引入，也必须保持：

```text
PostgreSQL = 任务和业务状态权威
Redis/BullMQ = 调度加速层
```

### 3.10 Obsidian

Obsidian 定位为：

```text
Markdown 知识库
+ 用户可读投影层
+ 导入/导出交换层
```

v1 默认采用：

```text
PostgreSQL 正式数据
→ ExportJob
→ Markdown
→ Obsidian Vault
```

未来导入时：

```text
Obsidian Markdown
→ 外部原始记录
→ 分析
→ 候选
→ 用户确认
→ 正式业务对象
```

不允许：

```text
Obsidian 文件修改
→ 直接更新 Action / Goal / Memory
```

### 3.11 部署

推荐部署：

```text
Docker Compose
+ 用户自有电脑 / 家用小主机 / 私有服务器
```

组件：

```text
api       NestJS Business Core
ai        Python FastAPI AI Service
postgres  PostgreSQL + pgvector
proxy     可选 HTTPS / 私有网络入口
```

v1 默认不要求部署 Redis、MinIO 或独立向量数据库。

## 4. 关键数据流

### 4.1 文字输入

```text
Expo
→ SubmitTextInput
→ NestJS 保存 OriginalRecord / SessionMessage / AnalysisRun
→ NestJS 判断是否需要 RAG
→ PostgreSQL 结构化筛选
→ pgvector / 关键词召回
→ Python AI Service 或 Pi Agent Runtime
→ External Data Egress Policy
→ 模型调用
→ 返回结构化分析、候选和建议
→ NestJS 校验并保存
→ 返回普通回复和确认卡片
```

### 4.2 语音输入

```text
Expo 录音
→ 转写
→ 用户检查和编辑
→ 用户确认发送
→ SubmitVoiceInput
→ NestJS 创建正式 OriginalRecord
→ 进入与文字相同的分析链路
```

语音确认不等于：

```text
创建行动
保存记忆
确认敏感外发
```

### 4.3 附件输入

```text
用户选择附件
→ 客户端临时状态
→ 用户确认提交
→ NestJS 保存原始附件和元数据
→ 登记“未安排深度解析”或可执行解析任务
→ v1.0 保留原始附件
→ v1.1 解析成功后写入 AttachmentParseResult
→ 必要时创建补充 AnalysisRun
```

附件保存成功和附件解析成功相互独立。

### 4.4 Agent 运行

```text
业务任务
→ NestJS 创建 AnalysisRun
→ Context Builder 读取权威数据和 RAG 依据
→ Final Payload Builder 组装最小上下文
→ External Data Egress Policy
→ Pi Agent Runtime
→ Read Tool / Proposal Tool
→ Agent Event Mapper
→ NestJS 保存分析结果和候选
→ ConfirmationBatch
```

Agent 工具只允许：

```text
只读工具
提议型工具
系统控制工具
```

不暴露：

```text
任意 SQL
任意 Shell
任意文件读写
任意网络请求
正式对象写入工具
```

### 4.5 用户确认和正式写入

```text
用户提交确认
→ SubmitConfirmationBatch
→ NestJS 校验候选、批次、版本、风险和权限
→ 一个业务事务：
   UserConfirmationAction
   正式对象创建/更新
   候选和批次状态
   SourceRelation
   ChangeHistory
   ReminderPlan 变更
   IndexUpdateJob 登记
   ContextRefreshJob 登记
→ 提交事务
→ 异步刷新索引和处境
```

### 4.6 RAG

```text
任务场景判定
→ PostgreSQL 结构化硬筛
→ PostgreSQL 全文检索
→ pgvector 语义召回
→ Python RAG 组织/重排
→ 状态、时间、可信度、确认和敏感标记复核
→ 最小依据包
→ NestJS 组装最终上下文
→ External Data Egress Policy
→ Pi Agent 或 Python AI 工作流
```

RAG 不直接写入正式业务对象。

### 4.7 摘要、提醒和周复盘

```text
BackgroundJob
→ NestJS 查询正式对象
→ ContextView / RAG
→ Pi Agent 或 Python AI
→ 生成摘要、提醒内容、复盘结果或候选
→ 正式变更进入 ConfirmationBatch
→ Notification Adapter 负责投递
```

通知适配器不拥有业务写入权。

### 4.8 导出和 Obsidian

```text
PreviewExport
→ 用户确认范围和保护选项
→ 冻结导出快照
→ ExportJob
→ 从 PostgreSQL 和私有文件存储读取
→ 生成 Markdown / JSON / 原始文件包
→ 敏感和凭证排除检查
→ 保护和完整性校验
→ 交付或写入 Obsidian Vault
```

## 5. 同步和异步边界

### 5.1 适合同步处理

```text
请求格式校验
权限校验
普通查询
原始记录事务
附件原始保存
确认批次正式事务
目标/行动/记忆状态变更
软删除和恢复命令
导出预览
隐私外发决定
```

### 5.2 必须异步处理

```text
输入分析
附件解析
附件补充分析
RAG Embedding
复杂重排
建议生成
每日摘要
每周复盘
提醒投递
索引更新
索引重建
导出文件生成
模型重试和切换
```

客户端不应通过 HTTP 等待时长判断业务是否保存成功。统一返回：

```text
task_id
status
resource_refs
```

实时体验可以使用：

```text
SSE
WebSocket
轮询
```

具体传输方式在接口契约阶段确定。

## 6. 外发安全边界

统一命名：

```text
External Data Egress Policy
```

所有离开私有核心主机的数据请求都必须经过：

```text
最终载荷组装
→ 外发策略
→ 脱敏 / 提醒等待 / 阻止
→ 外部适配器
```

覆盖：

```text
pi-ai 模型请求
Python AI Service 的外部模型请求
Embedding
语音识别
OCR
网页解析
第三方工具
```

必须防止：

- Pi Agent 绕过策略直接访问模型。
- Python Worker 绕过 NestJS 直接发送原始个人数据。
- 重试请求复用未经重新检查的载荷。
- 外部服务收到 API Key、内部 ID、本地路径或未脱敏秘密。

## 7. 状态和权威性边界

### 7.1 权威数据

```text
PostgreSQL 正式业务对象
原始文件存储中的原始附件
```

### 7.2 派生数据

```text
pgvector
全文索引
RAG 依据集合
ContextView
摘要
复盘展示结果
提醒实例
Agent Session
LangGraph Checkpoint
```

### 7.3 正式确认门槛

```text
候选
→ 用户明确确认
→ NestJS 校验
→ PostgreSQL 事务
→ 正式对象生效
```

### 7.4 Agent 状态和业务状态分离

```text
Pi Agent State / LangGraph State
= AI 执行状态

Goal / Action / Memory / Decision
= 产品正式业务状态
```

AI 执行状态变化不能自动改业务状态。

## 8. 日志、审计和可观测性

统一拆分：

```text
AnalysisRun
ModelCallLog
SensitivePolicyLog
AgentRunTrace（可选）
BackgroundJob
ChangeHistory
```

日志可以记录：

```text
任务类型
选定模型
实际模型
开始/结束时间
是否调用 RAG
是否调用个人记忆
是否命中敏感信息
是否发生切换
尝试次数
最终状态
错误分类
```

禁止记录：

- API Key；
- Authorization Header；
- 完整模型请求；
- 完整 RAG 上下文；
- 完整模型原始输出；
- 完整敏感明文；
- 未审查的 Pi 全量 Session。

## 11. 当前结论

本项目采用以下 v1 全栈架构：

```text
前端：Expo + React Native + TypeScript
业务后端：NestJS + TypeScript
主 Agent Runtime：pi-agent-core
模型适配：pi-ai
AI/RAG：Python + FastAPI
RAG/文档集成：LangChain
复杂 AI 工作流：LangGraph（限定使用）
数据库：PostgreSQL + pgvector
附件：私有核心主机本地文件系统 + Storage 抽象
后台任务：PostgreSQL BackgroundJob + NestJS Scheduler
知识库：Obsidian 单向 Markdown Adapter
部署：Docker Compose 私有核心主机
```

项目的权威边界为：

```text
NestJS + PostgreSQL = 业务权威
Pi = Agent Loop 底座
Python = AI/RAG 执行层
LangChain = AI 集成层
LangGraph = 复杂 AI 工作流层
Obsidian = 知识交换层
pgvector = 派生检索层
```

本架构不允许：

```text
Agent 直接写正式对象
Python 直接写正式业务表
RAG 直接修改业务状态
Obsidian 修改直接回写业务对象
通知直接修改 Action/Goal
索引替代 PostgreSQL 权威数据
```
