## 1. 文档目的

本文件回答：

```text
助手在什么场景下读取个人历史？
如何选择相关内容？
如何区分当前事实、历史信息、待确认线索和助手推测？
如何把这些内容安全地组织给模型和用户？
```

v1 的统一原则：

```text
结构化权威数据优先
→ 状态和来源先于相似度
→ 当前建议与历史复盘分场景
→ 处境模型只做聚合快照
→ RAG 只提供依据，不产生正式事实
→ 所有外发上下文在发送前经过敏感信息处理
```

RAG 和个人处境模型必须分工：

- **RAG**：从本地权威数据和原始证据中召回与当前任务相关的少量内容。
- **个人处境模型**：把当前目标、行动、限制、记忆、结果和决策聚合成易于理解的当前状态快照。

二者都不能：

- 自动创建目标、行动或长期记忆；
- 自动修改正式对象；
- 把模型推测变成用户事实；
- 用索引替代权威结构化数据；
- 把全部个人历史无差别发送给外部模型。

## 2. 关键问题与推荐答案

### 问题 1：RAG 应在哪些场景启用？

**推荐答案：** 由 Local Core 按任务类型显式选择检索场景，不是每次普通聊天都默认读取个人数据。

| 场景 | 是否默认使用个人 RAG | 推荐范围 |
|---|---:|---|
| 纯闲聊、无个人信息依赖的通用问答 | 否 | 不读取个人数据 |
| 当前问题和行动建议 | 是 | 当前目标、行动、截止时间、现实限制、相关记忆和历史结果 |
| 决策辅助 | 是 | 当前处境、相关目标/行动、决策记录、类似历史结果和必要原始证据 |
| 输入分析和候选生成 | 按需 | 只补充理解当前输入所需的正式对象、事实和原始证据 |
| 用户询问“依据是什么” | 是 | 优先读取本次建议已保存的依据集合 |
| 每日行动摘要 | 是 | 当前目标、行动、截止时间、限制、相关结果和待确认内容 |
| 每周目标复盘 | 是 | 当前和历史处境、目标、行动结果、建议效果、决策和过期记忆 |
| 附件解析后的补充理解 | 按需 | 只读取与附件内容和当前任务相关的本地资料 |
| 用户主动查看历史 | 是 | 按用户指定时间、对象和状态读取历史资料 |

RAG 是否启用由任务需求决定，不由“数据库中是否有内容”决定。没有个人上下文依赖的普通问答不应因为系统具备 RAG 就自动检索个人数据。

### 问题 2：RAG 的总体检索链路是什么？

**推荐答案：** 固定采用以下链路：

```text
任务和权限范围判定
→ 确定当前 / 历史检索场景
→ 结构化硬筛
→ 关键词召回与语义召回
→ 合并、去重、同源聚合
→ 状态、时间、可信度和确认状态复核
→ 形成少量候选依据集
→ 首轮上下文组装
→ 判断是否需要补充检索
→ 形成最终依据集合
→ 上下文最小化
→ 敏感信息处理
→ 发送外部模型（如需要）
```

关键边界：

- 结构化筛选先于关键词和语义召回。
- 召回结果必须再次依据权威对象状态过滤。
- RAG 结果只是候选依据，不是正式写入命令。
- 敏感信息处理发生在最终外发载荷形成后、供应商适配器之前。
- 所有模型重试都重新执行敏感信息处理。

### 问题 3：结构化筛选、关键词和语义召回如何配合？

**推荐答案：** 结构化筛选负责限制范围，关键词和语义召回负责寻找相关内容，三者不能互相替代。

#### 第一层：结构化硬筛

先确定：

```text
本地数据空间
任务类型
当前或历史场景
允许的数据对象类型
删除和归档范围
确认状态范围
时间范围
敏感访问边界
```

结构化硬筛必须排除不应进入当前场景的对象，不能先把所有历史内容召回后再依赖模型判断哪些不该使用。

#### 第二层：关键词召回

适合：

- 目标和行动名称；
- 日期、截止时间和时间表达；
- 专有名词；
- 用户原话；
- 明确的限制、人物、项目或文件名；
- 需要精确追溯的短语。

#### 第三层：语义召回

适合：

- 同义表达；
- 隐含问题；
- 不同说法表达的相同偏好或限制；
- 相似行动和过去结果；
- 需要跨原始表述寻找相关历史的场景。

关键词和语义召回可以并行，结果合并后必须执行：

```text
去重
→ 同源片段聚合
→ 版本选择
→ 状态复核
→ 冲突识别
```

### 问题 4：结构化对象和原始记录谁优先？

**推荐答案：** 结构化对象优先提供当前可操作状态，原始记录负责补充证据和细节。

推荐优先级：

```text
当前目标
→ 当前行动和截止时间
→ 当前有效现实限制
→ 当前有效长期记忆
→ 相关行动结果
→ 相关决策和复盘结果
→ 相关事实
→ 最近相关原始记录
→ 更早的历史原始记录
```

原始记录不能因为文本相似度高，就覆盖正式目标、行动或记忆的当前状态。

例如：

```text
原始记录曾写“下周完成”
正式行动后来已经确认延期到下月
→ 当前建议应使用正式行动的延期状态
→ 原始记录只能作为历史依据或解释变更原因
```

如果正式对象与原始记录存在冲突，应显示状态和时间，而不是让模型自行选择并隐藏冲突。

### 问题 5：首轮检索应该做到什么程度？

**推荐答案：** 首轮只建立回答当前任务所需的最小依据包，不追求一次读取全部可能相关内容。

首轮优先回答：

1. 用户当前要解决什么问题。
2. 当前有哪些直接相关的目标、行动和限制。
3. 是否存在相关的已确认记忆、结果和决策。
4. 是否已有足够来源支撑低风险回答或建议。
5. 是否存在明显冲突、过期、删除或低可信度信息。

首轮结果建议包含：

```text
当前用户输入
+ 当前任务相关处境摘要
+ 当前有效正式对象
+ 必要的近期行动结果
+ 少量直接原始证据
+ 不确定性说明
```

首轮不应默认包含：

```text
全部长期记忆
全部历史处境
全部聊天记录
所有待确认候选
与当前任务无关的敏感内容
```

### 问题 6：什么时候进行补充检索，什么时候停止？

**推荐答案：** 只有发现明确的信息缺口时才补充检索；补充检索必须有目标，不能无限扩大历史范围。

可以触发补充检索的情况：

- 首轮只命中相似内容，缺少直接依据；
- 需要查找某个明确的过去决策或行动结果；
- 用户追问时间线、原话或依据来源；
- 发现当前对象与历史来源冲突；
- 处境模型命中，但底层来源不完整或已发生变化；
- 当前建议属于重要决策，需要核验低可信度或过期信息；
- 用户明确要求扩大历史范围。

补充检索应围绕缺口执行，例如：

```text
扩大时间范围
→ 查询关联行动结果
→ 回查原始记录
→ 查找冲突来源
→ 查找更新版本
```

以下情况应停止检索并明确说明：

- 补充检索仍无足够来源；
- 只找到待确认、低可信度或助手推断；
- 只有过期历史，未找到当前有效信息；
- 相关原始来源已经删除；
- 索引不健康且结构化查询也无法补足依据。

停止检索后可以给出低风险、条件化建议，但不能用扩大历史召回来掩盖信息不足。

### 问题 7：哪些状态和内容应硬排除，哪些可以降级使用？

**推荐答案：** 采用“硬排除、默认降级、场景允许”三层规则。

#### 硬排除

默认不得进入普通 RAG 或普通建议上下文：

- 已彻底删除的内容；
- 已删除原始记录的原文；
- 语音确认前的临时转写；
- 语音确认前的临时附件；
- 失败且没有有效结果的分析临时内容；
- 已取消候选作为普通建议的正向依据；
- 已被明确标记为不可使用的内容。

#### 默认降级

可以受限召回，但必须携带状态：

- 待确认目标、行动和记忆候选；
- 助手抽取的事实；
- 助手推断的处境判断；
- 低可信度事实；
- 有争议的事实或记忆；
- 已归档内容；
- 仅有历史支持的内容。

#### 场景允许

在明确场景下使用：

- 过期记忆：历史复盘和过去决策解释；
- 历史处境版本：复盘和解释过去建议；
- 已取消建议：只用于理解用户过去未采纳情况，不作为当前正向依据；
- 已删除正式对象的必要状态摘要：仅在用户主动查看历史且删除规则允许时展示。

“可召回”不等于“可当作已确认事实”，也不等于“可触发正式变更”。

### 问题 8：事实、长期记忆和待确认内容在 RAG 中如何区分？

**推荐答案：** 所有检索结果都要携带状态、来源和可信度，不能仅按文本内容发送给模型。

| 内容 | 普通建议 | 历史复盘 | 备注 |
|---|---:|---:|---|
| 已确认且当前有效长期记忆 | 可以 | 可以 | 作为个人长期理解依据 |
| 已确认目标和行动 | 可以 | 可以 | 作为当前执行状态依据 |
| 已确认事实 | 可以谨慎使用 | 可以 | 仍需看时间和可信度 |
| 助手抽取事实 | 可以受限使用 | 可以 | 必须标记抽取来源和可信度 |
| 助手推断 | 仅作线索 | 可以 | 不得伪装成用户明确表达 |
| 待确认候选 | 可以受限使用 | 可以 | 必须标记待确认 |
| 过期长期记忆 | 默认不可以 | 可以 | 必须标记历史状态 |
| 有争议记忆或事实 | 仅提示冲突 | 可以 | 不应静默选一条 |
| 已取消候选 | 默认不作为正向依据 | 可按需查看 | 不得直接恢复 |
| 已删除原始记录原文 | 不可以 | 不可以 | 只保留必要删除来源说明 |

事实和长期记忆的详细生命周期遵循《v1-事实与长期记忆》。RAG 本身不负责把事实升级为记忆，也不负责改变记忆状态。

### 问题 9：检索结果和建议依据应怎样展示？

**推荐答案：** 每次建议和重要回答保存本次依据集合，默认折叠，用户可以展开查看。

每条依据至少包含：

```text
必要内容摘要
来源类型
来源记录或对象
发生时间
最后确认或观察时间（如有）
当前状态
可信度
确认状态
表达方式：用户明确表达 / 助手抽取 / 助手推断
是否敏感
来源是否已删除
```

展示原则：

- 区分事实依据、历史背景、待确认线索和助手推测。
- 依据摘要不能把推测写成用户已经确认的事实。
- 处境模型被引用时，同时展示其关键正式来源，不只展示快照结论。
- 已删除原始记录不恢复或展示其原文。
- 内部 ID、本地路径、数据库字段名和 API Key 不展示给用户，也不发送给外部模型。
- 依据内容的敏感标记必须在本地界面中可见，但敏感原文是否完整显示遵循本地访问保护规则。

用户询问“你为什么这样建议”时，优先返回已经保存的本次依据集合，不重新生成一套可能不同的解释来替代原依据。

### 问题 10：没有找到相关信息时怎么回答？

**推荐答案：** 区分“确实没有记录”“只有不确定记录”“历史信息过期”“索引不完整”四种情况。

| 情况 | 推荐回答和行为 |
|---|---|
| 没有符合范围的记录 | 明确说当前没有找到可用的个人记录，可以邀请用户补充 |
| 只找到待确认或低可信度内容 | 说明这些只是线索，不能当作确定事实 |
| 只找到过期历史 | 说明只找到历史信息，未确认当前仍适用 |
| 来源存在冲突 | 展示冲突和来源，不静默选择一条 |
| 原始来源已删除 | 说明依据已删除，不猜测或恢复原文 |
| 索引更新失败或正在重建 | 说明搜索结果可能不完整，并优先做结构化直接查询 |
| 信息不足但用户要求建议 | 给出低风险、条件化建议并说明缺少的信息 |

没有相关记录时：

- 不虚构个人历史；
- 不凭空生成长期记忆；
- 不自动创建行动；
- 不把“不知道”改写成“用户没有这个目标”。

### 问题 11：索引如何更新、失败和重建？

**推荐答案：** 索引是可重建的派生层，结构化数据和可访问原始内容才是权威来源。

更新链路：

```text
权威对象或来源变更
→ 同一事务登记 IndexUpdateJob
→ 异步更新、删除或重建索引
→ 成功标记完成
→ 失败进入幂等重试和补偿
```

至少以下变化需要触发索引更新：

- 原始记录新增、删除或恢复；
- 附件新增、解析成功、解析失败或解析结果替换；
- 事实、目标、行动、行动结果、决策或长期记忆变化；
- 确认、取消、过期、归档、软删除和恢复；
- 来源关系变化；
- 可信度、确认状态、敏感标记和关键时间变化；
- 处境模型候选、当前、历史或作废状态变化。

索引更新失败时：

- 不回滚用户已确认的正式对象；
- 保留索引任务失败状态和重试信息；
- 结构化查询继续可用；
- 查询层必须依据权威状态过滤残留的旧索引项；
- 不把索引故障误报成“没有个人记录”。

重建原则：

- 以结构化对象和仍可访问的原始记录为输入；
- 不重建已彻底删除内容；
- 不重建已删除原始记录的正文；
- 不重建语音确认前临时数据；
- 不重建失败且无有效结果的分析临时内容；
- 使用对象版本，避免旧索引覆盖新状态。

具体索引产品、分块规则、Embedding 方案和召回参数由后续技术选型决定。

### 问题 12：处境模型到底是什么？

**推荐答案：** 个人处境模型是面向当前行动和决策的、可版本化的状态快照，不是完整用户画像，也不是新的事实来源。

它用于回答：

```text
当前最重要的目标是什么？
正在推进哪些行动？
当前有哪些已确认的现实限制？
近期发生了哪些重要变化？
当前有哪些风险、阻碍、冲突或信息缺口？
```

处境模型的性质：

- 聚合目标、行动、现实限制、长期记忆、行动结果和决策。
- 面向当前建议提供紧凑上下文。
- 可以保存历史版本，用于复盘和解释过去决策。
- 必须能追溯到正式对象和原始来源。
- 不能反向覆盖目标、行动、记忆、事实或决策。
- 不能把模型推断直接包装成用户真实状态。
- 不是完整个人档案，不默认包含所有历史信息。

### 问题 13：处境模型的最小内容应该是什么？

**推荐答案：** v1 只保存与当前行动和决策相关的最小状态。

#### 当前状态

```text
当前重要目标
进行中的目标
相关行动及状态
相关截止时间
已确认的现实限制
当前问题
最近重要变化
风险和阻碍
最近重要决策
相关行动结果
相关当前有效长期记忆
待确认或存在冲突的内容
```

#### 依据元信息

```text
处境模型版本
生成时间
适用时间范围或新鲜度说明
版本状态
确认状态
不确定性说明
来源关系集合
敏感标记
```

字段可以为空。没有相关信息时显示“暂无记录”或“不足以判断”，不能让模型补全缺失内容。

“当前重要目标”和“当前行动”不是处境模型新建的对象，而是对正式目标和行动的聚合引用。

### 问题 14：处境模型和正式对象是什么关系？

**推荐答案：** 正式对象是权威来源，处境模型只做聚合和解释。

```text
正式目标 / 行动 / 限制 / 记忆 / 结果 / 决策
→ 聚合为处境模型
→ 处境模型用于当前建议和复盘
```

处境模型不能：

- 创建新的正式目标；
- 改变行动状态；
- 修改截止时间；
- 保存长期记忆；
- 使旧记忆过期；
- 代替决策记录；
- 用快照内容覆盖来源对象。

处境模型中的重要判断需要关联来源关系，关系类型可以包括：

```text
支持
补充
冲突
替代
派生
```

如果处境模型内容仅来自助手推断或来源已经失效，只能作为待确认候选或低可信度提示。

### 问题 15：处境模型何时更新？

**推荐答案：** 采用“有实质影响才生成新版本”，不因每条输入或每次检索排序变化都生成正式新版本。

建议触发条件：

```text
确认创建或修改目标
确认创建或修改行动
确认行动状态或截止时间变化
确认新的现实限制
确认新的长期记忆或记忆冲突更新
重要决策确认并影响当前行动
正式对象被删除、归档、过期或标记为不再适用
行动结果显示执行条件发生变化
用户明确要求刷新或纠正处境
```

不应单独生成正式新版本的情况：

```text
普通闲聊
与当前任务无关的记录
模型重复提及已有信息
低可信度推断
只有检索排序变化
没有影响当前行动或决策的摘要更新
```

时间经过可以触发“可能不新鲜”或“建议复核”，但不能仅因长时间未提及就自动将记忆或限制改为过期。

### 问题 16：处境模型如何区分候选、当前和历史版本？

**推荐答案：** 采用以下版本状态：

```text
候选
当前
历史
已作废
```

#### 候选版本

- 尚未获得必要确认。
- 可以受限参与检索。
- 必须标记为待确认。
- 不能作为已确认硬约束。
- 不能覆盖当前版本。
- 与当前版本冲突时同时展示来源和差异。

#### 当前版本

- 当前建议默认使用的处境快照。
- 同一数据空间只允许一个明确的当前版本。
- 必须记录生成时间和适用范围。
- 其中的关键判断必须能回指当前有效正式对象。
- 不能因为是当前版本就把所有内容都当作用户明确表达。

#### 历史版本

- 被后续版本替代的旧处境。
- 保留生成时间、来源和当时状态。
- 普通建议默认不使用。
- 历史复盘和过去决策解释可以使用。

#### 已作废版本

- 来源不足、生成错误、用户明确否定或不可继续使用。
- 不参与普通建议。
- 是否在历史界面展示服从删除和历史规则。

### 问题 17：处境模型候选是否都需要用户确认？

**推荐答案：** 不要求用户确认每次普通聚合，但会改变正式理解或影响重要决策的处境判断必须进入确认中心。

可以自动生成临时视图或候选的内容：

- 汇总已确认目标和行动；
- 反映已确认状态和截止时间；
- 聚合当前有效限制和记忆；
- 展示相关结果和决策；
- 标记信息缺失、冲突或可能过期。

必须进入确认中心的内容：

- 新增或改变当前现实限制；
- 改变当前重要目标或优先级判断；
- 将风险、阻碍、能力或资源判断保存为正式处境结论；
- 因冲突信息决定采用新版本并废弃旧结论；
- 由处境模型推动目标、行动、记忆或决策的正式变更；
- 用户明确纠正当前处境描述。

不建议每次打开建议都要求用户确认完整处境模型，否则会阻塞行动闭环。

### 问题 18：处境模型中的待确认内容能否参与建议？

**推荐答案：** 可以作为受限线索，但不能作为已确认事实或硬性限制。

```text
当前有效且已确认
→ 正常依据

待确认或存在冲突
→ 受限线索，显式标记

过期、已删除或已作废
→ 普通建议排除，按历史场景处理
```

待确认处境可以用来发起澄清，例如：

```text
系统发现你可能暂时无法投入完整时间，这是否仍然成立？
```

但不能直接据此：

- 拒绝用户行动；
- 改变目标优先级；
- 判定行动不可执行；
- 保存新的长期记忆；
- 对外声称这是用户当前事实。

### 问题 19：敏感处境内容如何进入模型上下文？

**推荐答案：** 本地可以保存完整处境内容，但外发时只发送任务所需的最小字段，并重新经过统一敏感信息处理。

```text
读取本地处境模型
→ 按任务筛选相关维度
→ 组装 RAG 依据和用户输入
→ 形成最终外发载荷
→ Sensitive Information Policy Hook
→ 按提醒、脱敏或阻止策略处理
→ 发送供应商（如允许）
```

必须遵守：

1. 不默认发送完整处境模型。
2. 不发送与当前任务无关的敏感内容。
3. 敏感标记不能代替最终外发检测。
4. 敏感长期记忆每次被选入外发上下文时重新检查。
5. 每次重试、换模型、后台任务和外部 Embedding（如果未来采用）都重新检查。
6. 脱敏后不足以支撑可靠判断时，明确说明信息不足、等待用户决定或阻止发送。
7. 基础调用日志不保存完整处境上下文和完整 RAG 结果。

隐私外发确认与处境模型确认是两条不同边界：

```text
允许某段内容外发
≠
确认该内容成为当前处境
```

### 问题 20：删除和过期如何影响 RAG 与处境模型？

**推荐答案：** 删除和过期不自动级联删除所有关联对象，但必须重新评估受影响依据的可用性。

#### 删除原始记录

- 已删除原文不再参与普通 RAG。
- 已确认目标、行动、记忆和决策不自动删除。
- 来源关系显示原始记录已删除。
- 处境模型历史版本不静默改写。
- 如果某个当前判断只依赖已删除来源，应标记依据不足或需要刷新。
- 如果仍有其他有效来源，可以保留判断，但来源集合应反映删除状态。

#### 过期记忆或限制

- 过期不等于错误。
- 普通建议不使用过期记忆作为当前依据。
- 历史复盘可以使用过期记忆并标记历史状态。
- 过期现实限制不能继续作为当前硬约束。
- 仅因长时间未提及不自动过期。

#### 彻底删除

- 彻底删除后的内容不得被普通 RAG、处境模型新版本或建议依据召回。
- 索引重建不能恢复彻底删除正文。
- 历史界面是否显示最小删除摘要遵循数据删除和导出规则。

### 问题 21：每日摘要和每周复盘如何使用处境模型？

**推荐答案：** 每日摘要消费当前处境，每周复盘消费当前和历史处境；二者都不能自动写回正式对象。

#### 每日摘要

可以使用：

```text
当前重要目标
当前行动和截止时间
当前有效限制
相关近期行动结果
当前风险和阻碍
待确认内容
```

每日摘要不负责：

- 重新定义当前处境；
- 展开全部历史分析；
- 自动修改目标、行动或记忆；
- 自动确认新的处境结论；
- 把一次摘要保存为长期经验。

#### 每周复盘

可以使用：

```text
当前处境模型
历史处境模型
过去目标和行动
行动结果
决策记录
建议采纳和效果
过期记忆
```

周复盘可以生成：

- 复盘展示内容；
- 新建议；
- 处境更新候选；
- 目标或行动变更候选；
- 记忆和决策经验候选。

涉及正式对象的变更仍进入确认中心。

每日摘要和周复盘的具体时间、时区、渠道、频率和补偿规则由《v1-行动摘要与提醒》确定。

## 3. 推荐的检索依据对象字段

RAG 结果面向 Local Core 和模型时，至少保留以下逻辑字段：

```text
检索结果标识
对象类型
对象版本
内容摘要
来源类型
来源对象引用
发生时间
最后确认或观察时间
当前状态
可信度
确认状态
表达方式
是否敏感
是否已删除
召回方式：结构化 / 关键词 / 语义 / 处境聚合
```

对外模型上下文应转换为不包含内部实现信息的内容：

```text
必要内容
来源的用户可理解名称
时间
状态
可信度
确认和不确定性说明
```

不得发送：

- 内部数据库 ID；
- 本地文件路径；
- 索引键；
- 数据库字段名；
- API Key；
- 与任务无关的敏感内容。

## 4. 上下文最小化规则

### 4.1 推荐上下文结构

```text
当前用户输入
+ 任务指令和输出约束
+ 当前任务相关的精简处境卡
+ 少量正式对象和来源依据
+ 必要的冲突、状态和不确定性说明
```

### 4.2 裁剪优先级

1. 当前用户输入、任务指令和必要输出约束。
2. 当前相关目标、行动、截止时间和现实限制。
3. 当前有效且相关的长期记忆。
4. 相关行动结果、决策和建议效果。
5. 少量相关原始记录和附件解析结果。
6. 待确认线索、低可信度信息和历史背景。
7. 低相关、重复、过旧内容。

### 4.3 裁剪规则

- 不静默截断当前用户输入。
- 优先移除低相关、重复、较旧或可由来源摘要替代的内容。
- 不因裁剪把助手推断写成确定事实。
- 不因裁剪丢失待确认、过期或冲突状态。
- 不把完整处境模型无差别发送给模型。
- 记录是否发生上下文裁剪，但不把完整上下文写入基础调用日志。
- 裁剪后仍超限时，明确返回上下文超限，不静默切换模型或省略关键限制。

## 5. 与模型和敏感信息的边界

RAG 的最终结果必须经过模型调用和敏感信息链路：

```text
RAG 召回
→ 状态过滤
→ 来源和依据组装
→ 上下文最小化
→ 最终外发载荷
→ 敏感信息处理
→ Model Gateway
```

RAG 不能直接调用外部模型，也不能绕过 Model Gateway。

每次模型重试或切换时：

- 重新确认当前任务上下文；
- 重新执行状态和来源过滤；
- 重新组装该模型的外发载荷；
- 重新经过敏感信息处理钩子。

## 6. 已确认边界、本轮采用规则和待决策项

### 6.1 已确认边界

- RAG 采用结构化筛选、关键词/语义检索和模型综合判断。
- 结构化数据优先，原始记录作为补充和证据。
- 普通建议只使用当前有效记忆；历史复盘允许使用过期记忆。
- 待确认内容可以受限进入 RAG，但必须携带待确认状态。
- 已删除原始记录原文不再参与普通检索。
- 检索结果需要来源、时间、状态、可信度、确认和敏感标记。
- 找不到记录时明确说明；推测必须标记为推测。
- 处境模型是正式对象的聚合快照，不是新的事实来源。
- 当前处境变化时可以生成新版本；重要判断需要确认。
- 每日摘要和周复盘不能绕过确认中心修改正式对象。
- 所有外部模型请求在发送前经过统一敏感信息处理。

### 6.2 本轮采用的详细规则

以下规则作为本文件的 v1 详细基线：

1. 纯闲聊且不需要个人上下文时默认不启用个人 RAG。
2. 结构化硬筛先于关键词和语义召回。
3. 关键词和语义召回作为互补通道，合并后去重、聚合和状态复核。
4. 首轮检索只建立最小依据包，只有明确缺口才补充检索。
5. RAG 结果永远不能直接触发正式写入或状态变更。
6. 索引更新任务登记与权威对象变更同事务，索引实际更新异步执行。
7. 索引是可重建派生层，索引故障不能被误报为无记录。
8. 当前处境模型只允许一个明确当前版本，候选、历史和作废状态分开。
9. 普通聚合可以自动生成临时视图；改变正式处境判断或影响重要决策的内容进入确认中心。
10. 处境模型重要判断必须能够回指正式对象和原始来源。
11. 待确认、低可信度、过期、冲突和敏感内容始终显式降级。
12. 每次外发只使用任务所需的最小 RAG 和处境上下文。
13. 每次模型重试、换模型、后台任务和未来外部 Embedding 请求重新经过敏感处理。
14. 不做复杂历史趋势挖掘、完整个人画像和自动长期人格推断。

### 6.3 仍待决策项

以下内容不因本文件而锁定：

- 关键词索引和语义索引的具体产品。
- Embedding 使用本地模型还是外部服务。
- 外部 Embedding、OCR、语音识别是否统一纳入外发策略边界的具体接入方式。
- 文本和附件解析结果的分块规则。
- 首轮召回数量、补充检索触发阈值和排序权重。
- 相关度、时间、状态、可信度和用户确认的具体排序公式。
- 索引版本、重建任务和索引健康检查的具体实现。
- 处境模型字段的具体结构和版本存储格式。
- 处境模型新鲜度和适用时间范围的计算方式。
- 处境候选、事实候选和正式记忆候选的具体展示交互。
- 用户对当前处境的修正粒度和确认卡片细节。
- 删除来源后处境模型重新评估的具体触发和提示方式。
- 每日摘要和每周复盘的具体时间、时区、渠道和补偿规则。

## 7. 验收标准

### 7.1 检索入口和范围

- 纯闲聊且不需要个人上下文时不默认读取个人数据。
- 当前建议能读取当前目标、行动、截止时间、限制、相关记忆和历史结果。
- 历史复盘能读取历史处境、过期记忆和过去行动结果。
- 输入分析不会把待确认内容当成已确认事实。

### 7.2 状态和来源

- 检索结果携带来源、发生时间、状态、可信度、确认状态、表达方式和敏感标记。
- 已删除原始记录原文不进入普通 RAG。
- 过期记忆不进入普通建议，但可以进入历史复盘。
- 待确认内容如被召回，界面和模型上下文都保留待确认标记。
- 低可信度和助手推断不会被展示为用户确认结论。

### 7.3 检索失败和重建

- 首轮不足时可以围绕明确缺口补充检索。
- 无结果、过期、冲突、来源删除和索引不完整能够被区分说明。
- 索引更新失败不影响正式对象保存。
- 索引可以依据结构化对象和仍可访问的原始内容重建。
- 重建不会恢复已彻底删除内容或已删除原始正文。

### 7.4 处境模型

- 处境模型是可追溯、可版本化的聚合快照，不是新的事实来源。
- 当前处境只有一个明确当前版本。
- 当前、候选、历史和已作废版本能够区分。
- 重要处境判断可以回指目标、行动、限制、记忆、决策或原始来源。
- 处境模型不会自动修改正式目标、行动或长期记忆。
- 删除来源后，受影响处境会被标记为依据不足或需要刷新。

### 7.5 上下文和安全

- 外部模型只收到当前任务的最小必要上下文。
- RAG 和处境模型不直接调用外部模型。
- 每次模型请求、重试、后台任务和未来外部 Embedding 都经过敏感信息处理。
- 外发上下文不包含内部 ID、本地路径、数据库字段和 API Key。
- 基础调用日志不保存完整 RAG 结果或完整处境上下文。

### 7.6 摘要、复盘和确认

- 每日摘要使用当前处境，但不自动修改正式对象。
- 每周复盘可以使用历史处境和过期记忆，但不自动写回当前状态。
- 摘要和复盘产生的正式目标、行动、记忆、决策和处境变更进入确认中心。
- RAG 只提供依据，不直接产生正式事实或状态变更。

- 《v1-确认中心》：候选、批次、确认命令、风险和正式写入。
- 《v1-行动摘要与提醒》：摘要、复盘和提醒的时间、渠道、补偿和频率。
- 《v1-目标与决策辅助》：建议生成、目标冲突和决策辅助流程。
- 《v1-数据导出》：RAG 依据、处境版本和敏感字段的导出格式。

## 9. 当前不做的事情

v1 暂不做：

- 复杂历史趋势挖掘。
- 自动构建完整用户画像或人格模型。
- 自动把一次成功或失败固化为长期决策经验。
- 自动合并相似长期记忆。
- 让处境模型直接修改正式对象。
- 让 RAG 结果直接触发行动、记忆或状态变更。
- 为当前文档锁定具体向量库、Embedding、分块参数或召回数量。
- 为跨设备同步建立云端检索主库。
