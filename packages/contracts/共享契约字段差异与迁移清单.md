# 共享契约字段差异与迁移清单

> 状态：T01 契约已冻结，前端、后端、Agent 与数据库后续只消费 `@partner-agent/contracts`，不得另建同义 DTO。

## 逐字段差异表

| 领域/字段 | 前端现状 | 后端/Agent 现状 | 数据库现状 | 统一共享契约 | 差异处理 |
| --- | --- | --- | --- | --- | --- |
| 用户身份 | 登录后只保留 `username`，会话范围另解 JWT `sub` | JWT `sub` 写入 `request.userId`，会剥离客户端 `user_id` | 各业务表以 `owner_id` 隔离 | `AccountPublicUser.id` 必须等于可信 JWT `sub`；username 仅展示 | 前端保存完整 `AccountPublicUser`；公共 Query/Command 移除 `user_id`；owner 永不由客户端提交 |
| `session_id` | 新会话曾用本地随机值冒充服务端 ID | 可创建或接收已有聊天会话 ID | chat session 为 owner-scoped text | 首次提交可省略；服务端受理结果的 `data.session_id` 为权威值 | 前端另用本地 UI key，收到受理结果后才订阅/持久化 session ID |
| `operation_id` | 回包未核验请求 ID | controller 只验非空 | 多数表为 text，`session_messages.operation_id` 为 uuid，非 UUID 曾被静默置空 | Command operation ID 固定 RFC 4122 UUID；提供 `isOperationId` | 后端入口统一校验；数据库/消息迁移不得再静默丢关联 |
| `message_id` | REST 使用 DB ID，WS/history 曾本地合成 | WS 助手 item 曾按 task 合成，完成后才落消息 | `session_messages.id` 是稳定消息资源 ID | 资源字段使用真实 message ID；展示 ID 单独使用 `message:*` 或 `task:*:assistant` | 前端不再以正文、时间或数组下标猜 ID；后端在首个可见输出前建立稳定消息 ID |
| `task_id` | 状态拆成本地字段并混入 UI phase | ChatTask 是执行权威 | chat task 主键及消息关联 | `TaskRef` / `ChatSessionTaskRef`；任务助手和 runtime 分别使用稳定 item ID | UI-only phase 单独命名；不得写回服务端 TaskState |
| `tool_call_id` / `confirmation_id` / `execution_id` | approval ID 多处 fallback，终态会伪造风险 | 三类 ID 分属调用、审批、执行回执 | 工具确认与回执分表持久化 | `SessionToolView` 存在才返回对应 ID，禁止相互替代 | REST 恢复从工具权威记录投影；前端不从 metadata 或默认风险补值 |
| `model_config_id` | UI 选择值被当作实际调用结果 | 服务端可默认，Task 保存解析值，Provider trace 另存实际模型 | ChatTask/Message 已有模型字段但助手消息映射不完整 | 请求可省略；受理 `resolved_model.model_config_id` 必填；消息展示字段使用同一配置 ID | list/resolve/保存/调用共用服务端能力源；配置 ID 不与裸 provider model ID 混用 |
| `reasoning_level` | 曾只处理 low/medium/high 并自行补 medium/off | resolve、list、store 存在多套默认与 off 过滤 | 已支持 `off/minimal/low/medium/high/xhigh/max` | 全部引用 `ReasoningLevel`；`ModelConfig.default_reasoning_level` 必须属于真实 `reasoning_levels` | 非推理模型固定 `['off']`；客户端不追加等级、不猜默认 |
| 模型公开字段 | 可能接收 `api_key_ref` | 配置写入与列表复用同一类型 | 凭据应仅安全保存 | 公开 `ModelConfig` 不含凭据；写入使用 `ModelConfigInput` | `isModelConfig` 拒绝公开载荷中的 `api_key_ref` |
| 消息 `status` | 乐观态、网络未知与服务端状态混用 | DB 状态与 ChatItem 状态需私有转换 | `pending/streaming/complete/failed/cancelled` | `SessionMessageStatus` 及穷尽 `SESSION_MESSAGE_STATUS_TO_CHAT_ITEM_STATUS` | `complete` 仅展示为 `completed`；本地 submitting/unknown 不伪装服务端失败或完成 |
| 任务 `state` | waiting 状态曾显示 running/queued | 7 个 ChatTask 状态 | ChatTask check constraint 同 7 状态 | `TASK_STATES` 与穷尽映射；两种 waiting 映射为展示 `pending` | 后端和前端删除影子 union，直接消费共享映射 |
| 工具 `status` | 展示缺 executing/indeterminate/undone | 私有 ConfirmationStatus 有 8 状态 | 工具表保存 8 状态及版本 | `SESSION_TOOL_STATUSES`、安全 `SessionToolView`、穷尽展示映射 | ACK 只代表控制命令结果，不代表工具资源终态 |
| REST message | 内联弱类型，metadata 任意 | memory/PG 返回字段不一致 | Entity 有 sequence/status/关系/模型 | 独立 `SessionMessageDto`，必填 id/session/sequence/role/content/status/revision/created_at | 禁止任意 metadata；真实存在的 task/operation/model/reasoning 必须返回 |
| ChatItem `revision` | 本地 session 世代号易与服务端修订混淆 | 读取时尚无统一逐项修订 | 待后续消息/runtime 迁移承载 | 每个可恢复 ChatItem 必填正整数 `revision` | 本地世代号改称 view generation；不得使用 Date.now、数组序号或 WS sequence 伪造 revision |
| WS `sequence` | 被用于频道水位 | 每个频道独立递增；同事件多频道值可不同 | WS stream position 持久化 | 仅作对应 channel 重放 cursor | 禁止跨频道比较或转换为 message sequence/item revision |
| WS `text_delta` | 只按到达顺序拼接 string | 只有 `data:string` | 正文尚未按 delta 持久恢复 | 保留 `data:string`，另必填 `item_id/item_revision/message_id/text_offset` | `text_offset` 按追加前 JavaScript UTF-16 code unit 长度；不连续即 REST 对账 |
| WS 其他展示事件 | 多处靠 event type 本地造 item | 缺 item identity/revision | 事件只是投递记录，不是业务真相源 | 修改展示项的事件实现 `DisplayItemRevisionV1` | 纯 done/cancel/recovery 控制事件不伪造 item 字段 |
| REST 快照完整性 | `items` 存在就整体 replace | 只返回消息及有限 runtime | 工具权威记录、消息和任务分散 | `ChatSessionSummary.items/messages/tool_views` 均为权威数组 | 逐 item revision 合并；旧快照不能删除本地/实时较新 item |
| structured preview 类型 | 复用 candidate 卡和“确认”动作 | adapter/事件也映射为 candidate | 尚无聊天预览附件字段 | 独立 `ChatPreviewV1` + `ChatItem.type='structured_preview'` | candidate 只代表正式确认中心候选；预览不得含 candidate/batch/confirmation ID |
| structured preview 状态 | 可能被文案当作已确认 | 无真实 producer | 不应写正式业务/确认表 | 固定 `confirmation_status:'unconfirmed'`、`applied:false` | ChatItem `status:'completed'` 仅表示“预览生成完成”，不代表确认或生效 |
| structured preview 来源 | kind/id 任意 | 尚未校验 owner/session | 来源表有 owner 关系 | 只允许 `original_record` / `chat_message`，公开预览至少一个来源 | 后端还须校验来源存在、属于当前 owner 且来自本次受理输入 |
| structured preview 内容 | 只校验 object | Agent 输出无正式 schema | jsonb 不能代替语义校验 | action 首版：title、说明、计划/截止时间、IANA 时区、优先级、confidence、不确定性、风险摘要 | 模型只产生 `ChatPreviewProposalV1`；服务端补 preview ID、固定状态和权威来源 |
| 预览错误 | 泛化为任务失败 | 尚无稳定错误分类 | validation errors 结构不固定 | `STRUCTURED_PREVIEW_INVALID/MISSING/TOO_LARGE/SOURCE_INVALID` | 对外仅返回安全 code/path/message，不记录 offending value |

## 校验规则

- ChatItem `revision`、工具 `version`、消息 `sequence/revision` 都是正安全整数；WS `sequence` 是正整数，`text_offset` 是非负安全整数。
- `operation_id` 使用 RFC 4122 UUID。其余资源 ID 是非空 opaque string，不从前缀推断资源所有权。
- 公开 ModelConfig 的默认推理等级必须属于允许集合；非推理模型只允许 `off`；公开响应拒绝 `api_key_ref`。
- structured preview 仅开放 `kind:'action'`，拒绝额外字段。title 为 1–200 个 Unicode 字符；description、uncertainty、risk_summary 各不超过 2000 个字符；confidence 为 0–1。
- 时间必须是带 `Z` 或数字偏移的 RFC3339，并通过日历范围检查；同时出现时 deadline 不得早于 planned。timezone 必须是运行时支持的 IANA 名称。
- 每任务 1–20 个有效预览；整个 `chat_previews` 数组按 JSON UTF-8 编码不得超过 64 KiB。
- `SessionToolView` 使用字段白名单并拒绝 `arguments`、完整 `result`、`undoPayload`；allowed_actions 不允许重复或未知动作。
- 模型输出类型 `ChatPreviewProposalV1` 不包含 preview_id、确认状态和生效状态；公开类型 `ChatPreviewV1` 只能由服务端补齐这些字段。
